# FCT 数据分发器 v1.9.2（独立程序）

> ⚠ **v3.0.0 起本工具从「FCT 工具套件」里独立出来，是单独的 `FCT-Distributor.exe`。**
>
> 为什么独立：它能**改文件时间戳、按模板造数、批量投放 XML**。这些操作放在产线机台的
> 主程序里，误点一次会污染真实测试数据。所以现在**只发给工程/测试人员，不装到产线机台**。
>
> 产线机台上装的是 `Argus.exe`（`../FctAggregator/`），那边已经没有分发功能。

## 构建 / 自检 / 打包

```powershell
dotnet build FctDistributor.csproj -c Release                  # 要求 0 警告 0 错误
dotnet run --project selftest\SelfTest.csproj -c Release        # 全量自检（必须全绿；当前 71 项断言，含跨工程副本一致性）
dotnet publish FctDistributor.csproj -c Release -o dist
.\tools\make_package.ps1                                       # 完整包 + 覆盖包（带断言）
Compress-Archive -Path package_v1.9.0\* -DestinationPath FCT-Distributor-v1.9.0.zip -Force
```

## ⚠ 三个文件是主程序的副本，别只改一边

彻底分家的代价：以下文件在本工程与主程序里**各有一份**。

| 文件 | 与主程序的关系 |
|---|---|
| `Xlsx.cs` | **逐字节相同的副本**（xlsx 写出外壳） |
| `StationDetector.cs` | 精简副本：只有 IP→机台号 与型号校验 |
| `AppIcon.cs` | 精简副本：不依赖 `Logger` |

副本最大的风险是**静默漂移**（改一边忘另一边，两边自检还都是绿的）。所以本工程自检里有
**跨工程一致性断言**：会去读 `../FctAggregator/` 的源文件，逐条比对 IP 映射表、
逐字节比对 `Xlsx.cs`。源码不在时自动跳过（不影响独立部署）。

# FCT 数据分发器 (FCT-Distributor)

把 FCT 测试数据**一键投放**到机台的结果目录，并按文件名**修复时间戳**，主界面实时显示成果。

当前版本：**v1.9.2**（C# / .NET 8 WinForms，零第三方依赖）

> **v1.6.0 起默认「只投放到已有目录」**：程序**不再新建任何文件夹**，
> 只扫描目标根下**现有**的 `Offline\E3002781\{yyyyMMdd}` 目录，把生成的 XML 放进去。
> 两个模板（`O_` 中断 / `P_`）**只会出现在 Offline**，所以 `Online` 根本不扫、也不显示。

## 目录策略：只投放到已有目录（默认）

机台上的 `Offline\{型号}\{yyyyMMdd}` 目录是 FCT 测试软件自己建的。
本工具**只认这些现成目录**，一个都不新建：

```
扫描 {目标根}\Offline\E3002781\{yyyyMMdd}
  ├ 类别**只认 Offline**（Online 与其它顶层目录一概不扫）
  ├ 型号**只认 E3002781**（= 两个模板 SN 的前 8 位；SN 绝不改写，所以其它型号目录根本不看）
  └ 日期必须是合法 yyyyMMdd（且落在界面选的日期范围内）
每个入选目录 → 按模板生成文件放进去：**目录里已有同 SN 的文件就跳过，没有就加进去**
（每模板每日 1 个；**不限制目录内文件总数** —— 真实目录里本来就可能已有很多其它 SN 的文件）
```

| 情况 | 行为 |
|------|------|
| 目录不存在 | **跳过**并记日志，绝不 `mkdir`（执行阶段也再查一次） |
| 目录型号 ≠ `E3002781` | **整个目录不看**（SN 固定不改写，放进去就是脏数据） |
| 目录里已有同 SN 文件 | **跳过**（幂等；只看 SN，不看目录里有多少个文件） |
| 目录里只有其它 SN 的文件（哪怕已经很多） | **照常添加**，不存在数量上限 |
| 目标根下一个现有目录都没有 | 不生成任何条目，日志提示「本模式不新建目录」 |

> 需要旧行为（按日期范围**新建**目录树）时，取消勾选「只投放到已有目录(不新建)」。

## 目录映射规则

**目标目录**（FCT 测试软件的真实结构）：
```
{目标}\Offline\{型号}\{yyyyMMdd}\{前缀}_Fts_PEU_G49_FCT{n}_{SN}_{时间戳1}_{时间戳2}.xml
```

| 映射项 | 规则 |
|--------|------|
| 类别 | **固定 `Offline`** —— `O_`（中断）与 `P_` 这两个文件不会出现在 `Online` |
| 型号 | **固定 `E3002781`** = SN 前 8 位；所有生成的文件 SN 完全相同，所以**只可能出现在 `Offline\E3002781\`** |
| 文件名 | 只改 `FCT{n}` 段与末尾双时间戳，**SN 段原封不动** |

> 目标结构里**没有机台层级** —— 每台机台有自己的 `D:\Results`。
> 所以现场应让程序按 IP 自动识别机台（`172.28.55.11~16 → FCT1~6`，`.18 → FCT7`）。

## 模板生成：改了什么

以模板为蓝本，只动下面这些，其余原样保留：

| 项目 | 处理方式 |
|------|----------|
| **XML 内全部 `TIMESTAMP`** | **整体平移** —— 内部先后顺序、耗时、跨度分毫不动 |
| `BATCH` 根 `TIMESTAMP` | 单独推算为「测试开始前 N 分钟」，钳在 `[下限, 测试开始−1ms]` |
| `FACTORY@TESTER` | 改为 `PEU_G49_FCT{n}` |
| **`FACTORY@USER`** | 改为 `Operator`（见下方⚠️） |
| **`DUT@ID`（SN）** | **从不改**（金/银板就这两个 SN） |
| `PANEL@TESTTIME` / `DUT@TESTTIME` | 模板值 ± 抖动，两处保持相同 |
| 所有 `GROUP@TOTALTIME` / `@MODULETIME` | 递归按比例缩放，`Σ 顶层 TOTALTIME == PANEL.TESTTIME` |
| 文件名 | `FCT{n}` 段 + 双时间戳（第二个尾号 6 位随机，同日唯一） |
| 文件系统时间 | 创建 / 访问 / 修改 三个都设为文件名时间戳 |
| 目录时间 | 内部最晚文件 + 随机 1~300 秒，并向上冒泡到型号、类别目录 |

### ⚠️ USER 字段（关键）

内置两个模板的 `FACTORY@USER` 都是 **`Debug`**。而 Argus 的 `Classifier.IsDebug()`：

```csharp
public static bool IsDebug(string? user)
    => (user ?? "").Trim().ToLowerInvariant() == "debug";
```

**USER=debug 的数据会被整条跳过、一条都不入库。** 所以本工具默认**不勾选**改写（保留模板原值 Debug），需要被 Aggregator 入库时请手动勾选「改写 FACTORY@USER 为 Operator」，并在加载模板时高亮告警。

> Python 造数工具链（`batch_workflow.py` / `randomize_times.py`）从未处理过这个字段，
> 因此早期生成的 `FCT_Batch` 数据全部是无效的 debug 数据。

| 模板 | SN | 板 |
|------|-----|----|
| `P_` | `E3002781AFV75236898002K30500272` | **金板 Golden** |

## 模板生成参数

| 参数 | 默认 | 说明 |
|------|------|------|
| 测试窗口 | `08:00-11:45` | 测试窗口整体均匀分布到这个时段内 |
| BATCH 下限 | `08:00` | session 打开时间不得早于此（保证文件内所有时间都 ≥ 08:00） |
| 提前(分) | `1-15` | BATCH 比测试开始早多少分钟 |
| 测试时长±(秒) | `20.0` | 总时长在模板值上下浮动，**同步缩放** TIMESTAMP 分布与全部 GROUP 耗时 |
| 每模板/日 | `1`（锁定） | 业务硬规则，不可调；目录内文件总数**不限**（只看同 SN） |
| 分类目录 | `Offline`（**固定，不可选**） | 两个模板只会出现在 Offline；Online 不扫不显示 |
| **只投放到已有目录(不新建)** | ☑ | **不新建任何文件夹**，只往现有日期目录里放 |
| 型号 | `E3002781`（**固定，无开关**） | SN 绝不改写，只看 `Offline\E3002781\` |
| 跳过周日 / 周六 | ☑ / ☐ | 排除休息日 |
| 改写 USER | ☐（不改）⚠️ | 默认不勾选，保留模板的 `Debug`（⚠️ 会被 Aggregator 跳过不入库）；需要入库时请手动勾选 |
| 随机种子 | 空 | 填数字可复现同一批数据 |

## 分发前自动拦截

以下判为**无效**，不参与分发并在列表标红：

| 检查 | 说明 |
|------|------|
| 文件名段数不足 / 找不到 `FCT\d+` 段 | 无法定位机台 |
| SN 长度不足 8 | 无法取型号 |
| 型号不符合 `E`+7 位数字 | 与 `StationDetector.IsValidModel` 同口径 |
| 时间戳无法解析 | 末尾第 2 段须为 14~17 位合法时间 |
| 文件名机台号 ≠ 所在机台目录 | 防串台（源目录模式） |
| 文件名日期 ≠ 所在日期目录 | 防日期漂移（源目录模式） |

勾选「校验XML时间」后额外做**告警级**检查（源目录模式）：
XML 内最晚 `TIMESTAMP` 与文件名时间戳的日期是否一致、偏差是否超容差（默认 60s）。

## 修时间戳：自选文件夹范围

点【仅修复时间戳】不再一上来就整个根目录全改，而是先弹一个范围选择窗：

```
根目录：D:\Results        文件类型：xml / csv / log / txt
关键字: [______]   日期: [2026-07-01] ~ [2026-08-08]  [按日期勾选] [清过滤]
☑ Offline\E3002781\20260701    —    2 个文件，最新 2026-07-01 11:44
☑ Offline\E3002781\20260702    —    2 个文件，最新 2026-07-02 10:31
☐ Offline\E3009999\20260703    —    2 个文件，最新 2026-07-03 09:58
[全选][清空][反选]  ☐ 含所选目录的子目录   ☑ 同时更新父目录时间
```

| 能力 | 说明 |
|------|------|
| 列出候选 | 递归根目录，列出**所有直接含目标文件的文件夹**（相对路径 + 文件数 + 最新文件时间） |
| 默认全选 | 想全修就直接点【确定】；只修部分就先【清空】再勾 |
| 关键字过滤 | 按型号 / 日期 / 路径片段筛；【全选/清空/反选】**只作用于当前可见项**，不误伤被过滤掉的勾选 |
| 按日期勾选 | 目录名是 `yyyyMMdd` 的按日期范围批量勾选；非日期目录不参与、保持原状 |
| 含子目录 | 默认否（每个候选本身就是叶子目录）；勾上后选父目录就能一锅端，且**嵌套重叠的文件不会被处理两次** |
| 父目录冒泡 | 默认开：目录时间向上传到型号 / 类别 / 根（取子项最晚），**绝不越过根目录** |

确认框会把选中的文件夹列出来（前 8 个 + 剩余数量），日志区同步打印范围与结果汇总。

### 大数据量：不卡、能停、不白写

| 优化 | 做法 |
|------|------|
| **日志限流** | 工作线程只入队，UI 每 120ms 批量 `AppendText` 一次；明细日志最多 200 行，之后只每 400ms 报一行汇总 |
| **进度限流** | 百分比变且超 80ms 才刷一次（原来每个文件一次 `BeginInvoke`，直接把消息队列打爆——这才是“卡死且点不到中止”的真实原因） |
| **枚举也能取消** | 枚举阶段每 512 个文件查一次 token，百万文件也能立即停 |
| **跳过已正确** | 用枚举时就拿到的 `FileInfo` 缓存时间对比，已经对的**根本不写盘** |
| **少 open** | 要写时只 `File.OpenHandle` 一次，三个时间一起设（原来按路径设 = 3 次 open） |
| **取消不丢结果** | 中止时返回**已完成的部分报告**，成果条标橙色“已中止” |
| **列表不爆** | 候选文件夹最多显示 3000 项（剩下靠关键字过滤），但**全选/清空/反选按过滤命中的全量生效** |
| **扫目录不卡窗** | 选择框弹出后在后台线程扫，带【停止扫描】按钮与实时计数；一次枚举就算出「文件数 + 最新时间」，不额外 stat |

实测（单目录 5 万个 xml，`FCT_BIG_N=50000 dotnet run --project selftest\SelfTest.csproj -c Release`）：

```
50000 个文件全部处理（已改 50000）          耗时 3.66s   ≈ 13,700 个/秒
日志只产生 210 行（旧版会刷 50000+ 行 → UI 直接死）
第二次跑：50000 个已正确直接跳过、一个都不重写   耗时 0.48s
预先取消：1ms 返回；运行中取消：37ms 内停下
```

## 导出 xlsx（金银板 SN 台账）

点【导出 xlsx】得到**一个 Sheet、六列**的台账（零第三方依赖，直接写 OOXML）：

| 机台号 | 日期 | 金板 SN | 标注 | 银板 SN | 标注 |
|--------|------|---------|------|---------|------|
| FCT4 | 2026-07-01 | E3002781AFV75236898002K30500272 | Golden（金板） | E3002781AFV75236898002K30500274 | Silvery（银板） |

### 金银板就这两块

| 板 | SN | 说明 |
|----|-----|------|
| **金板 Golden** | `E3002781AFV75236898002K30500272` | 尾号 **272**，对应 `P_` 模板 |
| **银板 Silvery** | `E3002781AFV75236898002K30500274` | 尾号 **274**，对应 `O_` 模板 |

- 台账**只收这两块**：目录里其它 SN 的文件一律不进表，并在日志/弹窗里告知排除了多少个
- 认板是**整串精确比**（SN 全程不改写）；出现 `E3009999AFV…272` 这种改过型号的 SN 一概不认，当脏数据排除
- 每个【机台 + 日期】一行，金板一列、银板一列，各自后面跟一列 `Golden` / `Silvery` 标注
- 除此以外**不多任何列**（无型号 / 文件名 / 板数 / 状态）

### 数据源自动判断

| 情况 | 导出内容 |
|------|----------|
| 已扫描 / 已生成（有计划） | **这一批**的金银板（被跳过的不算，它们不会落盘） |
| 没有计划 | 直接扫 **目标根目录现有文件**（`Offline\{型号}\{日期}\*.xml`） |

其它细节：日期写成文本 `2026-07-01`（避开 Excel 按地区猬错）；首行表头已冻结；
默认文件名 `金银板SN台账_yyyyMMdd_HHmm.xlsx`，默认目录 = 目标根目录。

```bash

# 运行: dist\FCT-Distributor.exe  或  启动.bat（无 exe 方式，规避静态查杀）
```

## 版本历史

**v1.9.2**
- **配色跟随主程序换为黑白红三色体系**：【仅修复时间戳】按钮改主红浅调底
  （谨慎操作提示）、【导出 xlsx】回白底、标题条/日志窗归入中性灰阶（日志窗墨黑底）；
  只动颜色不碰布局，自检全绿

**v1.9.1（安全与健壮性加固）**
- **原子落盘**：模板生成先写 `.tmp` 再替换 —— 修复进程被杀/断电留下截断 XML、
  重跑又被「已存在同 SN」跳过的坏数据滞留问题
- **修时间戳范围框**：「停止扫描」改为返回已扫到的部分结果（旧实现会丢弃后全量重扫一遍）；
  扫描期间关窗不再可能因访问已释放控件而崩进程
- **目录时间冒泡上界**：带分隔符的前缀比较（`D:\Res` 不再误伤 `D:\Restaurant`）；
  未给上界时只冒泡到直接父级，绝不改到卷根
- **随机尾号耗尽**：600 次碰撞后报错而不是静默回落 "000000"；时间戳坑位失败即回滚
- **执行状态**：有失败项不算「已执行」，导出台账不再把没落盘的文件写成已生成
- **导出 xlsx 扫目标目录放后台线程**，大目录不再冻结界面
- `DirStampFrom` 跨天钳位边界 bug（23:59:59 + 1s = 次日零点）；`FileTimeUtil` 两段错误信息合并
- 自检新增「源目录分发 + 文件名解析边界」组（此前零覆盖）：Planner 校验/复制/幂等跳过、
  非法日期表驱动（非闰年 02-29 / 13 月 / 4-31）、防串台与防日期漂移；装饰性恒真断言改真校验；
  Xlsx 副本比对增加「两路解析到同一文件」的假绿防护

**v1.9.0**
- **SN 固定，绝不改写**：两个模板就是金/银板（`E3002781AFV…272` / `…274`），
  所以生成的文件**只可能出现在 `Offline\E3002781\{日期}\`**
- **删除「适配目录型号（改写 SN 前 8 位）」功能**（v1.6.0 引入，与实际业务不符）：
  文件名 SN 段与 XML 的 `DUT@ID` 现在一律原封不动
- 扫目录直接按固定型号过滤：`ScanExistingDateDirs(root, "E3002781")`，其它型号目录**根本不进候选**
- 台账认板改为**整串精确比**（不再按 SN 尾段）；新增 `SnExporter.Model` 常量
- 界面去掉那个勾选框，改为固定提示「型号固定 E3002781（SN 不改写）」
- 自检 67 项全通过（新增「只认 E3002781」「SN 一个字都没改」「E3009999 目录一条不进/一个文件不写」）

**v1.8.1**
- **修时间戳大数据量卡死 / 无法中止 —— 已修**：真因是“每文件一次日志 + 一次进度”的
  `BeginInvoke` 把 UI 消息队列打爆（叠上 `_txtLog.Lines` 每行 O(n) 分配）
- 日志改为**队列 + 每 120ms 批量刷**；明细最多 200 行，之后每 400ms 一行汇总；进度按百分比+80ms 限流
- 枚举阶段也可取消（每 512 个查 token）；中止时返回**部分报告**而不是丢弃
- **时间已正确的文件直接跳过**（新增 `Unchanged` 统计）；要写时只 open 一次句柄设三个时间
- 范围选择框：扫目录改到**后台线程** + 【停止扫描】+ 实时计数；列表限显 3000 项（勾选仍全量生效）
- 实测 5 万文件：3.66s 跑完（≨13,700 个/秒），重跑 0.48s，取消 37ms 内响应；自检 62 项全通过

**v1.8.0**

  所有含目标文件的文件夹（含文件数、最新文件时间），勾哪些就只修哪些
- 选择框支持：关键字过滤、按日期范围勾选、全选/清空/反选（只作用于可见项）、
