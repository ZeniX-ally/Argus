## 2026-08-14 — 打包/自检工具链修复（未发版，随下个版本号发布）

**打包脚本版本号写死 3.4.1，与 csproj 脱节。**

- 根因：`make_package.ps1` / `make_package_agg.ps1` 手写 `$ver = '3.4.1'`，
  csproj 已升 3.4.10，打出的 zip 仍叫 `Argus-v3.4.1.zip` / `Argus-Agg-v3.4.1.zip`（包名版本滞后于程序）；
- 修复：版本号自动读 `FctAggregator.csproj` 的 `<Version>`，找不到直接 throw，杜绝再脱节。

**自检内置模板检查在 SMB 共享盘上崩溃（win10 VM 实跑踩中）。**

- 根因：`Assembly.LoadFrom` 直接加载 `Y:\...\Argus.dll`（Samba 共享路径），
  Windows 更新后 .NET 抛 `FileLoadException 0x80131515「不支持的操作」`，整个自检被未处理异常打断
  （此前能过纯属环境行为未变）；
- 修复：先拷到本地临时目录再加载，资源清单检查语义不变；拷贝失败降级为单条 FAIL，不再崩整个自检。

**自检 http 推送计数竞态（1/570 偶发失败）。**

- 根因：`WaitUntil(col1.Count == 2)` 把心跳也算进总数 —— 推送器 worker 启动瞬间
  （`_lastHeartbeat` 初始 0）必发首条心跳，两条 fail 又几乎同时 POST，轮询窗口可能永远看不到「恰好 2 条」；
- 修复：只数 `type=fail` 的 body（心跳是噪音），其余断言不变。

**验证**：win10 VM 实跑自检 570 断言全绿 0 失败；三包产出 `Argus-v3.4.10.zip` /
`Argus-v3.4.10-update.zip` / `Argus-Agg-v3.4.10.zip`（版本号已正确）。

## v3.4.3 — 2026-08-13

**聚合链路加固：鉴权 / 重推可靠性 / 判活防时钟漂移 / 兜底重扫 / 飞书汇总告警 / 跨机台 XML。**

### 1. agg_token 共享访问令牌（安全）
- config 新增 `agg_token`：聚合端配置后，机台推送（POST fail/heartbeat）必须带 `X-Agg-Token` 头，
  浏览器看板需 `?token=` 访问或带同 header —— 不匹配一律 **403**，未配置则完全兼容旧部署（不开鉴权）。
- 一条改动同时关掉三个口子：机台推送无鉴权 / Web 看板无鉴权 / XML 下载无鉴权。

### 2. 推送可靠性（机台端）
- **成功路径按 seq 精确出队**：原实现整批发送成功后 `Clear()` 全清，部分失败时整队重推
  （已成功的重复发送）；现在逐个确认，成功项立即推进 `max_seq`，失败项留下轮重试。
- 心跳与 fail 推送统一携带 token 头（403 视为失败进断线补偿队列重推）。

### 3. 聚合端 HTTP 入库失败回 5xx
- 数据库写入失败（锁/磁盘/连接）时抛 `AggIngestException(machine, seq)`，HttpIngest/WebAggServer
  捕获后回 **500** + ERROR 日志带机台和 seq —— 机台端收到非 2xx 自动重推，不再静默丢事件。

### 4. 判活防时钟漂移
- **smb 判活改用 heartbeat.json 文件写时间**（LastWriteTime），不再信机台 JSON 里的 ts 字段
  （机台时钟快/慢不再误判在线离线）；ts 仅展示。
- **HTTP 心跳加 ts 未来时间校验**：机台时钟超前 >5 分钟记 warning 并回落当前时刻展示。

### 5. 兜底 fail 文件重扫
- 心跳轮询线程每 60 秒全量重扫一遍 `fail-*.json` 入队（FileSystemWatcher 在 SMB 上可能漏事件，

## v3.4.0 — 2026-08-12（聚合端 Phase 2 + B2 HTTP 双通道）

### 1. 功能

### 2. B2 双通道（HTTP 直推，飞书链路零影响）

### 1. 为什么拆
分发器能**改文件时间戳、按模板造数、批量投放 XML**。这些操作放在产线机台的主程序里，
误点一次后果很重（会污染真实测试数据）。所以按「彻底分家」处理：

源码从 `fct-aggregator-cs/modules/Distributor/` 用 `git mv` 移到顶层 `fct-distributor/`

## v2.7.1 — 2026-07-30

修一个 v2.7.0 的手感 bug：**单击卡片弹出预览时，预览里的文字是全选（蓝底）状态**，
看着就像"单击顺手把文字选中了"，而且再点一下就把选区冲掉了。

### 原因
WinForms 的 `TextBox` 只要是**因为窗口激活 / Tab 拿到焦点**就会**自动全选**内容
（鼠标点进去的焦点不会）。预览 popup 里那个只读明细 TextBox 是唯一的 tab-stop 控件，
`Show()` + `Activate()` 后焦点自动落到它身上 → 全选。

### 修法（三层，任一层失效也不漏）
1. 明细 TextBox 与合并清单 ListView 都设 `TabStop = false` —— 不再被激活焦点选中；

```sql
  AND NOT EXISTS (存在活跃维修记录: status NOT IN ('resolved','closed'))
  AND NOT EXISTS (已写入 dismissed_todos)
GROUP BY f.fail_reason, f.station_id
```

带来三个好处：
- **不会与真实数据不一致**（快照表最典型的坑）；
- **确认后自动消失**：靠维修记录的存在性拦截，不需额外标记；
- **复发自动重现**：记录拖到「已完成」后不再算活跃，同故障项再 FAIL 就自动回到待办。

### 4. 与【从FAIL选故障项】的分工

本次是**用 C# / .NET 8 (WinForms) 完整重构**，从 Python + PyQt6 迁移而来。功能全部保留并修复了多个真实机台上暴露的问题。

---

## 一、重构动机

| 问题 | Python 版 (v1.0.2) | C# 版 (v2.0.0) |
|------|-------------------|----------------|
| **杀毒误报** | PyInstaller / Nuitka 打包常被杀毒（尤其 SentinelOne）拦截查杀 | 改用 .NET，运行微软签名的 dotnet 运行时，规避行为查杀 |
| **发布体积** | 129 MB（zip 42 MB） | **1.2 MB**（框架依赖，机台需装 .NET 8）|
| **启动方式** | 单个大 exe | dotnet 运行 DLL / 小启动器 exe |

---

## 二、杀毒兼容性改进（本次重点）

Python 版在机台上被 SentinelOne 反复查杀，C# 版针对性解决：

1. **去除"自解压"行为**：不再用自包含单文件（避免运行时释放 WPF native DLL 到临时目录 —— 该行为被 EDR 判定为恶意 dropper）。
2. **去除"注册表 Run 键自启"**：Python 版写注册表 `Run` 键（病毒典型驻留手法，杀毒必查）→ 改为**启动文件夹快捷方式**。
3. **去除"启动即自我持久化"**：开机自启不再随程序启动自动写入 → 改为 **Debug 页手动开关**（消除 EDR 最敏感的行为特征）。
4. **不分发 exe（可选）**：提供 `启动.bat` 用 dotnet 运行 DLL，机台无 exe 可被静态查杀。

## 三、功能修复与改进

### 1. XML 解析（核心）
- **修复根节点识别**：Python 版找 `<root>`，但真实机台数据是 `<BATCH>` 格式 —— 之前完全解析不出数据。C# 版正确解析 BATCH 格式。
- **FCT.ini 读取修复**：改用**共享读取模式**，可读取正被 FCT 测试软件占用的文件（Python 的 open 默认允许，C# 需显式设置）。
- **FCT.ini 多路径查找**：config 路径找不到时自动尝试常见路径，并给出诊断信息。

### 2. 统计逻辑修复
- **当日统计修复**：改用**目录日期 (test_date)** 判断当日，不再依赖 XML 内部时间戳格式 —— 解决"累计有 FAIL、当日无 FAIL"的问题。
- **良率口径统一**：良率 = PASS /(PASS + FAIL)，中断不计入分母。
- **产品总数**：按 SN 去重统计。
- **XML 文件总数**：统计磁盘真实文件数（含 debug）。

### 3. 分类逻辑（保持一致）
- 产品结果看文件名前缀：`P_`=PASS、`F_`=FAIL、`O_`=中断。
- 中断细分：有真实 fail 项→FAIL，无→INTERRUPTED。
- `Get Unit Information` 的 fail 不计入不良。
- `USER=debug` 的数据跳过不入库。
- 无 station_id 时用 UNKNOWN 继续扫描入库（但不推送飞书）。

### 4. 界面优化
- **主页布局**：统计面板 20% / 日志框 80%，看跑码更舒展。
- **扫描跑码**：历史扫描逐条打印日志 + 统计计数实时增长。
- **状态栏**：徽章式设计（彩色状态灯），替代原来的文本标记。
- **设备状态页**：原生控件双列布局，一屏铺满不滚动，刷新不闪烁（控件复用 + 双缓冲）。
- **日志窗口**：显示启动后全部日志，实时追加，彩色分级。

### 5. 已移除功能（Python 版曾有，本次不含）
- 日报生成（xlsx）—— 因 xlsx 无法直接推送飞书且引发文件占用错误，已整体移除。
- 多机聚合（central_aggregator）—— 已下线。
- HTTP API —— 单机部署不需要（如需要可恢复）。

## 五、部署说明

**前置要求**：机台需安装 **.NET 8 Desktop Runtime**（一次性）。

**部署步骤**：
1. 解压 `FCT-Aggregator-CS.zip`
2. 检查 `config.json`：
   - `station_id`：留空则按机台 IP 自动识别（172.28.55.11~18）
   - `results_root`：测试结果目录（默认 `D:\Results`）
   - `fct_ini_path`：`C:\FTS\Apps\PEU\Cfg\FCT.ini`
   - `webhook_url`：飞书群机器人地址
3. 双击 `FCT-Aggregator.exe` 或 `启动.bat` 运行
4. 需要开机自启：打开软件 → Debug 页 → 点"开机自启"
