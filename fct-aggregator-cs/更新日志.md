# FCT-Aggregator 更新日志

## v2.4.0 — 2026-07-29

维修面板新增**待办栏**：每次检测到 FAIL 都需工程师确认问题，确认后自动进入看板工作流。
无 DDL 变更（只新增一张很小的 `dismissed_todos`，`CREATE TABLE IF NOT EXISTS`）。

### 1. 新增【待办】视图（新增 `TodoPanel.cs`）
- 维修记录页顶部的视图切换由【看板 / 列表】扩为【**看板 / 列表 / 待办**】。
- 待办列表自动列出 `test_records` 里**尚无人处理**的 FAIL 测试项，按故障项去重，
  展示：故障项目 / 出现次数 / 首次出现 / 最近出现 / 型号 / 机台。
- 「只看本机台」开关默认开（与【从FAIL选故障项】一致）。

### 2. 三个动作
| 动作 | 行为 |
|------|------|
| **确认问题** （双击行 / 按钮 / 右键） | 弹 `TodoConfirmForm` 补填维修人 + 严重度 → 自动建一条 `status='open'` 维修记录 → 出现在看板「未完成」列 |
| **忽略** | 写入 `dismissed_todos`，该故障项不再出现在待办（**不**创建维修记录） |
| **刷新** | 重新聚合（切页回来也会自动刷） |

### 3. 为什么不建待办表
待办 = `test_records` 的**实时聚合视图**，而不是快照表：

```sql
WHERE f.result='FAIL' AND TRIM(f.fail_reason) <> ''
  AND NOT EXISTS (存在活跃维修记录: status NOT IN ('resolved','closed'))
  AND NOT EXISTS (已写入 dismissed_todos)
GROUP BY f.fail_reason, f.station_id
```

带来三个好处：
- **不会与真实数据不一致**（快照表最典型的坑）；
- **确认后自动消失**：靠维修记录的存在性拦截，不需额外标记；
- **复发自动重现**：记录拖到「已完成」后不再算活跃，同故障项再 FAIL 就自动回到待办。

### 4. 与【从FAIL选故障项】的分工
| | 待办栏 | 【从FAIL选故障项】 |
|---|---|---|
| 触发 | **被动**，自动列出没人管的 | **主动**，手工挑 |
| 范围 | 只有待处理的 | 全部（含已处理） |
| 能力 | 快速确认建单 | 可深扫 XML、可多选、可合并为一条 |

两者不冲突，原按钮完整保留。

### 5. 新增 API
| 方法 | 说明 |
|------|------|
| `Database.ListPendingTodos(stationId)` | 待办项列表（`TodoItem`：故障项 / 机台 / 型号 / 次数 / 首次与最近出现） |
| `Database.DismissTodo(failItem, stationId, model)` | 忽略某故障项 |
| `Database.AcknowledgeTodo(failItem, stationId, model, resolver, severity)` | 确认问题，返回新建维修记录 ID |

### 6. 踩到的坑
- `TodoPanel` 的控件字段**不能写 `readonly`**：它们在 `BuildUi()`（非构造函数体）里赋值，
  `readonly` 会报 `CS0191`（先写成 `= new()` 又在 `BuildUi()` 里重赋也不行）。现统一 `= null!`。
- 自检工程的 `SelfTest.csproj` 用的是**显式 `<Compile Include>` 清单**（`EnableDefaultCompileItems=false`），
  新增的 `TodoPanel.cs` 必须手动加进去，否则 `MaintenancePanel.cs` 会报 `CS0246 未能找到 TodoPanel`。

### 7. 自检
114 项全通过（本次未新增数据层断言 —— 待办查询为纯 SQL 聚合，无新增可变状态）。
构建 0 警告 0 错误。

### 升级方式
用更新包（`FCT-Aggregator-v2.4.0-update.zip`，不带 config 与数据库）直接覆盖即可。
首次启动自动建 `dismissed_todos` 表，无需人工干预。

## v2.3.0 — 2026-07-29

维修记录录入方式重做：故障项目**从 FAIL 记录里挑**，不再敲字；去掉设备型号/SN；维修人可下拉选。
无 DDL 变更，数据库原地复用。

### 1. 新按钮【从FAIL选故障项】（新增 `FailItemPicker.cs`）
- 从库里的 FAIL 记录里汇总出测试项，**按故障项去重**，一项一行；
  列出出现次数 / 最近出现 / 涉及型号 / 涉及机台，**全程不显示 SN**。
- 勾一个或多个 → 确定 → 直接写进维修记录的「故障项目」。
  默认**每个故障项建一条**（看板上各自流转状态）；表单上可勾「合并为一条」。
- 两级取数：
  | 模式 | 数据源 | 特点 |
  |------|--------|------|
  | 打开即有（默认） | `test_records.fail_reason` | 秒出，但每条 FAIL 只有**首个**失败项 |
  | 【深扫 XML】 | 重解析 `xml_path` | 拿到**全部**失败项；后台线程、可随时停、进度限流（每 300ms）；XML 不在原路径时用库里首项兜底并提示数量 |
- 满足过滤、全选/清空、双击行即勾选、「只看本机台」开关（默认开）。

### 2. 表单去掉设备型号 / 设备 SN
- 维修记录只关心「哪个测试项坏了」，SN 与它无关 —— 表单两行输入删除（行数 10 → 8）。
- 列表视图「设备SN」列 → 换成「故障描述」；看板卡片第 2 行与悬停提示也不再显示 SN/型号。
- **DB 列与导出列保留**（`equipment_model` / `equipment_sn`）：历史记录里的值不丢、旧报表格式不变；
  新建的记录这两列为空。
- `MaintenanceForm` 里已不存在 `_model` / `_sn` 控件（自检用反射验证）。

### 3. 维修人员：可下拉选 + 【+ 人员】按钮管名单（新增 `ResolverManager.cs`）
- 表单的「维修人员」由 `TextBox` 改为 `ComboBox`（`DropDown` + 自动补全），
  右边新增一个【**+ 人员**】按钮，点开就是名单管理。
- 新建表 `resolvers`（`CREATE TABLE IF NOT EXISTS`，对旧库无风险；
  `name TEXT UNIQUE COLLATE NOCASE` —— 同一个人不会因大小写/空格出两条）。
- **下拉候选 = 名单 ∪ 历史记录里用过的名字**（名单在前），所以：
  - 一条维修记录都没有时也能先把班组名单录进去（以前候选只能从历史里长，空库时下拉是空的）
  - 敏错的名字可以从名单里删（以前敲错一次就永久赖在候选里）
- 名单管理支持：
  | 动作 | 行为 |
  |------|------|
  | **添加** | 输名字 → 【添加】（回车也行）；重复/空名字拒掉并提示 |
  | **删除** | 只从名单删，**不动历史记录**；确认框会告知该名字在多少条记录里出现过 |
  | **改名** | 可选「同时改掉历史记录里的旧名字」（治错别字），**默认不勾** —— 改名单 ≠ 改历史数据 |
  | 列表标注 | 只在历史记录里出现、不在名单里的名字会标「(仅历史记录)」 |
- 保存维修记录时，手敲的新名字**自动登记进名单**（“敲一次就记住”的行为保留）。

### 3b. 维修人员支持**多选**（一条记录多个维修人）
- 维修人一行变成：`下拉框` + 【**选择**】+ 【**+ 人员**】。
  【选择】打开 `ResolverPickerForm`（`CheckedListBox` 多选），可搜索 / 全选 / 清空，
  底部还能直接「添加并勾选」新人员，不用先跑去名单管理。
- 存储：仍用 `maintenance_records.resolver` 一列，多人存成 **`张三、李四`**（**无 DDL 变更**）。
- 新增 `ResolverUtil`（拆 / 合 / 成员级包含 / 成员级改名），并把下面三处全部改成**成员级**：
  | 位置 | 不改会怎样 |
  |------|-----------|
  | `DistinctResolvers()` | 候选里会冒出「张三、李四」这种**组合项** |
  | `CountRecordsByResolver()` | 按整列相等比 → 多人记录全部漏算（而用 LIKE 则「张三」会误中「张三丰」） |
  | `RenameResolver(sync)` | 整列 `SET resolver=@new` → **把同事抹掉**（「张三、李四」会变成「张三三」）；现在逐行拆开只换那个人 |
- 拖到【已完成】的补填框 `QuickResolveForm` 同样挂上【选择】，也能多选。
- 手敲时兼容 `、` `,` `，` `/` `;` `；` `|` 等分隔符，保存时统一规范为 `、`；
  多人名字会**逐人**登记进名单（不会把整串当成一个人）。

### 4. 新增 API
| 方法 | 说明 |
|------|------|
| `Database.FailItemSources(stationId, limit)` | FAIL 记录的可用作维修依据的源行（`FailItemSource`，**结构里根本没有 Sn 字段**） |
| `Database.DistinctResolvers(limit)` | 历史维修人（按使用次数倒序） |
| `Database.ListResolvers()` | 下拉候选 = 名单 ∪ 历史（名单在前，大小写不敏感去重） |
| `Database.RosterResolvers()` / `AddResolver` / `DeleteResolver` / `RenameResolver(old,new,sync)` / `CountRecordsByResolver` | 维修人员名单增删改查（均为**成员级**） |
| `ResolverUtil.Split / Join / Normalize / Contains / Replace` | 多人字段的拆合与成员级操作 |
| `FailItemPickerForm.Aggregate(sources)` | 纯函数去重聚合（供自检直接验去重逻辑） |
| `MaintenanceForm.BatchResults()` | 批量模式下要落库的记录集合（N 条 或 合并为 1 条） |

## v2.2.0 — 2026-07-29

维修记录页看板化。只动维修记录相关的 4 个文件 + 2 个新文件，
`Engine` / `Processor` / `XmlParser` / `Classifier` / `AppState` / `FeishuNotifier` /
`DebugPanel` / `FailListPanel` / `DeviceStatusPanel` 一律未动。

### 1. 看板视图（新增 `MaintenanceBoard.cs`）
- 维修记录页顶部新增【看板 / 列表】切换，**默认看板**；原列表视图完整保留。
- 5 列按处理流程排：**未知问题 → 正在排查 → 未完成 → 进行中 → 已完成**，
  列头带真实计数徐章（走 `CountMaintenanceByStatus()`，**不受每列加载上限影响**）。
- **拖拽卡片到另一列即改状态**；拖到【已完成】会先弹轻量补填框（维修人 / 维修措施，
  【确定】/【跳过】/【取消】三条路，取消 = 整个状态变更撒销）。
- 卡片全自绘（`OnPaint`，不放子控件）：子 Label 会吞掉鼠标事件导致拖不起来，

- 拖拽阈值用 `SystemInformation.DragSize`（否则单击就起拖、双击编辑会失灵）；
  每张卡自己也 `AllowDrop=true` 并把拖拽事件转发给所属列（WinForms 里子控件不开 AllowDrop 时拖拽事件不会冒泡）。
- 同列拖回 = 空操作，不打库；悬停列高亮；落下后**只重建受影响的两列**，不整页重载。

### 2. 维修记录可以编辑了
- `MaintenanceForm` 改为**新增 / 编辑双模**（`MaintenanceForm(stationId, edit)`），
  双击卡片或双击列表行即进编辑，标题显示「编辑维修记录 #12」。
- 编辑时操作副本（`Clone()`），点【取消】不会污染看板/列表里的原对象。
- 新增 `Database.UpdateMaintenance()` 全字段 UPDATE（之前只有单改状态的 `UpdateMaintenanceStatus`）。

### 3. 顺手治好的旧毛病
- 【**备注字段之前没有输入口**】：库里有列、模型有、导出也有这一列，
  但表单里从来没有输入框 → 永远是空。现已加多行备注框。
- 【**`updated_at` 之前没被读出来**】：建表就有这列、`UpdateMaintenanceStatus` 也写它，
  但 `ListMaintenance` 的 SELECT 从来没取、模型里也没这个字段。现已取出，
  列表新增「最后更新」列，导出新增第 12 列「更新时间」。
- 【**中文字典有两份**】：`StatusZh`/`SeverityZh` 在 `MaintenancePanel` 与 `MaintenanceExporter` 各一份，
  加状态时漏改一处 → 导出直接吐原始英文 key。现统一到新文件 **`MaintenanceStatus.cs`（单一来源）**。
- 【**`LIMIT 200` 硬编码**】：看板要同时显示 5 列时会被截断、各列数量失真。
  现改为参数（列表 500 / 看板每列 120），并用单条 `GROUP BY` 拿真实总数做列头徐章。
- 【**往期记录会被顶到最前**】：`CreateMaintenance` 手动指定过往日期时，
  `updated_at` 以前会取「现在」。现与 `created_at` 共用同一个 `COALESCE` 取值。
- 表单新增【当前状态】下拉（新建默认「未完成」）；右键菜单的「标记为…」改为 5 个状态 + 新增「编辑…」。

### 4. 数据库迁移（自动、幂等、带备份）
- 状态体系由 4 个改为 5 个：新增 `unknown` / `investigating`，**取消 `closed`**（并入 `resolved`）。
- `Database.Init()` 会把库里历史的 `status='closed'` 一次性改写为 `'resolved'`；
  **改写前先把 db 备份为 `{db}.bak-yyyyMMdd`**，备份失败则跳过迁移
  （此时 UI 仍能靠 legacy 映射把 `closed` 显示为「已完成」，不影响使用）。
- 迁移只改 `status`，**不动 `updated_at`** —— 保留记录真实的最后人工更新时间。
- **无任何 DDL 变更**（`status` 是 TEXT 且无 CHECK 约束，加值不需建表改造）。

### 5. 两个现场反馈的 bug（同版内修复）

- 【**看板卡片右键没反应**】卡片是自绘 `Panel`，只处理了左键（起拖/双击），
  右键既没菜单也不会冒泡。现在：
  `MaintenanceCard.ContextRequested` → `StatusColumn.CardContextRequested` → `MaintenanceBoard.ContextRequested`
  → `MaintenancePanel.BuildRecordMenu()`；**看板卡片与列表行共用同一份菜单**
  （`#ID 标题` / 编辑 / 标记为五个状态（当前项打勾且置灰）/ 删除）。
  右键按下时会清掉 `_pressed`，**右键按住拖动不会误走拖拽分支**。
- 【**删完再新建 id 不回 1**】建表用 `AUTOINCREMENT`，SQLite 把用过的最大值记在
  `sqlite_sequence` 里**永不复用** → 只有一条 `id=1`，删了再建变 `id=2`。
  `DeleteMaintenance` 现在在**同一事务**里把游标回抨到 `MAX(id)`：
  | 场景 | 下一个 id |
  |------|-----------|
  | 删空了 | 回到 **1** |
  | 删的是最后一条（1,2,3 删 3） | **3**（接着用） |
  | 删的是中间那条（1,2,3 删 2） | **4**（不回填空号，避开与已导出报表上的旧 #N 撞车） |
  删不存在的 id 时不动游标；`sqlite_sequence` 无该表行时 UPDATE 影响 0 行，无害。
  （`test_records` 不动 —— 那里的 id 无业务含义、去重靠 `xml_path UNIQUE`。）

## v2.1.0 — 2026-07-27

在 v2.0.0（C# 重构版）基础上新增两块功能，无破坏性变更，数据库可原地升级（表结构不变）。

### 1. FAIL 记录页（新增页面）
- 底部按钮栏新增「FAIL记录」页（`FailListPanel.cs`）。
- 列表展示本机所有 FAIL 记录：SN / 首个失败项 / 型号 / 时间，支持「刷新」。
- **双击某行 → 弹出报告式 XML 查看器**（`XmlViewerForm`）：
  头部信息（SN / 型号 / 机台 / 总体结果 / 时间）+ **完整测试流程（全部测试项，失败项标红）**，
  而不是只显示失败项，便于判断失败发生在流程哪一步、前后项是否异常。
- 数据来源：`Database.AllFails(stationId)`（按机台过滤，时间倒序）。

### 2. 维修记录导出（新增功能）
- 维修记录页工具栏新增「导出」按钮，下拉两种格式（`MaintenanceExporter.cs`）：
  - **Excel (.xlsx)** —— 零第三方依赖生成标准 OOXML，表头加粗、ID 为真数值，可直接透视/统计。
  - **CSV (.csv)** —— UTF-8 BOM，Excel 打开中文不乱码。
- 导出内容为**当前筛选结果**（跟随页面上的状态筛选：全部/待处理/进行中/已解决/已关闭）。
- 导出列：ID / 故障项目 / 设备型号 / 设备SN / 故障描述 / 严重度 / 状态 / 维修人 /

## v2.0.0（C# / .NET 重构版） — 对比 Python v1.0.2

本次是**用 C# / .NET 8 (WinForms) 完整重构**，从 Python + PyQt6 迁移而来。功能全部保留并修复了多个真实机台上暴露的问题。

## 一、重构动机

| 问题 | Python 版 (v1.0.2) | C# 版 (v2.0.0) |
|------|-------------------|----------------|
| **杀毒误报** | PyInstaller / Nuitka 打包常被杀毒（尤其 SentinelOne）拦截查杀 | 改用 .NET，运行微软签名的 dotnet 运行时，规避行为查杀 |
| **发布体积** | 129 MB（zip 42 MB） | **1.2 MB**（框架依赖，机台需装 .NET 8）|
| **启动方式** | 单个大 exe | dotnet 运行 DLL / 小启动器 exe |

## 二、杀毒兼容性改进（本次重点）

Python 版在机台上被 SentinelOne 反复查杀，C# 版针对性解决：

1. **去除"自解压"行为**：不再用自包含单文件（避免运行时释放 WPF native DLL 到临时目录 —— 该行为被 EDR 判定为恶意 dropper）。
2. **去除"注册表 Run 键自启"**：Python 版写注册表 `Run` 键（病毒典型驻留手法，杀毒必查）→ 改为**启动文件夹快捷方式**。
3. **去除"启动即自我持久化"**：开机自启不再随程序启动自动写入 → 改为 **Debug 页手动开关**（消除 EDR 最敏感的行为特征）。
4. **不分发 exe（可选）**：提供 `启动.bat` 用 dotnet 运行 DLL，机台无 exe 可被静态查杀。

---

## 三、功能修复与改进

### 1. XML 解析（核心）
- **修复根节点识别**：Python 版找 `<root>`，但真实机台数据是 `<BATCH>` 格式 —— 之前完全解析不出数据。C# 版正确解析 BATCH 格式。
- **FCT.ini 读取修复**：改用**共享读取模式**，可读取正被 FCT 测试软件占用的文件（Python 的 open 默认允许，C# 需显式设置）。
- **FCT.ini 多路径查找**：config 路径找不到时自动尝试常见路径，并给出诊断信息。

### 2. 统计逻辑修复
- **当日统计修复**：改用**目录日期 (test_date)** 判断当日，不再依赖 XML 内部时间戳格式 —— 解决"累计有 FAIL、当日无 FAIL"的问题。
- **良率口径统一**：良率 = PASS /(PASS + FAIL)，中断不计入分母。
- **产品总数**：按 SN 去重统计。
- **XML 文件总数**：统计磁盘真实文件数（含 debug）。

### 3. 分类逻辑（保持一致）
- 产品结果看文件名前缀：`P_`=PASS、`F_`=FAIL、`O_`=中断。
- 中断细分：有真实 fail 项→FAIL，无→INTERRUPTED。
- `Get Unit Information` 的 fail 不计入不良。
- `USER=debug` 的数据跳过不入库。
- 无 station_id 时用 UNKNOWN 继续扫描入库（但不推送飞书）。

### 4. 界面优化
- **主页布局**：统计面板 20% / 日志框 80%，看跑码更舒展。
- **扫描跑码**：历史扫描逐条打印日志 + 统计计数实时增长。
- **状态栏**：徽章式设计（彩色状态灯），替代原来的文本标记。
- **设备状态页**：原生控件双列布局，一屏铺满不滚动，刷新不闪烁（控件复用 + 双缓冲）。
- **日志窗口**：显示启动后全部日志，实时追加，彩色分级。

### 5. 已移除功能（Python 版曾有，本次不含）
- 日报生成（xlsx）—— 因 xlsx 无法直接推送飞书且引发文件占用错误，已整体移除。
- 多机聚合（central_aggregator）—— 已下线。
- HTTP API —— 单机部署不需要（如需要可恢复）。

## 五、部署说明

**前置要求**：机台需安装 **.NET 8 Desktop Runtime**（一次性）。

**部署步骤**：
1. 解压 `FCT-Aggregator-CS.zip`
2. 检查 `config.json`：
   - `station_id`：留空则按机台 IP 自动识别（172.28.55.11~18）
   - `results_root`：测试结果目录（默认 `D:\Results`）
   - `fct_ini_path`：`C:\FTS\Apps\XPT\Cfg\FCT.ini`
   - `webhook_url`：飞书群机器人地址
3. 双击 `FCT-Aggregator.exe` 或 `启动.bat` 运行
4. 需要开机自启：打开软件 → Debug 页 → 点"开机自启"
