# FCT-Aggregator 更新日志

## v2.7.1 — 2026-07-30

修一个 v2.7.0 的手感 bug：**单击卡片弹出预览时，预览里的文字是全选（蓝底）状态**，
看着就像"单击顺手把文字选中了"，而且再点一下就把选区冲掉了。

### 原因
WinForms 的 `TextBox` 只要是**因为窗口激活 / Tab 拿到焦点**就会**自动全选**内容
（鼠标点进去的焦点不会）。预览 popup 里那个只读明细 TextBox 是唯一的 tab-stop 控件，
`Show()` + `Activate()` 后焦点自动落到它身上 → 全选。

### 修法（三层，任一层失效也不漏）
1. 明细 TextBox 与合并清单 ListView 都设 `TabStop = false` —— 不再被激活焦点选中；
2. `OnShown` / `Activated` / TextBox 的 `GotFocus` 里统一调 `ClearAutoSelection()`：
   `SelectionLength = 0` + `ActiveControl = null`（焦点交给窗口本身，Esc 关闭仍有效）；
3. 手动用鼠标划选、`Ctrl+C` 复制**完全不受影响** —— 鼠标点进去的焦点本来就只放光标。

### 自检
新增 3 条断言：预览窗在打开列表里、**刚弹出时选区长度为 0**、焦点不在输入框上。
全部通过；GUI 与桌面提示冒烟通过；构建 0 警告 0 错误。

## v2.7.0 — 2026-07-30

卡片放不下的东西终于有地方看了：新增**单击预览**（`CardPreview.cs`），
并且**合并的 fail 项在卡片与预览上同时显示**。

### 1. 单击卡片 = 弹详情预览
- 两种卡片（`TodoCard` / `MaintenanceCard`）都支持，走 `BoardCardBase.PreviewRequested`。
- 预览是个无边框 popup：**失焦 / Esc / 打开下一个 / 看板 Reload / 切页 / 切视图** 都会自动关，
  全局只留一个实例（`CardPreviewForm.CloseCurrent()`）。
- 内容分三块：
  | 区域 | 内容 |
  |---|---|
  | 标题条 | 完整故障项名（不再被卡片宽度截断）+ 副标题（状态 · 优先级 · 次数 / 合并项数） |
  | 明细 | 只读 TextBox，**可选中复制**（现场经常要把测试项名贴到别处） |
  | 合并的 fail 项 | ListView：**每个原始测试项 + 它自己的真实不良次数**（`CountFailByItems` 一次 IN 查询） |
- 位置贴着卡片右侧弹，越界自动翻到左侧 / 贴边，保证完整可见。

⚠ **必须延迟一个 `SystemInformation.DoubleClickTime` 再弹**，否则双击（确认/编辑）会先闪一下预览。
双击时会 `CancelPreviewTimer()`，并用 `_suppressClick` 拦掉双击后的第二个 `MouseUp`
（消息顺序 Down→Up→Click→Down→**DoubleClick**→Up，不拦就会在双击后 500ms 又弹出来）。
右键、拖拽起拖也都不算单击。

### 2. 合并的 fail 项现在**卡上也能看到**
- 待办卡：高度随内容变（88 / 104 / 120），合并过的卡直接列出**前两个**原始测试项，
  再多的用 `+N 项` 提示，完整清单看预览。
- 维修记录卡：确认待办时写进备注的清单（`来源测试项：`）由
  `TodoGrouping.ParseSourceItems()` 回读 —— **不额外查库**（上百张卡每张一次 SQL 会卡），
  卡上多一行「合并 N 项：xxx +M」，卡高 80→100。
- 预览里维修卡会优先用**关联的待办行**（`GetTodoByMaintenance()`）取权威清单，
  取不到才回退到备注解析。
- 备注里的清单写入/回读统一走 `TodoGrouping.BuildSourceItemsNote()` / `ParseSourceItems()`，
  预览的「备注」行会把这一大段剔掉（它已单独成表，不重复堆）。

### 3. 新增 API
| 方法 | 说明 |
|---|---|
| `Database.CountFailByItems(items, stationId)` | 每个原始测试项各自的真实不良次数（一次 IN 查询） |
| `Database.GetTodoByMaintenance(maintenanceId)` | 由维修记录反查关联的待办行 |
| `TodoGrouping.BuildSourceItemsNote()` / `ParseSourceItems()` | 合并清单的写入 / 回读（单一来源） |
| `TodoCard.BuildPreview()` / `MaintenanceCard.BuildPreview()` | 预览内容（与卡片同一份数据，不会两处走歧） |

### 4. 自检
- 新增 15 条断言：单击排队 / 双击取消 / 双击后第二下 MouseUp 不再排 / 右键不弹 /
  未按下就松手不算单击；预览内容完整性；**优先级算区间内次数而非累计**（12 次→中，30 次→高）；
  合并卡比单项卡高；维修卡从备注回读清单；预览备注不重复堆清单。
- ⚠ 踩坑：自检里**不能真调 `OnMouseMove` 触发 `DoDragDrop`** —— 它会进模态拖拽消息循环，
  无鼠标输入时直接挂死（第一次跑把自检卡到 400s 超时）。改成只验「没按下就松手不算单击」。
- 全部通过；GUI 与桌面提示冒烟通过；构建 0 警告 0 错误。

## v2.6.0 — 2026-07-30

待办从「实时聚合视图」升级为**登记表**：只扫近一个月、同类测试项自动合并成大项、
登记后永久保留、可按时间区间查看、按 fail 次数排优先级。
新增表 `todo_items` / `app_meta`（都是 `CREATE TABLE IF NOT EXISTS`，旧库零风险）。

### 1. 只扫近一个月（`todo_scan_days`，默认 30）
- `SyncTodoItems(scanDays)`：只把 `test_date >= 今天-N天` 的 FAIL 并入待办。
  老库里几年的历史不良**不会**一次性灌成几千张卡。
- **增量**：`app_meta.todo_sync_last_id` 水位线，只处理 id 更大的行 → 反复同步不会重复累加次数。
- 触发点：历史扫描结束、每条实时 FAIL 入库后、看板每次 Reload、调试页【待办同步】。

### 2. 大项合并（`TodoGrouping.cs`）
归一化出 `group_key`，**同 key = 同一张卡**：

| 情况 | 结果 |
|---|---|
| `6.1.1.1 5V_Rail` / `6.1.1.2 5V_Rail` | ✅ 合并（步骤号不参与） |
| `CAN_Bus_Test_CH1` / `..._CH2`、`pin3`/`pin7`、`U12`/`U7` | ✅ 合并（通道/位号 token 丢弃） |
| `BSW_v_Kl30UC(XCP)` / `BSW_v_Kl30UC (KL30_LS_UC)(XCP)` | ✅ 合并（括号里的限定词/测量手段不参与） |
| `Check_5V_Rail` / `Check_12V_Rail`、`Delay_100ms`/`200ms` | ❌ **不合并**（数字+单位有物理含义，保留） |
| `Check(Voltage)` / `Check(Current)` | ❌ **不合并**（去括号后不足 2 个 token ⇒ 括号即核心语义，不丢） |

- 卡片标题 = 组内**最短**的原始项名（去步骤号），稳定不跳；原始项名全部存在 `variants` 里，
  确认建单时写进备注，可追溯。
- 真实库实测：7 个原始故障项 → 6 个大项（只合并了该合的那一对，无过度合并）。
- 调试页新增【合并预览】，上线前可先看本机数据会怎么归并。

### 3. 登记后永久保留（`todo_items`）
- 待办不再是 SQL 视图，而是一张**只改状态、从不删除**的登记表：
  不良滑出 30 天扫描窗口后，待办仍在（除非被处理完）。
- 状态机（`ReconcileTodoStates`，每次同步后跑，幂等）：

  | 触发 | 结果 |
  |---|---|
  | 确认问题 | `state=ack` + `maintenance_id` 关联，离开待办列 |
  | 关联记录拖到「已完成」 | `state=resolved`，记 `resolved_at` |
  | `resolved` 之后又出新不良 | 回到 `pending`（复发重现），**次数继续累加不清零** |
  | 关联记录被删 | 回到 `pending`（待办删不掉） |

### 4. 时间区间自由查看
- 工具栏新增【待办区间】：近 7 天 / 近 30 天(默认) / 近 90 天 / **全部（永久保留）** / 自定义…
- 区间统计是**现算**的：从 `test_records` 按区间聚合后再用同一套 `KeyOf` 归并，
  所以 `RangeCount`（区间内次数）与 `TotalCount`（累计次数）可以同时显示。
- 选中的区间只影响**显示**，不删除任何待办；切回「全部」就都回来了。

### 5. 按 fail 次数排优先级
- 待办列按次数倒序（有区间时按区间内次数），列顶就是最该先修的。
- 卡片左侧色条 + 徽章标注优先级：**高 ≥20 次（红）/ 中 ≥5 次（橙）/ 低（灰）**，
  阈值集中在 `TodoGrouping.HighThreshold / MediumThreshold`。
- 确认框里严重度默认按优先级预选（高 → 严重）。
- 卡片加高到 88px，四行：标题 / 优先级+次数 / 合并数+型号·机台 / 最近出现+「必须确认」。

### 6. API 变化
| 旧 | 新 |
|---|---|
| `ListPendingTodos(stationId)` | `ListTodoView(from?, to?, limit)` |
| `AcknowledgeTodo(failItem, station, model, resolver, severity)` | `AcknowledgeTodo(todoId, resolver, severity, status)` |
| — | `SyncTodoItems(scanDays)` / `CountPendingTodos()` / `GetTodoItem(id)` / `GetMeta(key)` |
`TodoItem` 字段随之改为 `Id / GroupKey / Title / Variants / VariantCount / TotalCount / RangeCount / State`。

### 7. 踩到的坑（自检抓出来的）
- **不能简单剔掉开头的数字**：`5V_Rail` 的 `5` 是电压值，剔了变成 `V_Rail`，
  还会把 `5V_Rail` 和 `12V_Rail` 错并成一项。现在只剔三种**确定是序号**的形式
  （`12) ` / `Step 3 ` / 多段号 `6.1.1.1 `），单个数字+空格宁可不剔。
- **`last_seen` 与 `resolved_at` 必须同格式**才能比较：`batch_timestamp` 是 `2026-07-30T10:00:00`，
  维修记录是 `2026-07-30 10:00:00`，`'T'(84) > ' '(32)` 会让「刚完成的记录」被误判成复发。
  统一 `NormalizeTs()` 成 `yyyy-MM-dd HH:mm:ss`。
- 自检里造数据用固定 `10:00` 时间戳、而跑测试时才 9 点多，也会踩上面这条 → 改用 `00:00`。

### 8. 自检 / 冒烟
- 新增两组断言：归一化规则 14 条（含 5 条**反向**断言，防过度合并）、
  登记表闭环 20 余条（窗口 / 幂等 / 增量 / 区间 / 优先级 / 确认 / 复发 / 删记录 / 机台隔离 / 重开库）。
- 真实库预览打进自检输出，可人工核对合并效果。
- 全部通过；GUI 与桌面提示冒烟通过；构建 0 警告 0 错误。

## v2.5.1 — 2026-07-30

**待办不可忽略 / 不可删除**。待办卡不是「一条可以划掉的事项」，而是 `test_records` 里
真实 FAIL 数据的**投影**；允许忽略等于允许把真问题抹掉，故本版彻底去掉这条出口。

### 1. 去掉「忽略」
- 待办卡右键菜单只剩 **确认问题 / 确认并置为某状态**，末尾一条禁用项写明
  「来自真实不良，不可忽略 / 删除」。
- `MaintenanceBoard.DismissTodo()` 删除（自检断言看板上**不存在任何 Dismiss\* 方法**，防止回流）。
- `Database.ListPendingTodos()` **不再读 `dismissed_todos`** —— 旧库里曾被忽略的故障项
  会因此**自动重新出现**在待办列（预期行为：那些都是真实发生过的不良）。
- `Database.DismissTodo()` 标记 `[Obsolete]` 但保留（不破坏旧调用方编译）；
  写入仍会发生，但没人读，所以**调了也不会让待办消失**。
- `dismissed_todos` 建表语句保留（`CREATE TABLE IF NOT EXISTS`），仅为旧库兼容与回退到
  v2.4/v2.5 时不报错。**不删用户已有数据。**

### 2. 删维修记录时说清后果
- 维修记录本身仍可删，但删的只是「处理单」，不是不良。
- 新增 `Database.CountFailRecords(failItem, stationId)`；删除确认框在该故障项仍有真实 FAIL 时提示：
  > ⚠ 该故障项在 FAIL 记录里还有 N 条真实不良，删掉本记录后它会以「未确认」卡片
  > **自动回到「待办」列**（不良不可删除）。如果问题已解决，请改为把卡片拖到「已完成」。
- 自检新增闭环断言：确认 → 删记录 → **待办自动回来**。

### 3. 唯一的消失路径
```
未确认不良卡  ──双击/拖动──▶  维修记录(待办/进行中/…)  ──拖到「已完成」──▶  待办列不再显示
                                    │
                                    └─ 删除记录 ⇒ 不良卡自动回到「待办」（删不掉）
```
再次出现同一故障项的 FAIL 时，卡片会重新冒出来（复发重现，逻辑与 v2.4.0 一致）。

### 4. 其它
- 卡片右下角提示文字 `双击确认` → **`必须确认`**；tooltip 增加「不可忽略/删除」说明。
- `TodoConfirmForm` 底部说明补一句「不良本身不可忽略，只能处理掉」。
- 自检全通过；`tools/smoke_gui.ps1` / `tools/smoke_notify.ps1` 通过；构建 0 警告 0 错误。

## v2.4.0 — 2026-07-29

维修面板新增**待办栏**：每次检测到 FAIL 都需工程师确认问题，确认后自动进入看板工作流。
无 DDL 变更（只新增一张很小的 `dismissed_todos`，`CREATE TABLE IF NOT EXISTS`）。

### 1. 新增【待办】视图（新增 `TodoPanel.cs`）
- 维修记录页顶部的视图切换由【看板 / 列表】扩为【**看板 / 列表 / 待办**】。

### 2. 三个动作
| 动作 | 行为 |
|------|------|
| **确认问题** （双击行 / 按钮 / 右键） | 弹 `TodoConfirmForm` 补填维修人 + 严重度 → 自动建一条 `status='open'` 维修记录 → 出现在看板「未完成」列 |
| **忽略** | 写入 `dismissed_todos`，该故障项不再出现在待办（**不**创建维修记录） |
| **刷新** | 重新聚合（切页回来也会自动刷） |

### 3. 为什么不建待办表
待办 = `test_records` 的**实时聚合视图**，而不是快照表：

```sql
WHERE f.result='FAIL' AND TRIM(f.fail_reason) <> ''
  AND NOT EXISTS (存在活跃维修记录: status NOT IN ('resolved','closed'))
  AND NOT EXISTS (已写入 dismissed_todos)
GROUP BY f.fail_reason, f.station_id
```

带来三个好处：
- **不会与真实数据不一致**（快照表最典型的坑）；
- **确认后自动消失**：靠维修记录的存在性拦截，不需额外标记；
- **复发自动重现**：记录拖到「已完成」后不再算活跃，同故障项再 FAIL 就自动回到待办。

### 4. 与【从FAIL选故障项】的分工
| | 待办栏 | 【从FAIL选故障项】 |
|---|---|---|
| 触发 | **被动**，自动列出没人管的 | **主动**，手工挑 |
| 范围 | 只有待处理的 | 全部（含已处理） |
| 能力 | 快速确认建单 | 可深扫 XML、可多选、可合并为一条 |

两者不冲突，原按钮完整保留。

### 5. 新增 API
| 方法 | 说明 |
|------|------|
| `Database.ListPendingTodos(stationId)` | 待办项列表（`TodoItem`：故障项 / 机台 / 型号 / 次数 / 首次与最近出现） |
| `Database.DismissTodo(failItem, stationId, model)` | 忽略某故障项 |
| `Database.AcknowledgeTodo(failItem, stationId, model, resolver, severity)` | 确认问题，返回新建维修记录 ID |

### 6. 踩到的坑
- `TodoPanel` 的控件字段**不能写 `readonly`**：它们在 `BuildUi()`（非构造函数体）里赋值，
  `readonly` 会报 `CS0191`（先写成 `= new()` 又在 `BuildUi()` 里重赋也不行）。现统一 `= null!`。

  新增的 `TodoPanel.cs` 必须手动加进去，否则 `MaintenancePanel.cs` 会报 `CS0246 未能找到 TodoPanel`。

## v2.0.0（C# / .NET 重构版） — 对比 Python v1.0.2

本次是**用 C# / .NET 8 (WinForms) 完整重构**，从 Python + PyQt6 迁移而来。功能全部保留并修复了多个真实机台上暴露的问题。

## 一、重构动机

| 问题 | Python 版 (v1.0.2) | C# 版 (v2.0.0) |
|------|-------------------|----------------|
| **杀毒误报** | PyInstaller / Nuitka 打包常被杀毒（尤其 SentinelOne）拦截查杀 | 改用 .NET，运行微软签名的 dotnet 运行时，规避行为查杀 |
| **发布体积** | 129 MB（zip 42 MB） | **1.2 MB**（框架依赖，机台需装 .NET 8）|
| **启动方式** | 单个大 exe | dotnet 运行 DLL / 小启动器 exe |

## 二、杀毒兼容性改进（本次重点）

Python 版在机台上被 SentinelOne 反复查杀，C# 版针对性解决：

1. **去除"自解压"行为**：不再用自包含单文件（避免运行时释放 WPF native DLL 到临时目录 —— 该行为被 EDR 判定为恶意 dropper）。
2. **去除"注册表 Run 键自启"**：Python 版写注册表 `Run` 键（病毒典型驻留手法，杀毒必查）→ 改为**启动文件夹快捷方式**。
3. **去除"启动即自我持久化"**：开机自启不再随程序启动自动写入 → 改为 **Debug 页手动开关**（消除 EDR 最敏感的行为特征）。
4. **不分发 exe（可选）**：提供 `启动.bat` 用 dotnet 运行 DLL，机台无 exe 可被静态查杀。

## 三、功能修复与改进

### 1. XML 解析（核心）
- **修复根节点识别**：Python 版找 `<root>`，但真实机台数据是 `<BATCH>` 格式 —— 之前完全解析不出数据。C# 版正确解析 BATCH 格式。
- **FCT.ini 读取修复**：改用**共享读取模式**，可读取正被 FCT 测试软件占用的文件（Python 的 open 默认允许，C# 需显式设置）。
- **FCT.ini 多路径查找**：config 路径找不到时自动尝试常见路径，并给出诊断信息。

### 2. 统计逻辑修复
- **当日统计修复**：改用**目录日期 (test_date)** 判断当日，不再依赖 XML 内部时间戳格式 —— 解决"累计有 FAIL、当日无 FAIL"的问题。
- **良率口径统一**：良率 = PASS /(PASS + FAIL)，中断不计入分母。
- **产品总数**：按 SN 去重统计。
- **XML 文件总数**：统计磁盘真实文件数（含 debug）。

### 3. 分类逻辑（保持一致）
- 产品结果看文件名前缀：`P_`=PASS、`F_`=FAIL、`O_`=中断。
- 中断细分：有真实 fail 项→FAIL，无→INTERRUPTED。
- `Get Unit Information` 的 fail 不计入不良。
- `USER=debug` 的数据跳过不入库。
- 无 station_id 时用 UNKNOWN 继续扫描入库（但不推送飞书）。

### 4. 界面优化
- **主页布局**：统计面板 20% / 日志框 80%，看跑码更舒展。
- **扫描跑码**：历史扫描逐条打印日志 + 统计计数实时增长。
- **状态栏**：徽章式设计（彩色状态灯），替代原来的文本标记。
- **设备状态页**：原生控件双列布局，一屏铺满不滚动，刷新不闪烁（控件复用 + 双缓冲）。
- **日志窗口**：显示启动后全部日志，实时追加，彩色分级。

### 5. 已移除功能（Python 版曾有，本次不含）
- 日报生成（xlsx）—— 因 xlsx 无法直接推送飞书且引发文件占用错误，已整体移除。
- 多机聚合（central_aggregator）—— 已下线。
- HTTP API —— 单机部署不需要（如需要可恢复）。

## 五、部署说明

**前置要求**：机台需安装 **.NET 8 Desktop Runtime**（一次性）。

**部署步骤**：
1. 解压 `FCT-Aggregator-CS.zip`
2. 检查 `config.json`：
   - `station_id`：留空则按机台 IP 自动识别（172.28.55.11~18）
   - `results_root`：测试结果目录（默认 `D:\Results`）
   - `fct_ini_path`：`C:\FTS\Apps\XPT\Cfg\FCT.ini`

3. 双击 `FCT-Aggregator.exe` 或 `启动.bat` 运行
4. 需要开机自启：打开软件 → Debug 页 → 点"开机自启"
