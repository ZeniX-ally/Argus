# FCT 数据聚合软件 更新说明（2.8.0）

## 本次变化：界面重新排版了

功能一个没少、没变位置逻辑，就是**看起来更像个正经的后台面板**，找东西更快。

### 1. 左边多了一列导航
原来五个按钮挤在窗口最下面，现在挪到**左侧一列**：
**总览 / 待办·维修 / FAIL 记录 / 设备状态 / 调试工具**，最下面是「退出程序」。

- **「待办·维修」右边会有一个红色数字角标** —— 现在有几条未确认不良，一眼就看到，不用点进去
- 键盘 **Ctrl+1~5** 直接切页，**Ctrl+R** 刷新当前页

### 2. 顶部状态改成了彩色小标签
原来是一行很长的英文文字，现在是一排小胶囊：
机台、采集状态、型号数、历史扫描、飞书、桌面提示。
**绿色=正常，黄色=进行中，红色=有问题，灰色=没配**，扫一眼就知道机台好不好。

### 3. 总览页做成了看板
- 上面一排大数字卡：**产品总数 / PASS / FAIL / 良率 / 待办**
- 第二排是今天的：今日 PASS / FAIL / 中断 / 良率
- 下面左边是统计明细（中断、Invalid、解析错误、XML 总数、未完成维修…），
  右边是**实时日志，比以前大了不少**

### 4. 底部多了一条状态栏
常驻显示：结果目录、数据库文件、待办几条、未完成维修几条、最后更新时间。

### 5. 其它
- 每个页面里那个跟顶部重复的大标题去掉了，省出的空间给内容
- 全局统一了配色和字号（以前各页面深浅不一）

## 升级方法

同 2.7.1：用更新包直接覆盖即可。
**这是纯界面改动** —— 数据库、配置、采集与推送逻辑一行没动，历史数据全部保留。

# FCT 数据聚合软件 更新说明（2.7.0）

## 本次变化：**单击卡片看详情**，合并的 fail 项卡上也看得到

### 1. 单击卡片 = 弹出详情预览
卡片就那么大，长的测试项名、故障描述、维修措施都显示不全。现在：

- **单击**任意卡片（待办卡、维修记录卡都行）→ 右边弹出一个详情框
- 里面是**完整内容**，而且文字**可以选中复制**（要把测试项名贴到别处很方便）
- 关掉它：点别处、按 Esc、或者点右上角 ✕（切页、刷新也会自动关）

以前卡片只写「已合并 3 个同类项」，得悬停才知道是哪几个。现在：

- **卡片上**直接列出前两个原始测试项，更多的显示 `+N 项`
- **预览里**列出**全部**原始测试项，还带**每一项各自的不良次数**，一眼看出是哪个通道/哪一步最坏
- 维修记录卡也一样：由待办确认来的记录，卡上会写「合并 3 项：6.1.1.1 5V_Rail +2」

### 3. 顺带
- 待办卡会按内容自动变高，不会挤在一起
- 预览的副标题直接写清「状态 · 优先级 · 次数」，不用再去数

# FCT 数据聚合软件 更新说明（2.6.0）

## 本次变化：待办更聪明了 —— 只看近一个月、同类自动合并、按次数排优先级

### 1. 待办只扫**近一个月**的不良
以前会把库里所有历史不良都列出来，机台跑了半年就会刷出上百张卡片。
现在只扫**最近 30 天**（想改就在 `config.json` 里写 `"todo_scan_days": 60`）。

### 2. 同类测试项**自动合并成一个大项**
同一个问题因为步骤号、通道号、位号不同而反复出现，以前是好几张卡，现在合成一张：

| 原始测试项 | 处理 |
|---|---|
| `6.1.1.1 5V_Rail`、`6.1.1.2 5V_Rail` | 合并成一张卡「5V_Rail」 |
| `CAN_Bus_Test_CH1`、`CAN_Bus_Test_CH2` | 合并 |
| `BSW_v_Kl30UC(XCP)`、`BSW_v_Kl30UC (KL30_LS_UC)(XCP)` | 合并 |
| `Check_5V_Rail` 与 `Check_12V_Rail` | **不合并**（5V 和 12V 是两回事） |
| `Delay_100ms` 与 `Delay_200ms` | **不合并** |

- 卡片上会写「已合并 N 个同类项」，**鼠标悬停能看到具体是哪几项**
- 确认建单时，这些原始项名会写进维修记录备注里，随时可追溯
- 不放心的话：【调试】页点【合并预览】，先看本机数据会怎么归并

### 3. 一旦进了待办就**永久保留**
待办不再是「查出来的临时列表」，而是一张登记表：
即使这条不良已经过了 30 天扫描窗口，卡片**仍然在**，直到你把它处理完。
（处理完 = 确认 → 修 → 拖到「已完成」；同一个问题以后再出，会自动回到待办，次数接着累加）

### 4. 可以自由选**时间区间**看
工具栏新增【待办区间】：**近 7 天 / 近 30 天（默认）/ 近 90 天 / 全部（永久保留）/ 自定义…**

- 选了区间，只显示「这段时间里真的出过不良」的项，卡片上同时显示
  **区间内多少次 · 累计多少次**
- 选区间**不会删除任何待办**，切回「全部」就全回来了

### 5. 按 fail 次数排**优先处理**
- 待办列自动**按不良次数从多到少排序**，列顶就是最该先修的
- 卡片带优先级标记：**高（≥20 次，红）/ 中（≥5 次，橙）/ 低（灰）**，左侧色条同色
- 点确认时，「严重程度」会按优先级帮你预选（高 → 严重）

## 升级方法

同 2.5.1：用更新包（**不带 config、不带数据库**）直接覆盖即可。

首次启动会自动建两张小表（`todo_items` 待办登记表、`app_meta` 水位线），
**不动任何历史数据**；然后自动把近 30 天的不良登记成待办。

# FCT 数据聚合软件 更新说明（2.5.1）

## 本次变化：待办**不能忽略、不能删除**

待办列里那些「未确认」的红标卡片，是数据库里**真实 FAIL 记录**的投影，
不是可以随手划掉的事项。所以这一版把「忽略」彻底去掉了：

### 1. 没有「忽略」了
- 右键待办卡片，菜单里只有 **确认问题** 和 **确认并置为「进行中」/「正在排查」…**，
  最后一行写着「来自真实不良，不可忽略 / 删除」
- 以前在旧版本点过「忽略」的故障项，**这一版会重新出现**在待办列
  （它们本来就是真出过的不良，不该被藏起来）

### 2. 让它消失只有一条路
```
未确认不良卡  →（双击/拖动）确认，建维修记录  →  修好后拖到「已完成」  →  待办列不再显示
```
以后同一个故障项**再出 FAIL**，它会自动重新冒出来提醒你 —— 这跟以前一样。

### 3. 删维修记录 ≠ 删不良
维修记录还是可以删的，但删掉的只是「处理单」。
如果这个故障项在 FAIL 记录里还有真实数据，删除时会明确提示：

> ⚠ 该故障项在 FAIL 记录里还有 N 条真实不良，删掉本记录后它会以「未确认」卡片
> **自动回到「待办」列**（不良不可删除）。如果问题已解决，请改为把卡片拖到「已完成」。

### 4. 小改动
- 卡片右下角的提示从「双击确认」改成「**必须确认**」
- 鼠标悬停卡片的说明里也写清了不可忽略/删除

## 升级方法

同 2.5.0：用更新包（**不带 config、不带数据库**）直接覆盖即可。
数据库结构没有变化；旧的「忽略」名单不会被删除，只是程序不再读它。

# FCT 数据聚合软件 更新说明（2.5.0）

## 本次变化：待办直接放进看板 + 有不良弹 Windows 桌面提示

### 1. 待办不用再切页了
原来的【待办】按钮**取消**，视图只剩【看板 / 列表】。
未确认的不良**直接显示在看板的「待办」列**（就是以前的「未完成」列，已改名为「待办」）：

- 列顶那些**暖色底、虚线框、带「未确认」红标**的卡片 = 新出现、还没人认领的不良
- 下面白底的卡片 = 已经确认、正在等修的维修记录
- 列头右上角红色的 `新 3` 就是未确认不良的条数，旁边的数字仍是维修记录数

### 2. 待办卡片怎么处理
- **双击卡片** → 填维修人 + 严重度 → 变成一条正式维修记录（留在「待办」列）
- **直接把卡片拖到「进行中」/「正在排查」等列** → 填完人就直接落到那一列（确认 + 开修一步到位）
- **右键卡片** → 确认问题 / 确认并置为某状态 / **忽略（不再提醒）**
- 修完拖到「已完成」后，如果同一个故障项**再次**出现 FAIL，它会自动回到「待办」列提醒你

### 3. 有不良会弹 Windows 桌面提示
一旦实时监控抓到 FAIL，右下角会弹出**系统原生通知**：型号、SN、坏在哪一项。

- **点这条通知**（或双击右下角托盘图标）→ 主窗口跳到前面，并**直接打开待办看板**
- 连续出不良不会刷屏：默认 15 秒内的多条会合并成一条 `⚠ FCT 不良 ×N`
- 右下角托盘图标右键 → 可临时关掉「桌面提示」
- 想永久关掉/改间隔，在 `config.json` 里加：

```json
"desktop_notify": false,
"notify_min_interval_sec": 30
```

（不写这两项就是**默认开启、15 秒**，老的 config.json 不改也能用）

- 主界面顶部状态栏能看到 `桌面提示: 🟢 ON`
- 调试页有【桌面提示测试】按钮，装机后点一下确认系统没把通知屏蔽（专注助手/通知设置）

### 4. 顺手修的问题
- 待办页可见时，新不良**自动出现**，不用手动点刷新
- 列表视图下点【导出】，以前导的其实是看板里的记录；现在导的就是你当前筛选出来的那些

同 2.4.0：用更新包（**不带 config、不带数据库**）直接覆盖即可。

# FCT 数据聚合软件 更新说明（2.4.0）

## 本次变化：新增待办栏，FAIL 不再遗漏

### 1. 新增【待办】视图
维修记录页顶部多了第三个视图按钮**「待办」**（看板 / 列表 / 待办）。

- 自动列出所有 FAIL 测试项中**还没有人处理的**（按故障项聚合）
- 显示：故障项目、出现了多少次、首次出现、最近出现、涉及型号与机台
- 只有**没有活跃维修记录**（即没有人在排查/处理中）的故障项才会出现
- 已经确认过的问题不再重复显示，直到它被彻底解决后再复发才重新出现

### 2. 操作方式
- **双击某行** → 弹出补填框（填维修人、选严重度）→ 自动创建一条「未完成」维修记录
- **选中 + 点【确认问题（建维修记录）】** → 同上
- **选中 + 点【忽略】** → 该故障项不再出现（不会创建维修记录，适合确认不是设备问题的情况）
- 右键同一条目也有「确认问题」和「忽略」菜单
- 「只看本机台」开关默认打开

### 3. 工作流衔接
确认问题后自动创建的维修记录会出现在**看板的「未完成」列**，工程师可以：
1. 在待办页确认问题 → 2. 到看板拖到「进行中」→ 3. 修完拖到「已完成」并补填维修措施
   即进入你熟悉的看板工作流，待办只负责「确认要修」。

### 4. 技术实现
- 数据来源 = `test_records` 实时聚合（不是独立表），不会产生数据不一致
- 已确认的项由维修记录的存在性防止重复出现，无需人工避免
- 忽略的项记入 `dismissed_todos` 表（很小，仅记录故障项名 + 机台）
- `TodoPanel.cs` / `TodoConfirmForm.cs` 新增，零第三方依赖

# FCT 数据聚合软件 更新说明（2.2.0）

## 本次变化：维修记录变成看板了

### 1. 一眼看完派活状态
维修记录页现在默认是**看板**，5 列从左到右就是处理流程：

```
未知问题  →  正在排查  →  未完成  →  进行中  →  已完成
```

- 每列列头有真实数量（不是当前显示的数量，是库里的总数）。
- 新增了两个状态：**未知问题**（刚发现、原因不明）、**正在排查**（在定位原因）。
- 不想用看板的，点顶部【列表】就回到原来的表格视图（没有去掉）。

### 2. 直接拖卡片就能改状态
- 把卡片拖到哪一列，它就变成那个状态，不用右键、不用开表单。
- 拖到【已完成】时会弹一个小框让你补上**维修人**和**维修措施**：
  - 【确定】保存补填内容并改状态
  - 【跳过】只改状态，不填
  - 【取消】什么都不变（状态也不改）
- 拖回原来那列，不会产生任何改动。

### 3. 已经录入的记录可以改了
- **双击卡片**（或双击列表里的一行）就能编辑，标题会显示「编辑维修记录 #12」。
- 之前录错了只能删了重录，现在所有字段（含记录日期、状态）都能改。
- 点【取消】就真的什么都不改。

### 4. 两个一直存在的小毛病修了
- **备注终于能填了**：以前导出里有「备注」这一列，但表单里根本没地方填，所以永远是空的。
- **多了「最后更新」时间**：列表多了一列，导出也多了一列，能看出哪条是最近动过的。

### 6. 修了两个使用上的问题
- **看板里右键卡片现在有菜单了**：右键任意卡片 → 编辑 / 标记为某个状态 / 删除，
  与列表视图右键的菜单完全一致（菜单顶部会显示这条是 #几号、什么故障）。
- **删掉记录后新建，编号不再白白跳号**：
  - 全删完了再新建 → 回到 **#1**（以前会变 #2）
  - 删掉最后一条再新建 → 接着用那个号
  - 删掉中间那条 → 不会把空号填回去（否则会和你以前导出的表格里的编号对不上）

### 7. 你原来的「已关闭」记录会发生什么
旧版有 4 个状态（待处理 / 进行中 / 已解决 / 已关闭），新版把「已关闭」并入了「已完成」。

- **首次启动新版时自动完成，不用你动手。**
- 改之前会先把数据库备份一份：`data\fct.db.bak-20260729`（文件名带当天日期）。
- 历史记录的内容、时间都不变，**只是状态名字从「已关闭」变成「已完成」**。

## 升级方法

用新包覆盖原程序文件即可，**保留原来的 `config.json` 和 `data` 文件夹**（历史数据不会丢）。
覆盖前请先退出软件。数据库不需要重建。
