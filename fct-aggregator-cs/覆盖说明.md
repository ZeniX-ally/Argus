# FCT-Aggregator v2.5.1 —— 更新包（覆盖用）

这个包里 **只有程序文件**，故意不放 `config.json`、不放 `data\`、不放 `logs\`。
所以可以直接整包覆盖到机台的程序目录，**不会动到你现场的配置和历史数据**。

## 覆盖步骤

1. 退出正在运行的 FCT-Aggregator（**注意右下角托盘图标也要退干净**，v2.5.0 起有托盘通知图标；
   否则 dll 被占用会复制失败）
2. 把本包里的文件**全部覆盖**到机台程序目录（原 `config.json`、`data\`、`logs\` 原样保留）
3. 双击 `FCT-Aggregator.exe` 启动；或用 `启动.bat`（走 `dotnet FCT-Aggregator.dll`，规避对无签名 exe 的静态查杀）
4. 确认窗口标题是 `Zenix-Ally | FCT-Aggregator v2.5.1`

## 数据库

**无任何表结构变更**，历史记录 / 维修记录全部原样保留，不需要迁移。

> 注意一个**预期的行为变化**：v2.5.1 起程序**不再读「忽略」名单**（`dismissed_todos` 表还在、数据不删），
> 所以你以前点过「忽略」的故障项，只要它在 FAIL 记录里真实存在，就会**重新出现在「待办」列**。

> 如果你是从 **v2.1.0 或更早**直接升上来，首次启动还会把历史的「已关闭」并入「已完成」
> （改之前先备份成 `data\fct.db.bak-<当天日期>`）。

## 本次改了什么

**待办不可忽略、不可删除。**
待办卡是数据库里真实 FAIL 数据的投影，不是可以随手划掉的事项：

1. 右键待办卡片，菜单里只剩【确认问题】/【确认并置为某状态】，并明确写着「不可忽略 / 删除」
2. 让它消失只有一条路：**确认 → 处理 → 拖到「已完成」**；同故障项再出 FAIL 会自动重现
3. 维修记录仍可删，但删除确认框会提示：该故障项还有 N 条真实不良，
   删掉后卡片会**自动回到「待办」列**

详见同目录：

- `版本更新说明.md` —— 面向使用（怎么点、看什么）
- `更新日志.md` —— 面向技术（改了哪些文件、为什么这么设计、踩了什么坑）

## 桌面提示相关（v2.5.0 起，可选配置）

默认**开启**，间隔 15 秒，不改 config.json 也能用。要调的话在 `config.json` 里加：

```json
"desktop_notify": true,
"notify_min_interval_sec": 15
```

- 装机后建议在【调试】页点一次【桌面提示测试】，确认 Windows 没把通知屏蔽
  （系统设置 → 系统 → 通知 / 专注助手）
- 临时想关：右下角托盘图标右键 → 取消勾选「桌面提示」（重启程序后恢复 config 里的设置）

## 注意

- 如果你把这个包解压到**空目录**里直接跑，因为没有 `config.json`，程序会用默认配置启动
  并在日志里记一条 `config.json 未找到(使用默认配置)` —— 那不是故障，但机台上请务必覆盖到原目录。
- 需要**全新安装**（含 config.json 模板）请用 `FCT-Aggregator-v2.5.1.zip`。
