
# Argus 更新说明（3.25.0）—— 对比 v3.3.0 的全部升级

## 本次变化：从"单机采集工具"升级为"产线级质量平台"

对比 v3.3.0（2026-08-12），一个多月里的主要升级，按使用场景分六块：

### 1. 多机台看板（Web，浏览器直接看）
- **全产线一屏**：任意机台开启看板（`Argus.exe agg --web`），浏览器看所有机台在线状态、FAIL 明细，不需要共享目录
- **机台互联**：机台之间 P2P 组网自动同步数据，一台掉线数据不丢，恢复后自动补齐
- **页面齐全**：总览 / 良率 / FAIL 检索 / 维修 / 设备监控 / 数据拉取 / 报告中心 / 告警规则 / 多机对比 / 全局搜索
- **账号与权限**：viewer / engineer / admin 三级角色，关键操作留审计日志
- **在线看报告**：任何机台任何产品的 XML 报告浏览器直接打开（失败项标红），还能两份报告对比差异
- **设备监控**：各机台 CPU / 内存 / 磁盘实时上报，磁盘不足、CPU 过高自动告警

### 2. 主程序界面（WinForms 客户端）
- **主页工业大屏**：24 小时产量/良率走势图、综合良率仪表环（当月口径）、Top5 故障排行、实时异常播报，2×2 大屏布局
- **暗黑模式**：全界面一键切换亮色/暗色，状态色自动适配，重启保持
- **FAIL 记录页**：按 SN 合并同类问题 + 树形分组折叠；文件名时间精准识别（精确到秒）
- **黑白红视觉体系**：全界面统一配色，状态色只在该提醒的地方出现
- **今日/当月双口径**：顶部 KPI 看今日，仪表盘看当月综合良率

### 3. 飞书告警（更好看、更聪明）
- **卡片升级 JSON 2.0**：两列对齐排版、分区线、手机上更清晰
- **抬头图**：所有告警卡顶部显示品牌通栏图片（config 配一次，全卡统一）
- **免配置推送**：程序内置默认群机器人，config 没配 webhook 也能发告警（配了优先用配置的）
- **更多告警类型**：机台离线/恢复、设备磁盘/CPU、良率跌破、链路断连、定时汇总

### 4. 待办 / 维修
- **待办合并按"原理"归并**（本次重点）：基于 G49 产品规范建立规则——同一被测对象的不同写法（万用表名 / 接口名 / 软件变量名）自动归一张卡，三相、四角等变体也归并；不同电源轨不混卡，诊断信息不丢
- **误报剔除**：`UUT Status Err`、`Get Unit Information` 这类非真实不良不再计入 FAIL、不再推送
- **升级向导**：图形化升级工具重写，现场一键升级；升级中断有覆盖兜底

### 5. 智能分析（算法 5 项规格全部落地）
- **良率归因**：FAIL 与机台/工装关联定位
- **预测自反馈**：预测准确率自动对账、阈值自推荐
- **季节性分解**：良率按时段/班次拆解，找规律性波动
- **设备健康分**：CPU/磁盘/内存/离线加权打分，分健康/预警/危急
- **机台端自学习**：本机滚动基线 + 故障知识归并 + 优先级权重校准（全部 config 开关，默认关，不影响现有行为）

### 6. 稳定性与数据
- 数据库读写分离 + 批量事务 + 每日维护备份
- 时间识别全量加固（多格式文件名/时间戳不再解析错）
- 历史库自动迁移，老版本升级无需动数据

## 升级方法
用 `deploy_update.ps1`（先演练再 `-Execute`），或手动把 `Argus-v3.25.0-update.zip` 覆盖到程序目录后启动 `Argus.exe`（或 `启动.bat`）。`data\`、`logs\` 原样保留；config.json 缺的新配置项全部有默认值，不填就是推荐行为。老版本直接升级，历史数据全兼容。

# Argus 更新说明（3.5.0）

## 本次变化：P2P 去中心化机台互联 + 轻量化 + 解析智能化

### 1. 去中心化 P2P 架构（取代中心聚合端）
- 每台机台 = 一个 **Mesh 节点**（`MeshNode`）：既是采集端，也是全产线 FAIL 副本节点与查询入口。
- **全量副本 + 按需拉取**：本机 `data/mesh_agg.db` 存全产线 FAIL 摘要；XML 报告不冗余存储，点开时从源机按需拉取。
- **静态邻居发现**：`config.json` 新增 `peers`（邻居地址数组）+ `mesh_port`（本机端口，默认 8081）。
- **对账补推**：`MeshGossiper` 定期与邻居交换 (machine, max_seq) 摘要，缺口增量拉取，断线自动补齐。
- 任意机台运行 `Argus.exe agg --web` 即开启本机看板，浏览器访问 `http://本机IP:8081/` 看全产线。

### 2. 全局待办池（跨机协作）
- 待办认领/状态变更实时广播同步；冲突以"认领抢占 + 版本号 last-write-wins"裁决。
- 数据落在 `todo_sync_state` 表，以 (origin_machine, todo_id) 为全局键。

### 3. 轻量化
- 删除中心端共享目录扫描/FSW 监听职责（`AggWatcher`）、`AgentPusher` 标记遗留，统一收敛到 `MeshNode`。
- XML 内容不再随事件常驻 512KB，按需拉取，显著降低内存/磁盘占用。

### 4. 解析智能化（高通用可扩展）
- 新增 `Parsing` 框架：`IResultParser` 插件接口 + `parsers.json` 可配置规则集 + 内置 `DefaultResultParser`。
- 路径结构/文件名前缀/SN 段位/排除项/时间戳提取全部可配置；新增型号只需加配置或实现插件，不动核心代码。
- 注册表 `ParserRegistry.Instance` 始终内置默认解析器兜底（`parsers.json` 缺失/非法也能解析现有格式），`Load` 后按配置重建。

## 升级方法
覆盖升级：退出旧程序 → 用更新包里的文件覆盖 → 启动 `Argus.exe`。`config.json`、`data\`、`logs\` 原样保留。
**注意**：去中心化下请在各机台 `config.json` 配置 `peers` 与 `mesh_port`；旧 `agg_*` 中心字段不再用于互联（`agg --web` 现启动本机 Mesh 节点）。

# Argus 更新说明（3.4.4）

## 本次变化：管理后台 —— 所有功能开关可视化，机台一键连接聚合端

### 1. 浏览器里直接开关功能（Web 设置页）
聚合服务的 Web 看板顶部多了**「设置」页签**，不用再手改 config.json：

| 开关 | 说明 |
|---|---|
| 监听端口 | 聚合服务端口，改后重启生效 |
| 访问令牌 | 机台推送/看板访问的钥匙，填入新值**立即生效** |
| 飞书告警 webhook | 机台离线告警 + 定时汇总推送到哪个飞书群 |
| 汇总间隔 | 每几分钟推一次各机台汇总 |
| 传输通道 | http（机台直推）或 smb（共享目录） |
| 共享目录根 / 报告白名单根 | 文件浏览与 XML 下载的目录范围 |

### 2. Windows 看板窗口也能改设置
聚合看板窗口**右下角「设置」按钮**，同样可以开关以上功能，保存**立即生效**，不用重启程序。

### 3. 机台端：填个 IP 就接入聚合
主程序**底部状态栏「聚合设置」按钮**：
- **连接聚合端**：输入聚合端 IP 和端口 → 点「连接」→ 本机马上开始往聚合端推数据（推送器自动重启）
- **本机一键成为聚合端**：点一下 → 若需要管理员权限自动弹 UAC 确认 → 自动配好防火墙/开机自启/启动聚合服务
  （全部内嵌在程序里，不依赖任何外部文件），这台机器就变成聚合端，浏览器打开 `http://本机IP:8080/` 就是看板
- **断开聚合推送**：一键停推

# Argus 更新说明（3.4.3）

## 本次变化：聚合端加固 —— 访问令牌 / 飞书离线告警与汇总 / 跨机台 XML / 看板搜索分页

### 1. 可选加锁：agg_token 访问令牌
想给聚合服务加个锁（防止产线内网别的机器乱推乱看），在**聚合端和每台机台**的
`config.json` 里配**同一串** token：
```json
"agg_token": "你们自己定的任意字符串"
```
配好后：机台推送自动带上令牌；浏览器打开看板时在地址栏加 `?token=你们定的串`。
不匹配的一律拒绝（403）。**不配 = 跟以前一样随便访问**（兼容现有部署）。

### 2. 机台离线自动告警到飞书（聚合端）
聚合端 `config.json` 加一行 `"agg_webhook_url": "https://open.feishu.cn/open-apis/..."`
（飞书群机器人的 webhook 地址）。配置后：
- 某台机**离线**（心跳超时 90 秒）→ 群里立刻收到红色告警卡：机台名 + 最后确认时间
- 每 **60 分钟**（可改 `agg_summary_minutes`）→ 群里收到一次汇总卡：
  几台在线几台离线、每台累计 FAIL 数、心跳时间

### 3. 任意机台的 XML 报告都能在 Web 看板下载
以前 Web 看板只能下载聚合机**本机**的报告；现在机台推送时把 ≤512KB 的 XML 一并上送，
聚合端落盘保存，Web 看板「报告」列点击即可下载**任何机台**的报告。

### 4. 看板更好用了
- FAIL 明细上方多了**搜索框**：输入 SN / 型号 / 失败原因 直接过滤
- 明细表支持**翻页**（每页 100 条，底部上一页/下一页 + 总数）
- 某台机从在线变离线时，浏览器会**响一声**提醒（首次打开不响）

## 升级方法
覆盖升级：退出旧程序 → 用更新包里的文件覆盖 → 启动 `Argus.exe`。`config.json`、`data\`、`logs\` 原样保留。
新配置项全部可选，不写就是原来的行为。

# Argus 聚合服务一键部署

产线维护者一键部署聚合 Web 服务（看板）：解压 → 双击 → 自动完成配置生成 / 防火墙放行 / 开机自启 / 启动服务。

- **用法**：解压发布包 → 双击「一键部署聚合服务.bat」（UAC 弹窗点"是"）→ 完成（原窗口关闭，新窗口显示部署过程）
- **浏览器访问**：部署完成后按窗口提示打开 `http://本机IP:8080/` 即可查看看板（各机台在线状态、FAIL 明细、文件浏览）
- **机台端配置**：每台机台 config.json 里加三项——
  `agg_enabled: true` + `agg_transport: "http"` + `agg_http_url: "http://聚合端IP:8080/"`
- **手动启动**：`Argus.exe agg --web`（前台常驻，Ctrl+C 退出）；或在启动文件夹里手动建快捷方式
- **注意事项**：
  - 端口被占用：改 config.json 的 `agg_http_port`（如 8081）后重新运行一键部署（防火墙规则会自动按新端口重建）
  - 开机自启用「启动文件夹快捷方式」实现，不写注册表（EDR/杀软兼容，不会触发"自我持久化"拦截）
  - 防火墙放行需要管理员权限（双击 bat 时 UAC 自动提权；失败则右键 bat → 以管理员身份运行）

# Argus 聚合端看板（Phase 2）

多机台 FAIL 聚合看板：各机台开启聚合推送后，把失败数据写到共享目录，
宿主机（D:\ArgusAgg）用 `Argus.exe agg` 打开看板，实时显示每台机在线/离线、
累计 FAIL 数，双击明细行可查看完整失败原因。

- **用法**：宿主机运行 `Argus.exe agg`（机台端不用）
- **机台配置**：config.json 里 `agg_enabled: true` + `agg_share_root: "\\宿主机IP\ArgusAgg"`
- **宿主配置**：config.json 里 `agg_share_root` 填共享目录根（未配置时看板会显示"未配置"，不报错）
- **部署位置**：D:\ArgusAgg（共享目录，每台机一个子目录，心跳 + FAIL 事件文件）

# Argus 更新说明（3.3.0）

## 本次变化：待办更好用了

- **新 FAIL 必现在待办列**：修复了跨天/异常数据导致「待办列不出现新 fail」的问题，

  备注等详细原因，再也不会漏记录
- **看板精简为 4 列**：去掉了「正在排查」列（原有记录自动并入「待办」列），
  「进行中」改名「**持续跟踪**」——流程变成：
  未知问题 → 待办 → 持续跟踪 → 已完成

# FCT 数据聚合软件 更新说明（2.6.0）

## 本次变化：待办更聪明了 —— 只看近一个月、同类自动合并、按次数排优先级

### 1. 待办只扫**近一个月**的不良
以前会把库里所有历史不良都列出来，机台跑了半年就会刷出上百张卡片。
现在只扫**最近 30 天**（想改就在 `config.json` 里写 `"todo_scan_days": 60`）。

### 2. 同类测试项**自动合并成一个大项**
同一个问题因为步骤号、通道号、位号不同而反复出现，以前是好几张卡，现在合成一张：

| 原始测试项 | 处理 |
|---|---|
| `6.1.1.1 5V_Rail`、`6.1.1.2 5V_Rail` | 合并成一张卡「5V_Rail」 |
| `CAN_Bus_Test_CH1`、`CAN_Bus_Test_CH2` | 合并 |
| `BSW_v_Kl30UC(XCP)`、`BSW_v_Kl30UC (KL30_LS_UC)(XCP)` | 合并 |
| `Check_5V_Rail` 与 `Check_12V_Rail` | **不合并**（5V 和 12V 是两回事） |
| `Delay_100ms` 与 `Delay_200ms` | **不合并** |

- 卡片上会写「已合并 N 个同类项」，**鼠标悬停能看到具体是哪几项**
- 确认建单时，这些原始项名会写进维修记录备注里，随时可追溯
- 不放心的话：【调试】页点【合并预览】，先看本机数据会怎么归并

### 3. 一旦进了待办就**永久保留**
待办不再是「查出来的临时列表」，而是一张登记表：
即使这条不良已经过了 30 天扫描窗口，卡片**仍然在**，直到你把它处理完。
（处理完 = 确认 → 修 → 拖到「已完成」；同一个问题以后再出，会自动回到待办，次数接着累加）

### 4. 可以自由选**时间区间**看
工具栏新增【待办区间】：**近 7 天 / 近 30 天（默认）/ 近 90 天 / 全部（永久保留）/ 自定义…**

- 选了区间，只显示「这段时间里真的出过不良」的项，卡片上同时显示
  **区间内多少次 · 累计多少次**
- 选区间**不会删除任何待办**，切回「全部」就全回来了

### 5. 按 fail 次数排**优先处理**
- 待办列自动**按不良次数从多到少排序**，列顶就是最该先修的
- 卡片带优先级标记：**高（≥20 次，红）/ 中（≥5 次，橙）/ 低（灰）**，左侧色条同色
- 点确认时，「严重程度」会按优先级帮你预选（高 → 严重）

同 2.5.1：用更新包（**不带 config、不带数据库**）直接覆盖即可。

首次启动会自动建两张小表（`todo_items` 待办登记表、`app_meta` 水位线），
**不动任何历史数据**；然后自动把近 30 天的不良登记成待办。

# FCT 数据聚合软件 更新说明（2.5.1）

## 本次变化：待办**不能忽略、不能删除**

待办列里那些「未确认」的红标卡片，是数据库里**真实 FAIL 记录**的投影，
不是可以随手划掉的事项。所以这一版把「忽略」彻底去掉了：

### 1. 没有「忽略」了
- 右键待办卡片，菜单里只有 **确认问题** 和 **确认并置为「进行中」/「正在排查」…**，
  最后一行写着「来自真实不良，不可忽略 / 删除」
- 以前在旧版本点过「忽略」的故障项，**这一版会重新出现**在待办列
  （它们本来就是真出过的不良，不该被藏起来）

### 2. 让它消失只有一条路
```
未确认不良卡  →（双击/拖动）确认，建维修记录  →  修好后拖到「已完成」  →  待办列不再显示
```
以后同一个故障项**再出 FAIL**，它会自动重新冒出来提醒你 —— 这跟以前一样。

### 3. 删维修记录 ≠ 删不良
维修记录还是可以删的，但删掉的只是「处理单」。
如果这个故障项在 FAIL 记录里还有真实数据，删除时会明确提示：

> ⚠ 该故障项在 FAIL 记录里还有 N 条真实不良，删掉本记录后它会以「未确认」卡片
> **自动回到「待办」列**（不良不可删除）。如果问题已解决，请改为把卡片拖到「已完成」。

### 4. 小改动
- 卡片右下角的提示从「双击确认」改成「**必须确认**」
- 鼠标悬停卡片的说明里也写清了不可忽略/删除

## 升级方法

同 2.5.0：用更新包（**不带 config、不带数据库**）直接覆盖即可。
数据库结构没有变化；旧的「忽略」名单不会被删除，只是程序不再读它。

# FCT 数据聚合软件 更新说明（2.5.0）

## 本次变化：待办直接放进看板 + 有不良弹 Windows 桌面提示

### 1. 待办不用再切页了
原来的【待办】按钮**取消**，视图只剩【看板 / 列表】。
未确认的不良**直接显示在看板的「待办」列**（就是以前的「未完成」列，已改名为「待办」）：

- 列顶那些**暖色底、虚线框、带「未确认」红标**的卡片 = 新出现、还没人认领的不良
- 下面白底的卡片 = 已经确认、正在等修的维修记录
- 列头右上角红色的 `新 3` 就是未确认不良的条数，旁边的数字仍是维修记录数

### 2. 待办卡片怎么处理
- **双击卡片** → 填维修人 + 严重度 → 变成一条正式维修记录（留在「待办」列）
- **直接把卡片拖到「进行中」/「正在排查」等列** → 填完人就直接落到那一列（确认 + 开修一步到位）
- **右键卡片** → 确认问题 / 确认并置为某状态 / **忽略（不再提醒）**
- 修完拖到「已完成」后，如果同一个故障项**再次**出现 FAIL，它会自动回到「待办」列提醒你

### 3. 有不良会弹 Windows 桌面提示
一旦实时监控抓到 FAIL，右下角会弹出**系统原生通知**：型号、SN、坏在哪一项。

- **点这条通知**（或双击右下角托盘图标）→ 主窗口跳到前面，并**直接打开待办看板**
- 连续出不良不会刷屏：默认 15 秒内的多条会合并成一条 `⚠ FCT 不良 ×N`
- 右下角托盘图标右键 → 可临时关掉「桌面提示」
- 想永久关掉/改间隔，在 `config.json` 里加：

```json
"desktop_notify": false,
"notify_min_interval_sec": 30
```

（不写这两项就是**默认开启、15 秒**，老的 config.json 不改也能用）

- 主界面顶部状态栏能看到 `桌面提示: 🟢 ON`
- 调试页有【桌面提示测试】按钮，装机后点一下确认系统没把通知屏蔽（专注助手/通知设置）

### 4. 顺手修的问题
- 待办页可见时，新不良**自动出现**，不用手动点刷新
- 列表视图下点【导出】，以前导的其实是看板里的记录；现在导的就是你当前筛选出来的那些

## 升级方法

同 2.4.0：用更新包（**不带 config、不带数据库**）直接覆盖即可。
数据库结构没有变化，历史记录、维修记录、忽略名单全部保留。

# FCT 数据聚合软件 更新说明（2.4.0）

## 本次变化：新增待办栏，FAIL 不再遗漏

### 1. 新增【待办】视图
维修记录页顶部多了第三个视图按钮**「待办」**（看板 / 列表 / 待办）。

- 自动列出所有 FAIL 测试项中**还没有人处理的**（按故障项聚合）
- 显示：故障项目、出现了多少次、首次出现、最近出现、涉及型号与机台
- 只有**没有活跃维修记录**（即没有人在排查/处理中）的故障项才会出现
- 已经确认过的问题不再重复显示，直到它被彻底解决后再复发才重新出现

### 2. 操作方式
- **双击某行** → 弹出补填框（填维修人、选严重度）→ 自动创建一条「未完成」维修记录
- **选中 + 点【确认问题（建维修记录）】** → 同上
- **选中 + 点【忽略】** → 该故障项不再出现（不会创建维修记录，适合确认不是设备问题的情况）
- 右键同一条目也有「确认问题」和「忽略」菜单
- 「只看本机台」开关默认打开

### 3. 工作流衔接
确认问题后自动创建的维修记录会出现在**看板的「未完成」列**，工程师可以：
1. 在待办页确认问题 → 2. 到看板拖到「进行中」→ 3. 修完拖到「已完成」并补填维修措施
   即进入你熟悉的看板工作流，待办只负责「确认要修」。

### 4. 技术实现
- 数据来源 = `test_records` 实时聚合（不是独立表），不会产生数据不一致
- 已确认的项由维修记录的存在性防止重复出现，无需人工避免
- 忽略的项记入 `dismissed_todos` 表（很小，仅记录故障项名 + 机台）
- `TodoPanel.cs` / `TodoConfirmForm.cs` 新增，零第三方依赖

## 升级方法

同 2.3.0：用更新包（**不带 config、不带数据库**）直接覆盖即可。

# FCT 数据聚合软件 更新说明（2.2.0）

## 本次变化：维修记录变成看板了

### 1. 一眼看完派活状态
维修记录页现在默认是**看板**，5 列从左到右就是处理流程：

```
未知问题  →  正在排查  →  未完成  →  进行中  →  已完成
```

- 每列列头有真实数量（不是当前显示的数量，是库里的总数）。
- 新增了两个状态：**未知问题**（刚发现、原因不明）、**正在排查**（在定位原因）。
- 不想用看板的，点顶部【列表】就回到原来的表格视图（没有去掉）。

### 2. 直接拖卡片就能改状态
- 把卡片拖到哪一列，它就变成那个状态，不用右键、不用开表单。
- 拖到【已完成】时会弹一个小框让你补上**维修人**和**维修措施**：
  - 【确定】保存补填内容并改状态
  - 【跳过】只改状态，不填
  - 【取消】什么都不变（状态也不改）
- 拖回原来那列，不会产生任何改动。

### 3. 已经录入的记录可以改了
- **双击卡片**（或双击列表里的一行）就能编辑，标题会显示「编辑维修记录 #12」。
- 之前录错了只能删了重录，现在所有字段（含记录日期、状态）都能改。
- 点【取消】就真的什么都不改。

### 4. 两个一直存在的小毛病修了
- **备注终于能填了**：以前导出里有「备注」这一列，但表单里根本没地方填，所以永远是空的。
- **多了「最后更新」时间**：列表多了一列，导出也多了一列，能看出哪条是最近动过的。

### 6. 修了两个使用上的问题
- **看板里右键卡片现在有菜单了**：右键任意卡片 → 编辑 / 标记为某个状态 / 删除，
  与列表视图右键的菜单完全一致（菜单顶部会显示这条是 #几号、什么故障）。
- **删掉记录后新建，编号不再白白跳号**：
  - 全删完了再新建 → 回到 **#1**（以前会变 #2）
  - 删掉最后一条再新建 → 接着用那个号
  - 删掉中间那条 → 不会把空号填回去（否则会和你以前导出的表格里的编号对不上）

### 7. 你原来的「已关闭」记录会发生什么
旧版有 4 个状态（待处理 / 进行中 / 已解决 / 已关闭），新版把「已关闭」并入了「已完成」。

- **首次启动新版时自动完成，不用你动手。**
- 改之前会先把数据库备份一份：`data\fct.db.bak-20260729`（文件名带当天日期）。
- 历史记录的内容、时间都不变，**只是状态名字从「已关闭」变成「已完成」**。

## 升级方法

用新包覆盖原程序文件即可，**保留原来的 `config.json` 和 `data` 文件夹**（历史数据不会丢）。
覆盖前请先退出软件。数据库不需要重建。

# FCT 数据聚合软件 更新说明（2.0.0）

- 软件用 C# 重新开发，体积从 129MB 缩减到 1.2MB。
