## 2026-08-14 — 时间识别全量加固（v3.4.14）：堵死同类错误的三个死角

v3.4.13 修了 batch_timestamp 时间源后，把系统里剩余的时间识别死角一并堵上：

1. **时区漂移**（`TimeUtil.Normalize`）：带显式偏移的 ISO 时间（`...T07:17:29.004+08:00`）原先走
   `DateTime.TryParse(AssumeLocal)`，工控机时区误设（如被改成 UTC）时会把 `+08:00` 整体换算成
   机器本地时间，推送/待办时间整体漂移。现在按**墙上时间**解析（剥掉偏移与毫秒，偏移前部分原样保留），
   任何机器上结果一致；`+0800` 无冒号、`Z` 后缀一并支持。
2. **文件名时间戳段位错位**（`Processor.ParsePath`）：原实现固定取第 7 段做时间戳，一旦 SN 含下划线
   段位漂移，会拿错段。现在用正则找**独立段**（下划线边界）的第一个 14/17 位纯数字段；
   真实样本第 8 段 16 位非标准时间戳自动跳过，不再误认。
3. **报告查看器时间不一致**（`XmlViewerForm.ParseReport`）：XML 报告查看器的「测试时间」原来读
   BATCH@TIMESTAMP，与主记录（PANEL 优先）不一致。改为 PANEL@TIMESTAMP 优先，BATCH 兜底。

**验证**：Linux 实测真实样本全链路（PANEL 时间 / 机台 FCT6 / 失败项）正确；自检 +9 用例
（时区 5 项 + 文件名段位 4 项），win10 VM 全量自检待跑。

## v3.4.0 — 2026-08-12（聚合端 Phase 2 + B2 HTTP 双通道）

**多机台聚合看板：`Argus.exe agg` 子命令，部署在共享目录宿主机。**

### 1. 功能

- **合并入库**：启动全量扫描 + FileSystemWatcher 增量（Created/Renamed，机台端 .tmp→Move 改名路径），
  解析各机台推送的 `fail-{seq}.json` 进独立聚合库 `data/agg_center.db`，
  `UNIQUE(machine, seq)` 幂等去重，字段展开存储（machine/model/sn/fail_reason/test_date/...）。
- **心跳监控**：每 10s 轮询机台目录读 heartbeat.json，90s 无心跳判离线；机台目录自动发现/移除。
- **看板 UI**：机台卡片流（在线绿/离线红灯、心跳时间、累计 FAIL、最近 FAIL、待推队列）+ FAIL 明细表
  （双击查看完整失败原因）+ 状态栏，3s 定时 + 事件双驱动增量刷新防闪烁。
- **健壮性**：share_root 未配置/不存在只记日志不弹错；单文件 IO 失败重试 3 次后丢弃；
  心跳读取失败保持原状态不误报离线；后台线程异常不死亡。

### 2. B2 双通道（HTTP 直推，飞书链路零影响）

- **机台端**：AgentPusher 加 http 模式（`agg_transport: "http"` + `agg_http_url`），
  把与 fail 文件相同格式的结构化 JSON POST 到聚合端（UTF-8 无尾换行），心跳同通道；
  断线补偿队列/agg_queue.json 落盘/重启续推完全复用；飞书 webhook 推送不动。
- **聚合端**：HttpIngest（.NET 内置 HttpListener，`agg_http_port` 默认 8080），
  路由 `POST /api/fail`、`POST /api/heartbeat`、`POST /`（按 body type 分发），
  1MB body 上限，404/405/413；收到即入库（幂等去重）+ 实时触发看板刷新。
- **在线判定统一 LastSeen**：smb 心跳/HTTP 推送都刷新 LastSeen，超时判离线，两通道共用；
  新机台首次 HTTP 推送自动出现在看板。
- **部署提醒**：Windows 上 `http://+:8080/` 需要 URL ACL 或管理员权限，否则自动回落
  127.0.0.1 监听（机台端将连不上）——产线宿主建议以管理员运行。

- 宿主 config.json 配 `agg_share_root: "D:\ArgusAgg"`（smb 通道）或 `agg_transport: "http"` +

- 机台端 config.json 配 `agg_enabled: true` + `agg_share_root: "\\宿主IP\ArgusAgg"`（smb）

## v3.0.0 — 2026-07-31

### 1. 为什么拆
分发器能**改文件时间戳、按模板造数、批量投放 XML**。这些操作放在产线机台的主程序里，
误点一次后果很重（会污染真实测试数据）。所以按「彻底分家」处理：

源码从 `fct-aggregator-cs/modules/Distributor/` 用 `git mv` 移到顶层 `fct-distributor/`

## v2.7.1 — 2026-07-30

修一个 v2.7.0 的手感 bug：**单击卡片弹出预览时，预览里的文字是全选（蓝底）状态**，

### 原因
WinForms 的 `TextBox` 只要是**因为窗口激活 / Tab 拿到焦点**就会**自动全选**内容

1. 明细 TextBox 与合并清单 ListView 都设 `TabStop = false` —— 不再被激活焦点选中；
2. `OnShown` / `Activated` / TextBox 的 `GotFocus` 里统一调 `ClearAutoSelection()`：
   `SelectionLength = 0` + `ActiveControl = null`（焦点交给窗口本身，Esc 关闭仍有效）；
3. 手动用鼠标划选、`Ctrl+C` 复制**完全不受影响** —— 鼠标点进去的焦点本来就只放光标。

### 自检
新增 3 条断言：预览窗在打开列表里、**刚弹出时选区长度为 0**、焦点不在输入框上。

### 3. 为什么不建待办表

```sql
  AND NOT EXISTS (存在活跃维修记录: status NOT IN ('resolved','closed'))
  AND NOT EXISTS (已写入 dismissed_todos)
GROUP BY f.fail_reason, f.station_id
```

带来三个好处：
- **不会与真实数据不一致**（快照表最典型的坑）；
- **确认后自动消失**：靠维修记录的存在性拦截，不需额外标记；
- **复发自动重现**：记录拖到「已完成」后不再算活跃，同故障项再 FAIL 就自动回到待办。

## v2.0.0（C# / .NET 重构版） — 对比 Python v1.0.2

本次是**用 C# / .NET 8 (WinForms) 完整重构**，从 Python + PyQt6 迁移而来。功能全部保留并修复了多个真实机台上暴露的问题。

---

## 一、重构动机

| 问题 | Python 版 (v1.0.2) | C# 版 (v2.0.0) |
|------|-------------------|----------------|
| **杀毒误报** | PyInstaller / Nuitka 打包常被杀毒（尤其 SentinelOne）拦截查杀 | 改用 .NET，运行微软签名的 dotnet 运行时，规避行为查杀 |
| **发布体积** | 129 MB（zip 42 MB） | **1.2 MB**（框架依赖，机台需装 .NET 8）|
| **启动方式** | 单个大 exe | dotnet 运行 DLL / 小启动器 exe |

---

## 二、杀毒兼容性改进（本次重点）

Python 版在机台上被 SentinelOne 反复查杀，C# 版针对性解决：

1. **去除"自解压"行为**：不再用自包含单文件（避免运行时释放 WPF native DLL 到临时目录 —— 该行为被 EDR 判定为恶意 dropper）。
2. **去除"注册表 Run 键自启"**：Python 版写注册表 `Run` 键（病毒典型驻留手法，杀毒必查）→ 改为**启动文件夹快捷方式**。
3. **去除"启动即自我持久化"**：开机自启不再随程序启动自动写入 → 改为 **Debug 页手动开关**（消除 EDR 最敏感的行为特征）。
4. **不分发 exe（可选）**：提供 `启动.bat` 用 dotnet 运行 DLL，机台无 exe 可被静态查杀。

---

## 三、功能修复与改进

### 1. XML 解析（核心）
- **修复根节点识别**：Python 版找 `<root>`，但真实机台数据是 `<BATCH>` 格式 —— 之前完全解析不出数据。C# 版正确解析 BATCH 格式。
- **FCT.ini 读取修复**：改用**共享读取模式**，可读取正被 FCT 测试软件占用的文件（Python 的 open 默认允许，C# 需显式设置）。
- **FCT.ini 多路径查找**：config 路径找不到时自动尝试常见路径，并给出诊断信息。

### 2. 统计逻辑修复
- **当日统计修复**：改用**目录日期 (test_date)** 判断当日，不再依赖 XML 内部时间戳格式 —— 解决"累计有 FAIL、当日无 FAIL"的问题。
- **良率口径统一**：良率 = PASS /(PASS + FAIL)，中断不计入分母。
- **产品总数**：按 SN 去重统计。
- **XML 文件总数**：统计磁盘真实文件数（含 debug）。

### 3. 分类逻辑（保持一致）
- 产品结果看文件名前缀：`P_`=PASS、`F_`=FAIL、`O_`=中断。
- 中断细分：有真实 fail 项→FAIL，无→INTERRUPTED。
- `Get Unit Information` 的 fail 不计入不良。
- `USER=debug` 的数据跳过不入库。
- 无 station_id 时用 UNKNOWN 继续扫描入库（但不推送飞书）。

### 4. 界面优化
- **主页布局**：统计面板 20% / 日志框 80%，看跑码更舒展。
- **扫描跑码**：历史扫描逐条打印日志 + 统计计数实时增长。
- **状态栏**：徽章式设计（彩色状态灯），替代原来的文本标记。
- **设备状态页**：原生控件双列布局，一屏铺满不滚动，刷新不闪烁（控件复用 + 双缓冲）。
- **日志窗口**：显示启动后全部日志，实时追加，彩色分级。

### 5. 已移除功能（Python 版曾有，本次不含）
- 日报生成（xlsx）—— 因 xlsx 无法直接推送飞书且引发文件占用错误，已整体移除。
- 多机聚合（central_aggregator）—— 已下线。
- HTTP API —— 单机部署不需要（如需要可恢复）。

## 五、部署说明

**前置要求**：机台需安装 **.NET 8 Desktop Runtime**（一次性）。

**部署步骤**：
1. 解压 `FCT-Aggregator-CS.zip`
