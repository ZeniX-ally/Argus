## 1. 盘点结论（本地侧基线要点）

本地 Dashboard = 机台主程序（Argus.exe）全部 GUI 面，共 **9 个页签 + 3 个横切能力**：

| 面 | 内容 |
|---|---|
| 总览页 | 今日 KPI 卡 ×5（产品/PASS/FAIL/良率/中断）+ 累计 6 格（+待办数） |
| 待办/维修页 | 看板/列表双视图、状态筛选、待办区间、从 FAIL 选故障（含深扫 XML）、维修表单（批量/合并）、导出 12 列 |
| 维修看板 | 4 列状态机（unknown→open→in_progress→resolved）、卡片拖拽改状态、待办卡（优先级 20/5）、合并规则、人员管理 |
| FAIL 记录页 | 树形/表格双视图、搜索、高频标色（≥5 红/≥2 警告）、双击打开 XML |
| 设备状态页 | FCT.ini 解析（型号/版本/A2L/设备网格 COM 绿/USB 灰）、3s 刷新 |
| 调试工具页（--debug） | 推送测试/机台检测/查询/待办同步/配置/清库 |
| 聚合看板（内嵌工具） | 机台卡/FAIL 明细/KPI/离线时长/设置/告警 |
| 4 个工具页 | FAIL 排行 / 取数打包 / TDMS 波形 / 聚合看板（惰加载） |
| 横切 | 顶栏状态胶囊、扫描进度、状态栏、待办角标、Mesh 链路灯、快捷键、主题令牌、3s 轮询 |

**统一口径（线上必须复刻）**：良率 = PASS/(PASS+FAIL)，中断/Invalid/ParseError 不进分母；产品数按 SN 去重；debug 数据入库前即跳过（但 XmlCount 含 debug——需线上明确此差异）。

**⚠ 本次对照的新发现（此前 Dashboard 规划遗漏）**：
1. **维修/待办看板**是本地核心工作流（拖拽流转/状态机/待办永久保留/合并规则），原规划未覆盖 → 新增 S4 阶段
2. **设备状态页**（FCT.ini）是本地独有数据源（读机台本机文件），线上化必须先解决"数据上报" → 新增 S5 阶段

## 5. 交互与体验

- **操作习惯一致**：拖拽改状态、双击编辑、右键菜单（contextmenu）、快捷键（Ctrl+1~8）全部对齐本地
- **响应式**：CSS Grid/Flex + media query（零框架，延续零依赖原则）；≥1440 三列布局、平板两列、手机单列（维修看板 4 列压为横向滚动）
- **多浏览器/移动端**：只用 Web 标准（fetch/DragEvent/localStorage/Permission API），无桌面特定依赖；移动端优先「查看+确认」类操作，复杂编辑（维修表单）提示桌面端
- **可访问性**：对比度符合黑白红令牌、键盘导航、ARIA 标签
