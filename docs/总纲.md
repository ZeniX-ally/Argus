# Argus 测试工程师工作台 — 统一实施方案（总纲）

> 版本：v1（2026-08-27）｜整合 4 份前置规划：
> ①《架构优化与扩容方案.md》（P0~P3，P0 已落地 v3.5.3）｜②《设备监控面板功能规划.md》（D1~D3）
> ③《测试工程师Dashboard功能规划.md》（D1~D5）｜④《线上Dashboard功能对照与实现方案.md》（A/B/C 对照，S1~S6）
> 目标：把**日常拉取数据 → 查看报告 → 维修待办 → 监控良率/设备 → 追踪程序变更**的完整工作流，在一个线上 Dashboard 上闭环，本地功能只增不减，且架构可扩展、可维护。

---

## 1. 方案定位

把此前分散的四份规划整合为**一条主线、八个阶段**，所有需求按依赖关系归位。整合后统一用 **Phase 1~8** 编号（替代 M/S 混合编号），每阶段可独立验收、可发布、可回滚。

**需求全景 → 统一功能地图**：

| 需求来源 | 功能需求 | 归入阶段 |
|---|---|---|
| 架构优化（P1/P2） | /api/metrics、日志滚动、每日备份、XML 容灾缓存 | Phase 2 |
| 架构优化（P2） | 无头服务化（Windows Service）、推送并发、Gossiper 自适应 | Phase 8 |
| 设备监控面板 | 设备信息采集（CPU/内存/磁盘/版本）、在线/离线、趋势、磁盘/CPU 告警 | Phase 6 |
| Dashboard 规划 | 数据拉取、报告中心、程序调整日志、良率监控、数据明细、联动/搜索/收藏/权限/布局 | Phase 3/4/7/8 |
| 在线 XML 查看 | 任意机台任意产品 XML 在线等效查看（D5） | Phase 4 |
| 完整同步对照 | 维修/待办看板（S4）、设备状态页（S5）、调试/诊断、导出、审计 | Phase 5/6/8 |

## 2. 整体架构（四层 + 横切）

```
┌─ L2 展示层（public/ 静态资源，零依赖，响应式）─────────────────────────┐
│ 总览 │ 数据拉取 │ 报告中心 │ 程序日志 │ 良率监控 │ 数据明细 │ 设备状态 │ 设置 │
│   维修/待办看板（4 列拖拽）· 在线 XML 查看（等效本地）· 多机台对比        │
└───────────────────────────────┬─────────────────────────────────────┘
┌─ L1 服务层（WebAggServer API，agg_token 鉴权）────────────────────────┐
│ /api/status /api/stats /api/devices /api/maintenance /api/todos      │
│ /api/mesh/query /api/xmlview /api/xml /api/fetch(异步) /api/export   │
│ /api/metrics /api/audit /api/settings                                │
└───────────────────────────────┬─────────────────────────────────────┘
┌─ L0 数据底座（AggDatabase，单写者+短租读）────────────────────────────┐
│ agg_records(FAIL) │ yld_daily(良率) │ device_info/samples(设备)      │
│ proc_change_log(程序) │ maintenance/todo(维修) │ users(权限) │ audit(审计)│
│ 源机 test_records（PASS 全量索引，按需拉取，不复制到聚合端）             │
└───────────────────────────────┬─────────────────────────────────────┘
┌─ 采集端（机台 Argus.exe 扩展）───────────────────────────────────────┐
│ 心跳 30s(轻量状态) │ 日统计上报 │ L1 系统信息 5min │ FCT.ini 状态上报   │
│ mesh 推送(FAIL/待办/维修事件，断线补偿+幂等，已有)                     │
└─────────────────────────────────────────────────────────────────────┘
横切：权限（users 三角色+审计）· 告警（飞书，复用 AggAlertService）· 安全
      （agg_token/白名单/DTD Prohibit/CSV 注入防护）· 可观测（/api/metrics）
```

## 3. 功能模块依赖关系（关键约束）

| 依赖 | 原因 | 违反后果 |
|---|---|---|
| 前端全部模块 → **public/ 静态资源服务**（Phase 1） | 单文件 const 字符串在 8 模块后不可维护（D2） | 前端无法演进 |
| 良率/明细/总览 → **心跳日统计 yld_daily**（Phase 1） | 聚合端无 PASS 计数（D1） | 良率无底座 |
| 设置/审计/高危操作 → **users 三角色**（Phase 1） | 导出/删除/清库需分级（D3） | 无权限边界 |
| 在线 XML 查看 → **源机检索 /api/mesh/query**（Phase 4） | PASS 索引只在源机（D5） | 查不到 PASS 报告 |
| 设备状态页 → **DeviceInfoCollector + FCT.ini 上报**（Phase 6） | FCT.ini 是机台本机文件 | 无数据源 |
| 维修看板 → **maintenance API 服务端化**（Phase 5） | 拖拽/状态机/导出需后端 | 前端无法流转 |
| 数据拉取/报告中心 → **Fetcher/FailRanker 逻辑抽取**（Phase 7） | 桌面工具能力需服务端化 | 重复实现+口径漂移 |
| 排障与发布 → **/api/metrics + 备份**（Phase 2） | 后续阶段问题需可观测可恢复 | 黑盒排障 |

**可并行支线**：Phase 2（可观测）与 Phase 4/5 部分并行；Phase 6 机台端采集可与 Phase 5 并行开发；Phase 8 的推送并发/Gossiper 自适应是纯后端优化，随时可插。

## 6. 扩展性与可维护性设计

| 原则 | 落地 |
|---|---|
| **口径一致靠复用** | 解析（XmlReportParser）、合并（TodoGrouping.KeyOf）、状态机（Normalize）、良率公式、CSV 注入防护全部**服务端复用 C# 逻辑**，前端零重复实现 |
| **零第三方依赖** | 图表 canvas 自绘、xlsx 手写 OOXML、CSS Grid 响应式；离线可用、无 CDN |
| **模块化前端** | public/ 按模块独立文件（HTML/JS/CSS），服务端拼接，单 exe 部署 |
| **配置化** | 所有新行为走 config.json 可配项（缺省向后兼容），机台端配置零改动可升级 |
| **数据不囤积** | 聚合端只存摘要（FAIL/日统计/设备快照）；PASS 明细留源机按需拉取；samples 按天滚动 |
| **自检随行** | 每阶段 +N 自检断言（口径对拍、并发、权限、拖拽状态机全路径），全绿才发版 |
| **发布统一** | make_release.ps1 适配 public/；update 包覆盖升级不破坏 data/logs |
