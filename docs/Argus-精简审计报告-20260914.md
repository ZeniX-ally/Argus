## 2. 🟠 口径漂移（违反"口径单一来源"纪律）

`CODEBUDDY.md §2` 明确：口径单一来源，**禁止在第二处重实现**。以下均已出现第 2～7 处实现。

### 2.1 字节格式化 7 份，且有**两套进制**

| 进制 | 位置 |
|---|---|
| **1000（十进制）** | `Core/FctProgramBackup.cs:289` · `Db/Database.Storage.cs:339` · `Db/StorageOptimizer.cs:78` · `Db/StorageOptimizer.cs:295`（同文件两个类各一份） · `Ui/BackupCodePanel.cs:161`（内联） |
| **1024（二进制）** | `Infra/FeishuNotifier.cs:375` · `modules/Fetcher/Packager.cs:95` · `modules/TdmsViewer/MainForm.cs:762` · `modules/TdmsViewer/Program.cs:86` |

**后果**：同一个 2,147,483,648 字节的库，存储页显示 `2.15 GB`，新上的飞书每日摘要卡显示 `2.00 GB` —— **差 7%，同一个库两个数**。这是本轮新增卡片时引入的可见不一致。
**修复**：收敛为 `Infra` 下单一 `FmtBytes`（建议统一 1024，并在函数注释里写清选择理由），全项目改调用点。

### 2.2 CSV 转义 3 份逐字节副本（CWE-1236 防护）

`Infra/CsvUtil.cs:7` 的 `Esc` 在以下三处有**逐字节相同**的私有副本：

- `modules/FailRanker/CsvExporter.cs:239`
- `modules/TdmsViewer/Exporter.cs:71`
- `Ui/MaintenanceExporter.cs:41`

**后果**：注入防护（前导 `'`）一旦要扩展（例如补 `\n` 起始、补 `%` 等），这 3 份不会跟着改，形成静默安全缺口。
**修复**：三处删私有 `Esc`，改调 `CsvUtil.Esc`。
> 注：`FeishuCardV2.Escape`（markdown 转义）与 `Xlsx.Escape`（XML 转义）是**不同关注点**，不算重复，保留。

### 2.3 良率公式散落 6+ 处

`Core/AppState.cs:125` · `Db/Database.cs:3657` · `Intelligence/SelfBaseline.cs:157` 与 `:223` · `Ui/DebugPanel.cs:262` 与 `:273` · `modules/FailRanker/CsvExporter.cs:75`
均为 `Pass / (Pass + Fail) * 100` 的各自实现。**修复**：抽 `StatsUtil.Yield(Pass, Fail)` 单一入口。

### 2.4 硬编码颜色 56 处绕过 `Theme`

`Ui/` 目录共 75 处 `Color.FromArgb`，其中 `Theme.cs` 占 19（合法），**其余 56 处散落**，`Ui/DashboardWidgets.cs` 一个文件就占 26 处。
**后果**：改主题色要翻多个文件，且容易漏改导致视觉不一致。
**修复**：把 DashboardWidgets 的 26 处收敛为 Theme 令牌（可分批）。

### 2.5 其他小口径重复

- 状态键字面量未走 `MaintenanceMeta` 常量：`Intelligence/LearningEngine.cs:116`、`Intelligence/OpsAlertMonitor.cs:57`（`"resolved"` / `"in_progress"`）

第 1～6 项已于 **v3.44.1** 一次交付；第 7～10 项已于**口径收敛批**（同版本，纯结构不升版本号）交付。

**第 7～10 项的执行口径（重要）**：硬约束是「输出与收敛前逐位一致」，因此只做**实现归并**，不统一任何有分歧的口径：

- CSV `Esc`：三份副本与 `CsvUtil.Esc` 逐字节相同 → 直接合一，输出不变。
- 字节格式化：7 处里只有 **5 处十进制 GB/MB 完全相同**，合并为 `ByteUtil.MbGb`；二进制两处 KB 小数位不同（1 位 vs 0 位），合并为 `ByteUtil.Human(b, kbDecimals)` 保留差异；`TdmsViewer` 两处「恒为 KB / 恒为 MB」的单次专用格式**不合并**（改成通用函数会改变档位）。**两套进制有意并存**——统一会改变现场显示值。
- 良率：8 处实现分属**两种浮点运算顺序**，且**结果差异可见**（`Pass=23/Fail=57` → 先乘后除 `28.75`、先除后乘 `28.749999999999996`，一位小数分别显示 28.8% 与 28.7%）。穷举 250 万组样本验证：原始值 21.8 万组不同、格式化后仍有 218 组不同。**故按运算顺序分两组归并为 `StatsUtil.YieldPct` 与 `StatsUtil.YieldPctDivFirst`，绝不合并**，并把这个原因固化成断言。
- 大屏颜色：26 处硬编码字面量 → 14 个 `Theme.Chart*` 令牌（值原样搬迁），剩 6 处是 `Color.FromArgb(alpha, Theme.X)` 透明度变体（合法，不处理）。

**仍未收敛（后续批次，不影响功能）**：`Ui/` 下其余 **36 处**颜色字面量，其中明显重复的有 `(200,16,46)` 出现 **7 次**（且 `Theme.ToolSummary`/`ToolNodeDir` 已是同值）、`(89,89,89)` **5 次**、`(140,140,140)` **2 次**、`(20,20,20)` **3 次**；另有 `(178,178,178)` 与 `(179,179,179)` 相差 1 的疑似笔误（**改动会改变输出，需你确认后再动**）。
