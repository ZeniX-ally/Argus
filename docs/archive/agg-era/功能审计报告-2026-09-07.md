## 1. Critical（4 条）

### C1.【D】GitHub 导出白名单误包含 git 追踪的 config.json，真实 agg_token 将随开源发布泄露
- **位置**：`scripts/make_github_export.ps1:15,36-37`；`FctAggregator/config.json`（git 已追踪）
- **描述**：`$include` 含 `FctAggregator` 整目录，而 `FctAggregator/config.json` 被 git 追踪（`git ls-files` 已验证），HEAD 版本含真实 `agg_token: fd1565…`。导出守卫 `$bad` 只拦点开头文件与 AGENT_RULES.md/CODEBUDDY.md，无密钥扫描。`make_package.ps1` 打 zip 时会清空 token，但 **GitHub 导出路径直接发布原始文件**。
- **复现**：执行 `make_github_export.ps1` → push github/main → token 公开于开源仓库。
- **建议**：`git rm --cached FctAggregator/config.json` + .gitignore + 提供 config.template.json；或导出脚本内对该文件清空密钥字段并把 `token|webhook|key` 加入 `$bad` 守卫。**建议在下次 GitHub 发布前必须完成。**

### C2.【B】POST /api/settings 无角色校验 — viewer 可改 agg_token 直接提权为 admin
- **位置**：`FctAggregator/Agg/WebAggServer.cs:638`（ServeSettingsSave 无 RequireRole）；提权链 `:435`
- **描述**：全局门只校验登录态。viewer 登录后 `POST /api/settings {"agg_token":"已知值"}` 立即生效 `_token`，攻击者随后以 `X-Agg-Token` 头获得 admin 级访问（管理用户、看审计、改告警规则）。同接口还可劫持 `agg_webhook_url`（告警改道外部地址）。宽松模式（无 token 无用户）下任意 LAN 客户端可调用。
- **复现**：viewer cookie → `POST /api/settings` 改 agg_token → 用新 token 访问 admin 接口 → 200。
- **建议**：入口加 `RequireRole(ctx,"admin")`；补路由级角色矩阵测试。

### C3.【B】POST /api/config/rollback 无角色校验且接受任意绝对路径 — 可覆盖 config.json
- **位置**：`FctAggregator/Agg/WebAggServer.cs:765-782`；`FctAggregator/Infra/Config.cs:501-515`
- **描述**：handler 无 RequireRole；`file` 传绝对路径时 `AppConfig.Rollback` 直接 `File.Copy(backupPath, config.json, overwrite:true)`——viewer 可把服务器上任意可读文件复制为 config.json，或借"回滚"把可能已泄露的旧 token 换回。
- **复现**：viewer cookie → `POST /api/config/rollback {"file":"C:\\任意\\文件.json"}` → config.json 被替换。
- **建议**：admin 校验 + Rollback 强制只接受 `data\config_backups\config_backup_*.json`。

### C4.【D】无感热升级的提交步骤必然失败：新进程无法覆盖自己正在运行的程序文件
- **位置**：`FctAggregator/Infra/UpdateChecker.cs:196,231-262`；`Ui/MainForm.cs:612-618`；`Program.cs:115-126`
- **描述**：`ScheduleRestart` 启动的是**同目录 Argus.exe**；新进程先执行 `CommitPendingUpdate`（互斥体检查之前），对 baseDir 内文件逐一 `File.Copy(overwrite:true)`——此时 Argus.dll 正是新进程自身已加载锁定的映像，Windows 拒绝写句柄，首个被锁文件即 IOException 进 catch。旁证：`tools/deploy_update.ps1:101-112` 离线部署都必须先杀进程才能覆盖。连锁漏洞：`MainForm.cs:613` 在重启**前**就 `MarkPrompted`，提交失败后该版本被永久静默（`UpdateChecker.cs:65` 跳过 prompted 版本），机器从此停留旧版本，仅一行日志，无重试无用户可见错误。
- **复现**：auto_update=true（默认）+ 更新目录放入 update.zip → 托盘通知 → 自动暂存 → 重启 → `[更新器] 提交更新失败` → 版本被标记已提示，升级永不生效。
- **建议**：改为"旧进程退出后由外部完成交换"（如启动 staging 内新副本再换入主目录，或复用 deploy_update.ps1 的杀进程+重试逻辑）；`MarkPrompted` 移到提交成功之后。

## 2. Important（18 条）

### A 组：采集入库链路（7 条）

**A1. 半成品文件先入库后无法更正（first-writer-wins）** — `Engine.cs:106-107,283-300`；`Database.cs:492-498`
watcher 只订阅 Created/Renamed 不订阅 Changed。机台原地渐进写入且中途停顿 >1.5s 时，半成品被解析入库；后续补完不再触发事件，且 `INSERT OR IGNORE`（xml_path UNIQUE）使正确终态永远写不进去；若改名收尾则产生重复记录。
复现：模拟机台先建文件写一半，停 2 秒，再补完——库中出现残缺记录且不更新。
建议：订阅 Changed 对已存在路径做重解析覆盖，或只接受改名落盘模式。

**A2. 每条实时入库触发全盘 XML 目录扫描（热路径 O(N²)）** — `Engine.cs:345` → `AppState.cs:47-74`
`ProcessRealtime` 每文件调 `RefreshStats()`，其中 `CountDiskXml` 全递归枚举 results_root + 3 条全表聚合 SQL；网络共享时每条记录可秒级阻塞。另 `Engine.cs:339` 丢弃 BatchInsert 已拿到的 id，每条多一次反查。
建议：磁盘计数低频定时/增量；InsertOne 返回 id 复用。

**A3. 运行期新增型号目录永不监控，静默丢数** — `Engine.cs:95-110,159-175`
watcher 仅对启动时发现的型号目录建立；运行期新产品导入的目录不在监控集，无任何错误日志。
复现：运行期间新建 `Online/新型号/` 并写入 XML → 永不入库。
建议：watcher 上移一层动态增挂，或周期性增量重跑 DiscoverModels。

**A4. Skipped 结果短路解析链且不留痕，静默丢文件** — `ParserRegistry.cs:145-162`；`Processor.cs:45-46`
自定义解析器 PathPattern 不匹配时返回 Skipped（非 null）会阻止回落到内置解析器；Processor 对 Skipped 直接 return，不写 parse_failure_log 不打日志——文件无痕消失。
复现：文件名前缀不在 `P_/F_/O_` 内（如 `X_...`）→ 无痕不入库。
建议：Skipped 继续尝试后续解析器；落 parse_failure_log（error_code=skip）。

**A5. PASS 文件不做 XML 有效性校验，损坏文件静默入库为 PASS** — `DefaultResultParser.cs:48-60,276-314`
PASS 分支 `ReadFactoryOnly` 的 catch 吞掉一切 XML 异常返回部分结果，截断/损坏的 P_ 文件变成"合法"PASS 记录，直接污染良率与月度终检统计。
建议：PASS 分支校验 XML 可完整读至末尾，否则走 parse_failure_log。

**A6. 读文件无大小上限，超大文件先整读进内存** — `Processor.cs:27`；`DefaultResultParser.cs:216`
`File.ReadAllText` 在任何大小检查之前执行；`AnalyzeMaxFileKb`（默认 2048KB）只在读完之后限制提取。数百 MB 失控 XML 会 OOM/卡死机台 PC。
建议：读前检查 `FileInfo.Length`，超限记 parse_failure_log（oversize）跳过。

**A7.【WIP】SN 补采逐行独立事务、无断点、重复扫描** — `BackfillTool.cs:171-193`（WIP）；`Database.cs:1254-1264`（WIP）
每条缺失记录单行 autocommit UPDATE（WAL+FULL 每行一次提交），大积压时启动期海量小事务与实时入库争锁；无"永久补不了"落点，每次启动重查重解析；水位条件 `wmd < today` 使水位=今天时仍重解析近 30 天文件。
建议：批量事务（500-1000 行/批）；补不了的 id 记黑名单；水位允许等于 today 跳过全量重跑。**建议在 WIP 提交前修正。**

### B 组：Web 聚合/权限（4 条）

**B1. DELETE /api/proc-log 无角色校验、无审计** — `WebAggServer.cs:175`（对照 POST `:3009` 要求 engineer）
viewer 可删程序日志且不留痕，权限矩阵被破坏。建议补 RequireRole(engineer) + LogAudit。

**B2. 服务端导出过滤不下推 SQL，老数据静默漏导** — `FetcherService.cs:207-225`；`AggDatabase.cs:259-286`
日期/型号/站点过滤只对"最新 2 万条"内存过滤；超 2 万条时导出历史日期段得到空结果，用户误判无数据——质量追溯的静默错误。建议过滤条件下推 SQL。

**B3. GET /api/settings、/api/config/backups 无角色校验** — `WebAggServer.cs:75,611-636,80,757-763`
viewer 可读飞书 webhook 明文（可向群里伪造消息）与服务器内部路径。建议 GET 提升 engineer/admin；webhook 只回布尔不回明文。

**B4. 登录无失败限速，token 永不过期无重置** — `WebAggServer.cs:1242-1264`；AggDatabase 用户表
可无限爆破弱口令；token 支持 `?token=` 传递会进访问日志，泄露后只能删号重建（连带丢布局/收藏）。建议失败锁定 + 失败审计 + token 重置接口。

### C 组：智能分析（3 条）

**C-I1. 资源-失败相关性计算剔除零失败小时，系统性高估相关** — `FailAttributor.cs:141-149`
零失败小时全部剔除后才算 Pearson 相关，r 被系统性抬高，容易输出虚假"CPU 与失败相关"。selftest 构造的数据每小时都有失败，恰好绕开该分支。
建议：以全部有采样小时为样本（0 值参与），门槛按总小时数判断。

**C-I2. 预测对账分类阈值硬编码、与配置脱节、actual 时刻错位** — `PredictAccuracyReconciler.cs:192-217,371-376`
CPU 命中硬编码 `>=95`（配置默认 90）；disk 硬编码 `<=5GB`（配置 10）；offline 在对账时刻取 gap 而非预测窗口内、单位错位（分钟阈值 vs 秒判定）；lead_days 用对账时刻倒推。三条设备预测规则的命中率/lead 数据建立在错位口径上。selftest 仅覆盖 ClassifyYieldHit，三个设备分类器零断言。
建议：统一从 cfg 取阈值；actual 在预测+1 天窗口内取样；lead 基于 predict.ts。

**C-I3. 漂移预警"今日"窗口实为凌晨部分天 + 维护错过整点则当天全缺** — `AnalysisEngine.cs:172-189`；`DbMaintenance.cs:46-50`；`Config.cs:31`
维护链默认 3 点执行，"今日"统计=00:00-03:00 部分天；`MinTodaySamples=3`（硬编码）下凌晨几个样本即可触发假漂移告警，文案宣称"今日均值"误导排查。`now.Hour == _hour` 精确整点匹配，进程 3:00-3:59 未运行则当天漂移/CPK/归因/自学习基线全部跳过且无补跑。
建议：今日窗口改"过去 24h"；MinTodaySamples ≥10；加当日滞后补跑。

### D 组：运维/升级/推送（4 条）

**D1. 提交失败路径用暂存期快照覆盖 data/，程序文件零备份** — `UpdateChecker.cs:169-174,249-261`
(a) 暂存后旧进程继续运行数秒可写入新记录，提交失败时把备份的 data/ 整目录覆盖回去——旧快照冲掉新数据；且备份是对活动 SQLite 库直接 File.Copy（非 backup API），快照可能不一致再覆盖回活动库有损坏风险。(b) 程序文件无备份/清单，提交中途断电留下新旧混合二进制无法自动恢复。
建议：提交失败不回灌 data/；SQLite backup API；程序文件 manifest+回滚。

**D2. 配置备份功能整体失效：Guid 格式串非法，每次 Save 静默跳过备份** — `Config.cs:325`
`$"{Guid.NewGuid():N[..6]}"` 非法格式符，插值抛 FormatException 被 `catch{}` 吞掉，`data\config_backups` 永远为空——叠加 config.json 损坏时 Load 静默回落默认值，现场配置丢失且无回退手段。
复现：设置页保存任意配置 → 观察 `data\config_backups` 永不生成文件。
建议：改 `{Guid.NewGuid().ToString("N")[..6]}`；Load 失败尝试从最近备份恢复。

**D3. AutoUpdateCheck 在 UI 线程解压 + 全量 data/ 复制，主窗口冻结** — `MainForm.cs:600-612`；`UpdatePromptForm.cs:123`
5 分钟周期检测 Tick 在 UI 线程执行 StageUpdate（几十 MB zip 解压 + 整个 data/ 复制）全部同步阻塞，data 大时窗口白屏无响应。
建议：StageUpdate 放 Task.Run，完成后 BeginInvoke 回 UI。

**D4. FCT 配置变更告警从未推送飞书：webhook 取到后只写日志** — `FctIniWatcher.cs:70-74`；`MeshReceiver.cs:184`
FCT.ini 变更（型号新增/固件变更）只落库 + Logger.Info，无 FeishuNotifier 调用——运维配了 webhook 也收不到通知，告警推送静默失效。
复现：任意机台 FCT.ini 变更 → 聚合日志有 [FCT变更]，飞书无消息。
建议：接入 FeishuNotifier（蓝色 FCT 变更卡片）或删除死代码。
