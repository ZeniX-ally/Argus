# 规格 01：良率归因（Yield Attribution）

> 状态：v3.20.0 候选 | 阶段 4（最后落地） | 改动范围：中 | 风险：中

---

## 1. 动机与目标

### 1.1 现状痛点

`AlertPredictor.Predict()` 当前输出形如：

```json
{
  "Machine": "FCT3",
  "Rule": "yield",
  "Level": "warn",
  "Current": 91.2,
  "Predicted": 87.5,
  "Detail": "良率下滑 91.2% → 预测 87.5% 跌破 90%"
}
```

现场工程师看完只能知道"会跌"，但**不知道是哪个失败项拖的**。下车间排查的时候，需要再去 `/api/fails?machine=FCT3` 翻半天。

### 1.2 目标

新增 `/api/yield/attribution` 端点，返回：

```json
{
  "machine": "FCT3",
  "window_days": 7,
  "current": { "yield": 91.2, "fail_count": 12, "total": 137 },
  "baseline": { "yield": 96.5, "fail_count": 4.8, "total": 138, "samples": 4 },
  "drop_pp": 5.3,
  "drivers": [
    {
      "fail_reason": "5V_Rail",
      "key": "5v_rail",
      "current_count": 8,
      "baseline_pct": 0.10,
      "current_pct": 0.67,
      "lift": 6.7,
      "contribution_pp": 3.5,
      "verdict": "primary"        // primary | secondary | noise
    },
    { "fail_reason": "12V_Rail", "current_count": 2, "lift": 1.4, "contribution_pp": 0.4, "verdict": "secondary" },
    { "fail_reason": "GPIO_Loopback", "current_count": 1, "lift": 0.8, "contribution_pp": -0.1, "verdict": "noise" }
  ],
  "confidence": 0.86,
  "generated_at": "2026-09-01T10:30:00"
}
```

**业务价值**：现场 1 分钟定位"该去修哪个治具/换哪个料/查哪台设备的哪个 IO"。

### 1.3 成功标准

| 指标 | 目标 |
|---|---|
| 归因覆盖率 | 当前 7 天有 ≥5 个 FAIL 的机台能给出归因的比例 ≥ 95% |
| 主因 Top1 准确率 | 人工复核 30 个真实告警，主因 Top1 命中率 ≥ 70% |
| API p95 延迟 | < 200ms（30 台机台规模，SQLite 短读连接） |
| 离线兼容 | 聚合端无数据时降级到本机 test_records，不报错 |

## 2. 数据口径与依赖

### 2.1 复用已有能力

| 资源 | 来源 | 用途 |
|---|---|---|
| `agg_records` 表 | DbMigrator v1 | 跨机台 FAIL 明细（聚合端） |
| `test_records` 表 | 本机 Database | 本机全量 FAIL（聚合端无数据时降级） |
| `yld_daily` 表 | DbMigrator v2 | 当前 7 天汇总良率/FAIL 总数 |
| `TodoGrouping.KeyOf()` | `TodoGrouping.cs` | 失败项归一（5V_Rail ≠ 12V_Rail，但同类步骤号归并） |
| `LocalMachine` 属性 | `MeshNode.cs` | 聚合端本机归因时使用 |
| `LocalDb` 属性 | `MeshNode.cs` | 本机 test_records 读取入口（v3.20.0 已存在） |

### 2.2 时间窗口

| 名称 | 含义 | 默认 |
|---|---|---|
| `current_window` | 当前观察窗口 | 近 7 天（含今天） |
| `baseline_window` | 历史基线窗口 | 过去 28 天，**剔除最近 7 天** |
| `baseline_align` | 同星期几对齐 | 同一 weekday 的历史数据聚合 |

例：今天是 2026-09-01（周一）
- current = `[2026-08-26, 2026-09-01]`（7 天，含今天）
- baseline = `[2026-07-29, 2026-08-25]`（28 天）的**所有历史周一**（4 个样本）

### 2.3 "基线可比性"前置

基线窗口要求 ≥ 3 个同 weekday 样本，且总测试数 ≥ 30，否则不归因（返回空 drivers + 提示信息），
避免冷启动期数据不够导致假阳性。

## 3. 算法与伪代码

### 3.1 输入输出

```
输入: machine, current_days=7, baseline_days=28
输出: AttributionReport
```

### 3.2 算法伪代码

```text
function AttributeYield(machine, current_days, baseline_days):
    # 1) 当前窗口 FAIL 明细（来自聚合端 agg_records 或本机 test_records）
    current_failures = QueryFails(machine, today - current_days + 1, today)
    current_total    = Sum(yld_daily[ machine, today-current_days+1 .. today ].total)
    
    # 2) 基线窗口：按 weekday 分组
    baseline_groups = GroupByWeekday(QueryFails(machine, today - current_days - baseline_days, today - current_days))
    # weekday 索引 0..6 各自聚合 fail_reason 出现次数
    baseline_by_reason_weekday = {}
    for w in 0..6:
        baseline_by_reason_weekday[w] = CountByKey(failures, KeyOf)  # dict[reason_key] = int
    
    # 3) 计算基线占比（剔除 current 窗口）
    baseline_total = CountAll(failures_in_baseline_window)
    baseline_pct = { reason: count/baseline_total for reason, count in baseline_by_reason }
    
    # 4) 当前窗口失败项分布
    current_total_fail = len(current_failures)
    if current_total_fail < 3: return EmptyReport("样本不足")
    current_pct = CountByKey(current_failures, KeyOf) / current_total_fail
    
    # 5) 计算每个失败项的 lift 与 contribution
    drivers = []
    all_keys = Union(baseline_pct.keys, current_pct.keys)
    for key in all_keys:
        cur_c = current_pct.get(key, 0)
        base_c = baseline_pct.get(key, 1e-9)  # 防 div/0
        lift = cur_c / base_c                 # 1.0 = 无变化
        # 用全机台良率跌幅 × 该项占比归因
        drop_pp = current_yield - baseline_yield
        contribution_pp = drop_pp * (cur_c / sum(current_pct.values()))
        drivers.append({key, lift, contribution_pp, current_count, base_pct=base_c})
    
    # 6) 判定 verdict
    for d in drivers:
        if d.lift >= 3.0 and d.contribution_pp >= 1.0:
            d.verdict = "primary"
        elif d.lift >= 1.5 and d.contribution_pp >= 0.3:
            d.verdict = "secondary"
        else:
            d.verdict = "noise"
    
    # 7) 置信度（基线样本越多越可信）
    confidence = clamp(0.3 + 0.1 * baseline_sample_count, 0.3, 0.95)
    
    # 8) 排序：主因在前，按 contribution_pp 倒序
    drivers.sort(key = -d.contribution_pp)
    return {machine, drivers, current_yield, baseline_yield, drop_pp, confidence, ...}
```

### 3.3 关键参数

| 参数 | 默认值 | 含义 |
|---|---|---|
| `lift_threshold_primary` | 3.0 | lift ≥ 3 判定为主因（"出现频率是历史的 3 倍以上"） |
| `lift_threshold_secondary` | 1.5 | lift ≥ 1.5 判定为次因 |
| `min_contribution_pp_primary` | 1.0 | 主因还要贡献 ≥ 1pp 良率跌幅 |
| `min_current_fail_count` | 3 | 当前窗口 < 3 个 FAIL 不归因 |
| `min_baseline_sample_count` | 3 | 基线 < 3 个同 weekday 样本不归因 |

参数**不外露到 config**（开发期确认后写死），避免给现场增加配置负担。

## 4. 接口与签名

### 4.1 新增静态类 `YieldAttributor`（`YieldAttributor.cs`）

```csharp
namespace FctAggregator;

public static class YieldAttributor
{
    public sealed class AttributionReport
    {
        public string Machine = "";
        public int WindowDays = 7;
        public YieldStats Current = new();
        public YieldStats Baseline = new();
        public double DropPp;                       // current.Yield - baseline.Yield (pp)
        public List<Driver> Drivers = new();
        public double Confidence;                   // 0..1
        public string Note = "";                    // 样本不足等提示
        public DateTime GeneratedAt;
    }

    public sealed class YieldStats
    {
        public double Yield;        // 良率 0..100
        public int FailCount;
        public int Total;
        public int SampleCount;     // baseline 用：多少天样本
    }

    public sealed class Driver
    {
        public string FailReason = "";   // 展示名（= title）
        public string Key = "";          // 归一 key
        public int CurrentCount;
        public double BaselinePct;       // 0..1
        public double CurrentPct;        // 0..1
        public double Lift;              // current_pct / baseline_pct
        public double ContributionPp;    // 贡献的 pp
        public string Verdict = "noise"; // primary/secondary/noise
    }

    /// <summary>计算单台机台的良率归因（聚合端 agg_records；空数据时降级到本机 test_records）</summary>
    public static AttributionReport Attribute(
        AggDatabase aggDb,
        Database? localDb,           // null = 不降级
        MeshNode? mesh,              // 本机机台名 + PeerUrls 备用
        string machine,
        int currentDays = 7,
        int baselineDays = 28);
}
```

### 4.2 SQL 查询（嵌入到 `AggDatabase`）

不回源代码层 SQL（避免在 spec 锁定实现细节），只列出逻辑：

**Q1：当前窗口 FAIL 明细（聚合端）**
```sql
SELECT fail_reason, COUNT(*) AS cnt
FROM agg_records
WHERE machine = @m AND test_date BETWEEN @cur_from AND @cur_to AND fail_reason IS NOT NULL
GROUP BY fail_reason;
```

**Q2：基线窗口 FAIL 明细（聚合端）**
```sql
SELECT fail_reason,
       CAST(strftime('%w', test_date) AS INTEGER) AS weekday,  -- 0=Sun..6=Sat
       test_date
FROM agg_records
WHERE machine = @m AND test_date BETWEEN @base_from AND @base_to AND fail_reason IS NOT NULL;
-- 在 C# 层按 weekday 分桶 + 累计 cnt
```

**Q3：当前/基线总测试数（聚合端 yld_daily）**
```sql
SELECT SUM(total) AS total, SUM(fail) AS fail, SUM(pass) AS pass
FROM yld_daily
WHERE machine = @m AND test_date BETWEEN @from AND @to;
```

**Q4（降级路径）：本机 test_records**
- 走 `Database.RecentFails(limit)`（已有）+ 时间过滤在 C# 层做
- 总测试数走 `Database.FetchDailyStats(stationId)`（已有方法）

### 4.3 索引确认

- `yld_daily` 已有 `(machine, test_date)` 主键

## 5. API 与 UI 集成点

### 5.1 HTTP 路由（追加，不修改现有）

```
GET /api/yield/attribution?machine=FCT3&current_days=7&baseline_days=28
```

注册到 `WebAggServer.RegisterRoutes()` 的**智能化域** region 内（紧跟 `/api/alerts/predict`）：

```csharp
_pipeline.Add("GET", "/api/yield/attribution",
    ctx => { CountHit(); return ServeYieldAttribution(ctx); });
```

**响应**：`AttributionReport` 直接序列化为 JSON（与现有 `AggFailRow` 一样走 `IncludeFields=true`）。

**鉴权**：复用 `IsAuthenticated`（agg_token / users）；无新增鉴权逻辑。

**性能预算**：30 台机台聚合库，单机查询 < 50ms（含两次 GROUP BY + 一次 SUM）。

## 6. 数据库变更

**无新增表**，但建议新增一条索引（不阻塞编译，缺索引走全表也能跑通，只是慢）：

```sql
-- AggDatabase DbMigrator v8（追加在 Migrations 末尾）
CREATE INDEX IF NOT EXISTS idx_agg_fail_reason ON agg_records(machine, fail_reason);
```

理由：归因查询按 `(machine, fail_reason)` 分组，缺该索引时会扫整张 `agg_records` 表（30 台 × 30 天 ≈ 数十万行）。

## 7. 配置项

**本规格不新增 config.json 键**。所有参数（lift 阈值、贡献阈值、min count）写死在 `YieldAttributor.cs` 顶部常量。

理由：
1. 现场不需要调"什么算主因"——这是算法内部决策
2. 加配置等于给现场增加调参负担（与"`PriorityScorer` 不外露"原则一致）
3. 后续如果需要调，**直接改默认值**比让现场改 config 更安全

如果产品坚持要可配置，再开 `yield_attribution_*` 三键（v3.20.1 follow-up）。

## 8. 自检断言（必跑）

在 `selftest/SelfTest.cs` 新增分组 `[归因]`，至少 12 条断言：

| # | 断言 | 模拟数据 |
|---|---|---|
| 1 | 空库返回 EmptyReport，无异常 | agg_db = 空 |
| 2 | 当前窗口 < 3 FAIL → 不归因，note 含"样本不足" | 1 个 FAIL |
| 3 | 基线窗口 < 3 同 weekday → 不归因 | 2 个历史周一 |
| 4 | 5V_Rail 出现 8 次（历史占 10%）→ primary，lift ≈ 6.7 | 手工注入 |
| 5 | 12V_Rail 出现 2 次（历史占 12%）→ secondary，lift ≈ 1.4 | 同上 |
| 6 | GPIO_Loopback 出现 1 次（历史占 15%）→ noise（lift<1.5） | 同上 |
| 7 | drivers 按 contribution_pp 降序 | 断言排序 |
| 8 | confidence 范围 [0.3, 0.95] | 多种 baseline sample count |
| 9 | 聚合端空数据时降级到 localDb | mock 两条路径 |
| 10 | /api/yield/attribution 返回 JSON 含 drivers[] | HTTP 自检（参考现有 `/api/alerts/predict` 自检套路） |
| 11 | 当前/基线日期窗口计算正确（边界日 23:59、跨月） | mock 跨月数据 |
| 12 | 多机台独立归因，不串数据 | 注入 FCT3/FCT4 数据 |

**关键回归**：原有的 669 条自检**不能红**，特别是 `yield日统计` 分组（v3.19.0）。

## 9. 边界与回退

| 场景 | 行为 |
|---|---|
| 聚合端无该机台数据 | 降级用 `localDb`（如本机就是该机台）→ 仍空则返回 `note="无历史数据"` |
| 当前窗口全是 PASS（0 FAIL） | `drop_pp` 为负（良率上升），drivers 为空 |
| 失败项名极不规范（如乱码） | `KeyOf` 归一后仍能聚合（已验证） |
| `lift` 计算遇 baseline_pct=0 | 默认 1e-9，避免 div/0；这种项自动 `lift = current_pct/1e-9 → 极大`，可能误判 primary；用 `current_count >= 2` 兜底 |
| `confidence < 0.3` | UI 显示半透明 + 工具提示"样本不足，结论仅供参考" |
| 配置升级/降级 | 零配置项，纯代码逻辑，**无回退成本** |
| DB schema 异常（缺列） | `try { ... } catch { return EmptyReport("schema 不兼容"); }` |

**回退开关**（防止现场首次升级出问题）：
- 不提供，回退靠 git revert 一个 PR（这是新 API，旧客户端不调用）

## 11. 备注

- 本规格**不引入 ML**：lift/贡献率全部是统计指标，0 个机器学习概念
- 不引入 NuGet 包：纯 Microsoft.Data.Sqlite + Linq
- 不动 schema 主结构：新增索引一条，无破坏性变更
- 性能依赖 `idx_agg_fail_reason`，未建时全表扫会慢但不报错
- 跨机台数据已在 `agg_records`，**无需新增推送**
