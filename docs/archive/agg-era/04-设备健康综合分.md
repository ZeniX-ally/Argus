# 规格 04：设备健康综合分（Device Health Score）

> 状态：v3.20.0 候选 | 阶段 3（中间落地） | 改动范围：小 | 风险：低

---

## 1. 动机与目标

### 1.1 现状痛点

`HighlightEngine.GetHighlights()` 当前是**单指标阈值**：

```csharp
if(cfg.DeviceAlertCpuPct>0 && info.CpuUsage >= cfg.DeviceAlertCpuPct)
    list.Add(new HighlightItem{ ..., Level="critical", Reason=$"CPU {info.CpuUsage:0.0}% >= {cfg.DeviceAlertCpuPct}%" });
if(cfg.DeviceAlertDiskFreeGb>0 && info.DiskFreeGb>0 && info.DiskFreeGb < cfg.DeviceAlertDiskFreeGb)
    list.Add(new HighlightItem{ ..., Reason=$"磁盘 {info.DiskFreeGb:0.0}GB < 阈值 {cfg.DeviceAlertDiskFreeGb}" });
```

问题：
- **CPU 单独高** → 一律告警，但跑一次备份就这样
- **磁盘低 + CPU 高 + 心跳抖** → 三个单指标都触发，**告警风暴**（3 条飞书 = 1 个真问题）
- 现场："告警太多，真正的问题被淹没"

### 1.2 目标

每个机台算一个**健康综合分（Health Score）** = 0..100，0=要崩，100=健康。
告警阈值由"单指标超阈"改为"健康分低于阈值"，单告警内容也由"哪个指标超阈"变成"综合健康度低 + 主要扣分项"。

示例 `/api/devices/health` 响应：

```json
{
  "machines": [
    {
      "machine": "FCT3",
      "health": 42,
      "level": "warn",
      "components": [
        { "name": "cpu",     "score": 35, "weight": 0.30, "raw": "92%",         "trend": "+1.2%/天" },
        { "name": "disk",    "score": 50, "weight": 0.30, "raw": "12GB",        "trend": "−0.3GB/天" },
        { "name": "memory",  "score": 70, "weight": 0.15, "raw": "78%",         "trend": "stable" },
        { "name": "offline", "score": 40, "weight": 0.25, "raw": "心跳延迟 75s", "trend": "std=68s" }
      ],
      "top_concern": "offline",
      "recommendation": "检查网络/服务存活（参考 AlertHealer）"
    },
    { "machine": "FCT5", "health": 88, "level": "ok", "components": [...], "top_concern": null }
  ],
  "summary": { "ok": 18, "warn": 4, "critical": 1 },
  "generated_at": "2026-09-01T10:30:00"
}
```

**业务价值**：告警从"几条平铺"变成"一条综合 + 扣分排名"，工人一眼看到"先看什么"。

### 1.3 成功标准

| 指标 | 目标 |
|---|---|
| 告警数量减少 | 同一机台同一天，单指标告警数 ≥ 3 时，综合告警应 = 1 条 |
| 误报率 | 综合分健康（> 70）的机台，单指标超阈时**不告警**（除非超阈值 1.5 倍以上） |
| 推荐一致性 | `top_concern` 与 `AlertHealer` 自愈建议一致率 ≥ 90% |
| 计算开销 | 30 台 × 4 指标 = 120 次小计算，< 50ms |

### 2.2 评分维度（components）

| 名称 | 数据源 | 权重（默认） | 评分函数 |
|---|---|---|---|
| `cpu` | `device_info.cpu_usage` + 趋势 | 0.30 | 见 §3.2 |
| `disk` | `device_info.disk_free_gb` + 趋势 | 0.30 | 见 §3.3 |
| `memory` | `device_info.mem_used_mb / mem_total_mb` | 0.15 | 见 §3.4 |
| `offline` | `device_info.last_seen` 间隔 + 心跳 std | 0.25 | 见 §3.5 |

权重**可配**，但默认就够。

## 3. 算法与伪代码

### 3.1 综合分公式

```
health = 0.30 × cpu_score
       + 0.30 × disk_score
       + 0.15 × memory_score
       + 0.25 × offline_score

最终 health ∈ [0, 100]
```

### 3.2 CPU 子分

```text
function CpuScore(current, trend_per_day, cfg):
    # current: 当前 CPU% (0..100)
    # trend_per_day: 每日变化率（已由 DevicePredictor 算出）
    
    # 当前值映射（线性衰减）
    base_score = 100 - current                    # CPU 0% = 100 分, 100% = 0 分
    
    # 趋势惩罚（未来 3 天会怎么样）
    if trend_per_day > 0.5:
        predicted_3d = current + trend_per_day * 3
        if predicted_3d > 95:
            base_score -= 30
        elif predicted_3d > 80:
            base_score -= 15
    
    return clamp(base_score, 0, 100)
```

### 3.3 磁盘子分

```text
function DiskScore(current_free_gb, days_to_exhaust, cfg):
    # 当前余量映射（指数衰减，10GB 以下扣分狠）
    if current_free_gb >= cfg.DeviceAlertDiskFreeGb * 2:
        base_score = 100
    elif current_free_gb >= cfg.DeviceAlertDiskFreeGb:
        base_score = 70
    elif current_free_gb >= cfg.DeviceAlertDiskFreeGb * 0.5:
        base_score = 40
    else:
        base_score = 10
    
    # 耗尽预期惩罚
    if days_to_exhaust is not null:
        if days_to_exhaust <= 3:
            base_score -= 30
        elif days_to_exhaust <= 7:
            base_score -= 15
    
    return clamp(base_score, 0, 100)
```

### 3.4 内存子分

```text
function MemoryScore(used_mb, total_mb):
    if total_mb <= 0: return 100
    pct = used_mb / total_mb * 100
    if pct < 70: return 100
    if pct < 85: return 80
    if pct < 95: return 50
    return 20
```

### 3.5 离线/心跳子分

```text
function OfflineScore(gap_sec, heartbeat_std, cfg):
    base = 100
    if gap_sec > 300:       base = 0            # 真离线
    elif gap_sec > 90:      base = 40
    elif gap_sec > 60:      base = 70
    elif gap_sec > 30:      base = 90
    
    # 抖动惩罚（heartbeat_std > 60s 说明链路不稳）
    if heartbeat_std > 60:
        base -= 20
    
    return clamp(base, 0, 100)
```

### 3.6 Level 映射

| health 区间 | level | 行为 |
|---|---|---|
| [80, 100] | ok | 不告警 |
| [50, 80) | warn | 飞书 warn，红色 UI 高亮 |
| [0, 50) | critical | 飞书 critical，红色 UI 高亮 + 顶部 banner |

阈值可配（默认 80/50）。

### 3.7 top_concern 选择

`top_concern` = `components` 中 `score × weight` 最低的那个（最拖后腿的）。
例：cpu 35×0.30=10.5，disk 50×0.30=15，memory 70×0.15=10.5，offline 40×0.25=10，
→ top_concern = memory/offline 并列（取第一个）。

## 4. 接口与签名

### 4.1 新增静态类 `DeviceHealthScorer`

```csharp
namespace FctAggregator;

public static class DeviceHealthScorer
{
    public sealed class HealthReport
    {
        public List<MachineHealth> Machines = new();
        public HealthSummary Summary = new();
        public DateTime GeneratedAt;
    }

    public sealed class MachineHealth
    {
        public string Machine = "";
        public double Health;            // 0..100
        public string Level = "ok";      // ok/warn/critical
        public List<ComponentScore> Components = new();
        public string? TopConcern;       // component name
        public string? Recommendation;
    }

    public sealed class ComponentScore
    {
        public string Name = "";         // cpu/disk/memory/offline
        public double Score;             // 0..100
        public double Weight;            // 0..1
        public string Raw = "";          // "92%"
        public string Trend = "";        // "+1.2%/天" / "stable"
    }

    public sealed class HealthSummary
    {
        public int Ok;
        public int Warn;
        public int Critical;
    }

    /// <summary>计算所有机台健康分（30 台 < 50ms）</summary>
    public static HealthReport Score(AggDatabase db, AppConfig cfg);

    // 4 个子项 score 单独暴露供测试 + AlertPredictor/AlertHealer 复用
    public static double CpuScore(double current, double trendPerDay, AppConfig cfg);
    public static double DiskScore(double currentFreeGb, int? daysToExhaust, AppConfig cfg);
    public static double MemoryScore(int usedMb, int totalMb);
    public static double OfflineScore(double gapSec, double heartbeatStd, AppConfig cfg);
}
```

### 4.3 `HighlightEngine` 替换内部逻辑

```csharp
// HighlightEngine.cs
public static List<HighlightItem> GetHighlights(AggDatabase db, AppConfig cfg)
{
    // 旧逻辑：单指标阈值
    // → 改为：基于 DeviceHealthScorer.Score() 结果
    
    var healthReport = DeviceHealthScorer.Score(db, cfg);
    var list = new List<HighlightItem>();
    foreach (var m in healthReport.Machines.Where(x => x.Level != "ok"))
    {
        list.Add(new HighlightItem {
            Machine = m.Machine,
            Level = m.Level,
            Reason = $"健康分 {m.Health:0}（{m.TopConcern} 子项最低）"
        });
    }
    // 保留叠加预测 critical 的旧逻辑（兼容）
    try { ... } catch {}
    return list.GroupBy(...).ToList();
}
```

> **行为兼容性**：默认阈值（80/50）下，**只有当 ≥ 2 个子项明显异常时**才会从 ok 跌到 warn，
> 比 v3.19.0 单指标告警更"克制"，符合预期（关掉 70% 误报）。

## 8. 自检断言（必跑）

在 `selftest/SelfTest.cs` 新增分组 `[健康分]`，至少 12 条断言：

| # | 断言 | 模拟 |
|---|---|---|
| 1 | 全健康机台：health ≥ 80，level=ok | 注入 cpu=20/disk=100/mem=50%/last_seen=now |
| 2 | CPU 95%：cpu_score ≤ 10，整体 health 跌到 warn | |
| 3 | 磁盘 3GB < cfg.DeviceAlertDiskFreeGb：disk_score ≤ 40 | |
| 4 | last_seen 600s 前：offline_score = 0，level=critical | |
| 5 | 心跳 std=80s：offline_score 减 20 惩罚 | mock device_samples |
| 6 | 多指标同时异常 → 综合分 ≈ 加权平均 | 手算对比 |
| 7 | top_concern = 最低 (score × weight) 子项 | |
| 8 | threshold 边界：health=80 → ok，=79 → warn | |
| 9 | weight 调整后总分变化符合预期 | 注入 weight_cpu=0.5 |
| 10 | Recommendation 与 AlertHealer 一致 | 复用 AlertHealer.Heal() 自检 |
| 11 | /api/devices/health 返回 JSON 字段齐全 | HTTP 自检 |
| 12 | 与 HighlightEngine 集成：level=ok 不进高亮列表 | |

**回归**：现有 `DevicePredictor` 自检 + `HighlightEngine` 单指标断言不能红。

## 9. 边界与回退

| 场景 | 行为 |
|---|---|
| 聚合端无 device_info | 返回空 machines，summary 全 0 |
| device_samples < 3 条 | trend = "stable"，用 current 单独算 score |
| 设备 24h 内刚接入（last_seen 现在） | offline_score=100，不误判 |
| disk_free_gb = 0（未知） | disk_score = 0（保守，扣到底） |
| mem_total_mb = 0 | memory_score = 100（避免 div/0） |
| 配置 `health_score_enabled=false` | `HighlightEngine` 退回 v3.19.0 单指标逻辑 |
| 权重加和 ≠ 1.0 | 接受（不校验），可能总分超 100 → clamp |

**回退**：单 config key 关闭，**秒级回退**。

## 11. 备注

- **不引入 ML**：纯加权打分，0 个机器学习概念
- **算法全可解释**：每个 component 都有 raw + score，扣分原因清楚
- **不引入 NuGet**：纯 Linq + Math
- **不破坏老 API**：`/api/devices/inspect` 等保留，`/api/devices/health` 为新增
- **HighlightEngine 是"软替换"**：内部用新算法，但对外接口 + 行为（在默认阈值下）变化不大
- **自愈建议复用 AlertHealer**：避免重复实现
- **与规格 02 协同**：综合分 < critical_threshold 也是"预测"，可被 `predict_accuracy_log` 跟踪
