# 规格 03：季节性/班次分解（Seasonality Decomposition）

> 状态：v3.20.0 候选 | 阶段 2（中间落地） | 改动范围：小 | 风险：低

---

## 1. 动机与目标

### 1.1 现状痛点

`AlertPredictor` 当前对每台机台做线性趋势：

```csharp
bool declining = yields.Zip(yields.Skip(1), (a,b)=> b < a).Count(x=> x) >= 2;
double slope = (yields.Last() - yields.First()) / (yields.Count-1);
```

问题：
- **不看周期**：白班/夜班良率差 5pp 常见（夜班新手多），导致"昨天夜班拉低"被识别成"整体下滑"
- **不看周末**：周末只跑少量，良率抖动大，被识别成"异常"
- **阈值全局写死**：周一的良率基线应该比周五松（周一刚开机），但当前一视同仁

现场反馈："周一早上老误报"、"夜班没事也告警"。

### 1.2 目标

把全局良率序列**拆成三层**：

```
观测值 = 趋势(trend) + 周期(seasonal) + 残差(residual)
```

只用**残差**做告警判断：
- 残差 > +N σ → 真异常（往上偏离基线）
- 残差 < -N σ → 真下滑（往下偏离基线）

**周期定义**：默认**按小时**（24 小时 × 7 天，168 个时段），支持配置切换为：
- `daily` — 仅按小时（24 个时段）
- `weekly` — 仅按星期几（7 个时段）

### 1.3 成功标准

| 指标 | 目标 |
|---|---|
| 误报抑制率 | 模拟 7 天数据（带周期 + 1 次真异常）→ 残差告警触发数比 v3.19.0 减少 ≥ 60% |
| 异常检测召回 | 真异常日召回率 ≥ 95%（不漏报） |
| 性能 | 168 时段拟合 + 残差计算，单台 < 10ms |
| 配置兼容 | 默认值行为 = v3.19.0；只开配置后才启用分解 |

## 3. 算法与伪代码

### 3.1 STL（Seasonal-Trend decomposition using LOESS）简化版

完整 STL 用了 LOESS 局部加权回归，比较重。**本规格用简化版**：
- Trend = 7 天滑动平均
- Seasonal = 同期均值 - 总均值
- Residual = 原值 - Trend - Seasonal

无需 NuGet 包，纯 C# 实现。

### 3.2 伪代码（hourly 模式）

```text
function DecomposeHourly(machine, days_back=28):
    # 1) 拉取近 28 天每小时良率（无数据时填 0）
    series = []  # 长度 = 28 * 24
    for each (ts, pass, total) in QueryHourlyYield(machine, last 28 days):
        yield = total > 0 ? pass/total*100 : 100
        series[idx_of(ts)] = yield
    
    # 2) 趋势 = 24h 滑动平均（每天的均值）
    trend = []
    for d in 0..days_back-1:
        window = series[d*24 .. d*24+23]
        trend[d] = Mean(window.where(v => v > 0))
    
    # 3) 周期分量：按 hour-of-day 分桶求均值
    #    关键：每个 hour 的"季节分量" = 该 hour 的均值 - 全局均值
    seasonal_24 = []
    for h in 0..23:
        bucket = [series[d*24+h] for d in 0..days_back-1]
        seasonal_24[h] = Mean(bucket.where(v => v > 0)) - overall_mean
    
    # 4) 残差（每天对应 24 个残差，取日均值做告警）
    daily_residual = []
    for d in 0..days_back-1:
        residuals_today = [series[d*24+h] - trend[d] - seasonal_24[h] for h in 0..23]
        daily_residual[d] = Mean(residuals_today.where(v => !NaN))
    
    # 5) 异常判定
    sigma = StdDev(daily_residual)
    mean_r = Mean(daily_residual)
    anomalies = []
    for d in 0..days_back-1:
        z = (daily_residual[d] - mean_r) / (sigma + 1e-9)
        if |z| > cfg.YieldSeasonalityEpsilon:
            anomalies.append({date: d-ago, residual: daily_residual[d], severity: |z|})
    
    return {trend, seasonal_24, daily_residual, sigma, anomalies}
```

### 3.3 daily / weekly 模式

- **daily（24 时段）**：同 3.2 但 trend 用 7 日滑动平均
- **weekly（7 时段）**：按星期几分桶，trend 用 28 日线性回归

### 3.4 与现有 `AlertPredictor` 集成

```text
function Predict_yield_with_seasonality(machine):
    if not cfg.YieldSeasonalityEnabled:
        return PredictYield_v319(machine)   # 老逻辑，降级保留
    
    dec = Decompose(machine, days_back=28)
    if dec.sigma < 0.5:                       # 残差太小（数据平稳），用全局阈值
        return PredictYield_v319(machine)
    
    # 用最近一天的残差 + 趋势预测明天的良率
    latest_residual = dec.daily_residual[-1]
    latest_trend = dec.trend[-1]
    predicted_tomorrow = latest_trend + latest_residual  # 季节已叠加在 trend
    
    # 但告警判断只用残差超阈值的"显著异常"
    is_anomaly = abs(latest_residual) > cfg.YieldSeasonalityEpsilon * dec.sigma
    
    if is_anomaly and predicted_tomorrow < cfg.YieldAlertYieldPct:
        return PredictItem { Rule: "yield", Level: "warn",
                             Detail: "季节性分解: 残差 {latest_residual:.2f}pp 偏离基线 {dec.sigma:.2f}σ → 预测 {predicted_tomorrow:.2f}%" }
    return null
```

### 3.5 关键参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `yield_seasonality_enabled` | false | 总开关（默认关以保持兼容） |
| `yield_seasonality_mode` | "hourly" | hourly / daily / weekly |
| `yield_seasonality_epsilon` | 1.5 | 残差告警 σ 倍数（1.5 ≈ 87% 置信度） |
| `yield_seasonality_days` | 28 | 基线窗口 |
| `yield_seasonality_trend_window` | 7 | 趋势平滑窗口（天） |
| `yield_seasonality_min_sigma` | 0.5 | 残差 < 此值视作平稳，回退到 v3.19.0 |

## 4. 接口与签名

### 4.1 新增静态类 `YieldDecomposer`

```csharp
namespace FctAggregator;

public static class YieldDecomposer
{
    public enum SeasonalityMode { Hourly, Daily, Weekly }

    public sealed class DecompositionResult
    {
        public string Machine = "";
        public SeasonalityMode Mode;
        public int DaysBack;
        public List<double> Trend = new();        // 长度 = DaysBack
        public List<double> Seasonal = new();      // 长度 = 周期长度
        public List<double> Residual = new();      // 长度 = DaysBack
        public double OverallMean;
        public double Sigma;
        public List<AnomalyPoint> Anomalies = new();
        public DateTime GeneratedAt;
    }

    public sealed class AnomalyPoint
    {
        public DateTime Date;
        public double Value;        // 当日良率
        public double Residual;     // 残差
        public double ZScore;       // 标准化后的残差
        public string Severity = "warn";  // warn / critical
    }

    public static DecompositionResult Decompose(
        AggDatabase db,
        string machine,
        SeasonalityMode mode = SeasonalityMode.Hourly,
        int daysBack = 28,
        int trendWindow = 7);

    /// <summary>被 AlertPredictor 调用：若开启季节性，返回残差告警；否则返回 null（用老逻辑）</summary>
    public static List<PredictItem>? PredictWithSeasonality(
        AggDatabase db,
        AppConfig cfg,
        string machine);
}
```

### 4.3 `AlertPredictor` 改造点

```csharp
// AlertPredictor.cs 改一处
var rows = db.QueryDailyStats();
var grouped = rows.GroupBy(r => r.Machine);
foreach (var g in grouped)
{
    // v3.19.0 老逻辑
    var ordered = g.OrderBy(r => r.TestDate).TakeLast(5).ToList();
    if (ordered.Count < 3) continue;
    var yields = ordered.Select(r => r.Total > 0 ? (double)r.Pass / r.Total * 100 : 100).ToList();
    bool declining = yields.Zip(yields.Skip(1), (a, b) => b < a).Count(x => x) >= 2;
    double last = yields.Last();
    double slope = (yields.Last() - yields.First()) / (yields.Count - 1);
    double predicted = last + slope;

    if (declining && predicted < cfg.YieldAlertYieldPct && last >= cfg.YieldAlertYieldPct)
    {
        list.Add(new PredictItem { Machine = g.Key, Rule = "yield", Level = "warn",
            Current = Math.Round(last, 1), Predicted = Math.Round(predicted, 1),
            Detail = $"良率下滑 {last:0.0}% → 预测 {predicted:0.0}% 跌破 {cfg.YieldAlertYieldPct}%" });
    }

    // v3.20.0 新增：季节性残差叠加告警
    if (cfg.YieldSeasonalityEnabled)
    {
        var seasonalAlerts = YieldDecomposer.PredictWithSeasonality(db, cfg, g.Key);
        if (seasonalAlerts != null) list.AddRange(seasonalAlerts);
    }
}
```

## 8. 自检断言（必跑）

在 `selftest/SelfTest.cs` 新增分组 `[季节性]`，至少 10 条断言：

| # | 断言 | 模拟 |
|---|---|---|
| 1 | 全 0 输入不崩溃，返回空 anomalies | 空 series |
| 2 | 平稳数据（残差 < 0.5）→ 回退到 v3.19.0 路径 | 注入 28 天全 95% |
| 3 | 显著异常日被检出（残差 > ε × σ） | 注入 27 天 95% + 1 天 70% |
| 4 | hourly 模式：白班/夜班差异被识别为周期，不误报 | 注入白天 95% / 晚上 90% 循环 |
| 5 | weekly 模式：周一比周五低 5pp → 不被当异常 | 注入每周循环 |
| 6 | daily 模式：异常日检出 | 7 天数据，1 天突降 |
| 7 | sigma = 0（数据全相同）→ 不 div/0 | mock |
| 8 | 与 AlertPredictor 集成：seasonality 关时返回空 | cfg.YieldSeasonalityEnabled=false |
| 9 | /api/yield/decompose 返回 JSON 字段齐全 | HTTP 自检 |
| 10 | 跨机台独立分解，不串 | 多机台注入 |

**回归**：现有 `AlertPredictor` 9 条断言不能红（季节性关时行为 = 老逻辑）。

## 9. 边界与回退

| 场景 | 行为 |
|---|---|
| 数据不足（< 7 天） | 返回 `Anomalies` 空，trend/seasonal 用现有数据算 |
| 全部测试数 = 0 | `OverallMean = 100`（与 v3.19.0 保持一致） |
| 残差 NaN（数据稀疏） | 跳过该日，不参与 sigma 计算 |
| 配置 `yield_seasonality_enabled=false` | 完全走老逻辑，零开销 |
| 计算超时（极少见，> 5s） | catch + Logger.Warning + 走老逻辑 |
| `batch_timestamp` 缺失 | 用 `test_date` 当日良率（粗糙 fallback） |
| `cfg.YieldSeasonalityMode` 非法 | 默认回退 hourly + 警告日志 |

**回退**：单 config key 即可关闭，**秒级回退**。
