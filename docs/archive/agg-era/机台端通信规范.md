# 机台端 ↔ Web 端 原生通道通信规范

> 版本：v1（2026-08-27）｜性质：架构铁律 + 接口契约 + 容错设计 + 测试基线
> 适用范围：Argus 机台端软件（Argus.exe）与 Web 端 Dashboard（聚合服务 `Argus.exe agg --web`）之间的全部数据传输
> 核心要求：**所有数据传输必须通过原生通道（native channel）进行，不得使用或依赖任何第三方中间件、代理或自定义协议封装**

---

## 0. 结论先行

1. **现状已符合"原生通道"要求**：机台端 ↔ Web 端的全部通信自 v3.5.0 起走**原生 HTTP/1.1**（`HttpClient` ↔ `HttpListener`）+ JSON UTF-8，零第三方中间件、零代理、零自定义协议封装（JSON 是标准数据格式，不属于协议封装）。
2. **需处置的遗留项 2 个**（均为 v3.5.0 前产物，非原生直连，已 obsolete/deprecated）：
   - SMB 共享目录通道（`agg_transport=smb`，写文件到共享目录）——非原生通道；
   - 中心化模式（`HttpIngest`/`AggWatcher`）——虽是 HTTP 但依赖中心宿主。
3. **本规范动作**：①把"原生直连"确立为不可变约束（取消总纲 P3 的"可选消息总线"方向）；②给出遗留项处置路线（降级标注，不强删保兼容）；③固化接口契约与容错设计；④提供测试用例清单（标注现有自检覆盖与补缺项）。

---

## 1. 现状通信架构（逐条核实，代码位置见右）

```
┌─ 机台端 Argus.exe ─────────────────────────────┐
│ MeshPusher（HttpClient，Timeout 5s）             │
│   ├ POST /api/mesh/fail       FAIL 事件（幂等键 machine+seq）
│   ├ POST /api/mesh/heartbeat  心跳 30s（last_seq/queued）
│   └ POST /api/mesh/event      待办等广播（best-effort）
│ MeshGossiper（复用 SendStatic HttpClient）       │
│   ├ GET  /api/mesh/summary    各机台 max_seq 摘要
│   └ GET  /api/mesh/fetch?machine&from&to  增量补缺（≤20000 行）
│ MeshReceiver（跨机拉报告）                       │
│   └ GET  /api/file?id=        按需拉源机 XML（白名单）
└──────────────┬──────────────────────────────────┘
               │ 原生 HTTP/1.1 · JSON · X-Agg-Token 鉴权
┌──────────────▼──────────────────────────────────┐
│ Web 端聚合服务（HttpListener 单端口 8081）        │
│   /api/mesh/fail|heartbeat|event|summary|fetch|peers|xml
│   /api/file | /api/fails | /api/fails/count | /api/export.csv | /api/health | /api/settings
│   接收 → MeshReceiver（组提交 50ms/100 条）→ AggDatabase（(machine,seq) 幂等）
└─────────────────────────────────────────────────┘
```

| 通道 | 传输方式 | 是否原生 | 代码位置 |
|---|---|---|---|
| FAIL/心跳/事件推送 | HttpClient POST | ✅ 原生 HTTP | MeshPusher.cs（Timeout 5s） |
| 对账摘要/增量拉取 | HttpClient GET | ✅ 原生 HTTP | MeshGossiper.cs |
| 跨机 XML 拉取 | HttpClient GET | ✅ 原生 HTTP | MeshReceiver.cs:231 |
| 入站接收 | HttpListener | ✅ 原生 HTTP | WebAggServer.cs / MeshReceiver.cs |
| 遗留：SMB 共享目录 | File.Copy 到共享目录 | ❌ 非原生（v3.5.0 前） | AggWatcher.cs（obsolete）/ Config.AggTransport |
| 遗留：中心化 HTTP | HttpClient POST /api/fail | ⚠ HTTP 但中心化 | HttpIngest.cs（obsolete） |

**明确不存在**：第三方消息中间件（RabbitMQ/NATS 等）、反向代理/Nginx 类、自研二进制协议封装、WebSocket 代理层。

## 2. 原生通道契约（接口基线，v3.5.0 起稳定未变）

### 2.1 传输层
| 项 | 约定 |
|---|---|
| 协议 | HTTP/1.1（无 HTTPS 要求，内网；`agg_http_url`/peer 用 http 时启动告警提示可升 https） |
| 序列化 | JSON（UTF-8，字段 PascalCase） |
| 鉴权 | `X-Agg-Token` 头（POST 推送）／HttpOnly Cookie `agg_token`（浏览器）／`?token=`（兼容）；固定时间比较 |
| 超时 | 出站 5s（MeshPusher/静态共享 HttpClient）；入站 busy_timeout 5000ms |
| 上限 | POST body ≤1MB（超 413）；并发闸 64（超 503）；`/api/mesh/fetch` 单次 ≤20000 行；`/api/fails` limit ≤1000 |

### 2.2 端点清单
| 端点 | 方法 | 方向 | 请求 | 响应 | 语义 |
|---|---|---|---|---|---|
| `/api/mesh/fail` | POST | 机台→Web | `{machine, type:"fail", seq, ts, data:{station_id,model,test_date,sn,result,fail_reason,xml_path,…}}` | 200（成功/幂等忽略）；5xx（入库失败，触发对端重推） | **返回即已落库**（组提交阻塞至提交完成）；`(machine,seq)` 幂等 |
| `/api/mesh/heartbeat` | POST | 机台→Web | `{machine, type:"heartbeat", ts, last_seq, queued}` | 200 | 更新在线视图（90s 超时判离线）；last_seq 供对账 |
| `/api/mesh/event` | POST | 机台→Web | 待办等事件 JSON | 200 | best-effort 广播，最终一致由 Gossiper 兜底 |
| `/api/mesh/summary` | GET | 机台↔Web | 无 | `{machines:[{machine,max_seq}]}` | 对账基准 |
| `/api/mesh/fetch` | GET | 机台↔Web | `machine, from, to` | `{events:[fail-json…]}`（≤20000 行，seq 升序） | 增量补缺；`(machine,seq)` 幂等可重拉 |
| `/api/mesh/peers` | GET | 浏览器 | 无 | 邻居视图（Machine/Online/LastHeartbeat/Queued/FailCount） | 看板机台卡 |
| `/api/mesh/xml` | GET | 浏览器/机台 | `id` | XML 文本 | **本地读取必须过白名单**（H-1 加固）；跨机拉源机 `/api/file?id=` |
| `/api/file` | GET | 浏览器/机台 | `id` 或 `path` | XML 文件 | 白名单（resultsRoot / agg_xml / 日志） |
| `/api/fails`、`/api/fails/count`、`/api/export.csv` | GET | 浏览器 | `limit/machine/offset/q` | JSON / CSV（UTF-8 BOM + 公式注入防护） | 明细/计数/导出 |
| `/api/health`、`/api/settings` | GET/POST | 浏览器 | — | JSON | 健康 / 设置（token 不回显） |

## 3. 不符合原生通道项与处置

| # | 项 | 现状 | 处置 | 兼容性 |
|---|---|---|---|---|
| N1 | **SMB 共享目录通道**（`agg_transport=smb`） | v3.5.0 前机台把 FAIL 事件写文件到共享目录，聚合端扫描——依赖 SMB 文件系统，非原生直连 | ①config 解析已默认回落 http；②文档与设置页标注 deprecated；③v4.x 评估移除（保留解析兼容） | 不破坏：已用 smb 的旧配置仍工作，但新装一律 http |
| N2 | **中心化模式**（`HttpIngest`/`AggWatcher`） | v3.5.0 前中心宿主，obsolete | 仅 GUI 兼容路径保留；新部署一律去中心化 mesh | 保留但不演进 |
| N3 | **未来方案 P3 的"可选消息总线"**（RabbitMQ/NATS） | 总纲 P3 曾列为可选 | **取消**——本规范确立原生直连为铁律；扩容靠现有 mesh（多 peer 并发、对账间隔自适应） | 架构决策，写入总纲 |

## 4. 边界与容错设计（现状逐项核实）

| 场景 | 机制 | 状态 |
|---|---|---|
| 网络抖动/短暂断连 | 事件进内存队列（MaxQueue 5000），失败不丢；`mesh_queue.json` 落盘，重启续推 | ✅ 已实现（MeshPusher） |
| 长时间断连 | 看门狗退避重启 worker（5s×n 递增至 10）；每 peer 独立链路状态（ConsecutiveFailures≥3 → Disconnected → 飞书告警） | ✅ 已实现 |
| 推送丢事件 | `(machine, seq)` 幂等键 + 重启 `RunCatchUpScan` 补推；Gossiper 30s 对账兜底 | ✅ 已实现 |
| 入库失败 | 接收端组提交失败整批回滚 → 抛 AggIngestException → HTTP 5xx → 对端重推（幂等不重） | ✅ 已实现 |
| 对端超时 | 出站 HttpClient Timeout=5s（固定）；失败计入该 peer 链路失败计数 | ✅ 已实现 |
| 对端离线 | 心跳 90s 超时判离线 → 看板标红 + 飞书离线告警（防抖） | ✅ 已实现 |
| 消息过大 | POST body ≤1MB 超限 413；超大 body 排空上限 8MB（DoS 加固） | ✅ 已实现 |
| 并发洪峰 | SemaphoreSlim(64) 超限即 503 断连；接收端组提交（50ms/100 条）削 WAL 写放大 | ✅ 已实现 |
| 恶意/异常输入 | JSON 解析失败忽略；DTD Prohibit 防 XXE；xml_path 白名单（H-1）；token 固定时间比较 | ✅ 已实现 |

**结论：通信层容错机制完备，无需补代码缺口。** 唯一可选项（不阻塞）：Gossiper 拉取超时可配置（当前复用 5s 固定），列为 v4.x 增强。

## 5. 兼容性保证（改造原则）

- **接口契约零变更**：本规范只做"确立基线 + 处置遗留"，不改任何端点、方法、字段、状态码语义。
- **向后兼容**：`(machine,seq)` 幂等键、`X-Agg-Token` 鉴权、JSON 字段名全部不变；机台端 `config.json` 无需改动。
- **回归保障**：改动必须过全量自检（当前 647 项断言，含 HTTP 双通道、断连状态机、幂等、白名单、并发闸等通信相关组）。

2. SMB 配置回落断言：`agg_transport=smb` 时启动仍走 http（或明确标记 deprecated 的日志断言）。

## 7. 结论与后续

- **本轮无需重写通信层**：现状即原生直连，交付物为规范基线 + 遗留处置 + 测试映射。
- **架构铁律（写入总纲）**：机台端 ↔ Web 端一律原生 HTTP/1.1 直连；禁止引入消息中间件、代理、自定义协议封装；扩容依赖 mesh 原生机制（多 peer 并发、对账自适应），不引入新传输组件。
- **遗留清理时间表**：SMB 通道与中心化模式在 v4.x 随无头服务化一并评估移除（保留配置解析兼容）。
- **测试补强**：按 §6 补缺项新增 2 组自检断言。

## 附：与统一方案的关系
- 取消《统一实施方案_总纲》§P3-2 "事件总线（可选）"方向，替换为本规范的原生直连铁律。
- 本规范是 dashboard 全部接口（§2.2）的契约基线，后续新增端点（/api/xmlview、/api/devices 等）一律沿用同通道同约束。
