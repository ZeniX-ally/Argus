# 算法优化规格总览（v3.20.0 候选）

> 入口页：详细规格见 [`算法优化/`](./算法优化/) 目录
> 状态：待评审（2026-09）
> 承接：v3.19.0 智能化扩展（9 个智能化域）之后的算法升级

## 四份规格

| # | 规格 | 价值 | 风险 | 推荐落地阶段 |
|---|---|---|---|---|
| 01 | [良率归因](./算法优化/01-良率归因.md) | ROI 最高：把"会跌"升级为"为什么跌" | 中 | 阶段 4 |
| 02 | [预测准确率自反馈](./算法优化/02-预测准确率自反馈.md) | 让预测越用越准，自动调阈值 | 低 | 阶段 1 |
| 03 | [季节性分解](./算法优化/03-季节性分解.md) | 干掉 70% 误报（白班/夜班/周末） | 低 | 阶段 2 |
| 04 | [设备健康综合分](./算法优化/04-设备健康综合分.md) | 单指标告警 → 加权综合告警 | 低 | 阶段 3 |

## 落地路线

```
阶段 1：02 自反馈（低风险、立竿见影）   → 立即可推
阶段 2：03 季节性（纯加法、回退容易）    → 1 周后
阶段 3：04 健康分（替换内部算法）       → 2 周后
阶段 4：01 归因（多源 join、UI 工作量大） → 3 周后
```

每阶段独立 commit + PR + 验证 + 发布。任一阶段回滚都不影响其他。

## 共用前置

- 基线口径：**同机台历史同期**（用户确认）
- 数据库版本：依赖 v3.19.0 的 yld_daily / device_samples / agg_records；**仅 02 新增一张 predict_accuracy_log 表**
- 零第三方依赖（保持现状，不引入 ML.NET / NumPy 等）
- 默认参数下行为 100% 兼容 v3.19.0，新功能靠配置开关启用

详细见 [README.md](./算法优化/README.md)。
