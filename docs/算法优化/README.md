# 算法优化规格（v3.20.0 候选）

> 适用范围：FctAggregator 主程序（Argus.exe） + WebAggServer + SPA 前端
> 状态：**待评审**（2026-09）
> 承接：v3.19.0 智能化扩展（9 个智能化域）之后的算法升级
> 配套更新：`TECHNICAL_DOCUMENTATION.md`、`更新日志.md`

---

## 1. 背景

v3.19.0 在 9 个智能化域落地的能力是**基于简单规则的浅层智能**：

| 现有 | 局限 |
|---|---|
| `AlertPredictor` 线性趋势 | 只说"良率会跌"，不说"为什么跌" |
| `PriorityScorer` 静态加权 | 不考虑趋势变化（恶化中 vs 收敛中） |
| `HighlightEngine` 单指标阈值 | 单独 CPU 高可能是备份；单独 disk 低 + 离线抖才是真问题 |
| 阈值全部写死在 `config.json` | 误报后只能人工调，不会自动校准 |

这些能力方向对，但**算法深度不足**，限制了"智能"二字的兑现程度。本批规格对四个高 ROI 的优化做实现级细化，可独立落地、互相解耦、逐个 PR 上线。

## 2. 四份规格总览

| # | 规格 | 价值 | 改动范围 | 风险 |
|---|---|---|---|---|
| 01 | **良率归因** (Yield Attribution) | 最高：把"会跌"升级为"因为谁跌" | `Database` + `AggDatabase` + `WebAggServer` + `/public/js/` | 中（SQL 多源 join） |
| 02 | **预测准确率自反馈** (Predict Accuracy Loop) | 高：让所有预测自己越用越准 | `AggDatabase` 新表 + `AlertPredictor`/`DevicePredictor` 加钩子 | 低（只读计算） |
| 03 | **季节性/班次分解** (Seasonality Decomposition) | 高：干掉 70% 误报 | `AlertPredictor` 加窗口 + `AppConfig` 两条新阈值 | 低（纯加法） |
| 04 | **设备健康综合分** (Device Health Score) | 中：把"单指标告警"升级为"加权告警" | `DevicePredictor` 重写 + `HighlightEngine` 调阈值 | 低（替换实现） |

> **基线口径**（用户确认）：良率归因**只用"同机台历史同期"基线**（vs 过去 4 周同星期几）。
> 留一个 follow-up："全产线同期均值"作为 v3.20.1 增强，因为工业现场单台异常 vs 传染性异常的区分
> 确实有价值，但本期先保证基础归因稳。

## 3. 共用前置

### 3.1 数据库版本
四个算法都依赖 `yld_daily` + `agg_records` + `device_samples` 三张已存在的表，
**不引入新表（除规格 02 的 `predict_accuracy_log`）**。

| 表 | 已有版本 | 本批规格的新增字段 |
|---|---|---|
| `yld_daily` | DbMigrator v2 | 无（只查询） |
| `agg_records` | DbMigrator v1 | 无（只查询） |
| `device_samples` | P6（v3.19.0） | 无（只查询） |
| `predict_accuracy_log` | **新增** | 见规格 02 |

### 3.2 配置扩展
只有规格 03 增加两个新键（其他不改 config）：
```jsonc
// 季节性分解（v3.20.0）
"yield_baseline_window_days": 28,    // 良率基线取过去 N 天同星期几
"yield_seasonality_epsilon": 1.5,   // 残差告警 σ 倍数（默认 1.5 = 86% 置信度）
```
两者为空时**不启用**新逻辑，行为与 v3.19.0 完全一致（向后兼容）。

### 3.3 自检断言位置
所有自检统一加在 `selftest/SelfTest.cs` 的现有良率/预测分组里，**每条新算法独立成一个分组**，
保持原有 669+ 断言不被干扰。分组前缀：
- `[归因]` — 规格 01
- `[自反馈]` — 规格 02
- `[季节性]` — 规格 03
- `[健康分]` — 规格 04

### 3.4 不在范围内
- **不引入 ML.NET / 第三方 ML 库**（见 `AI 模型选型风险评估` 备注，本期用纯 C# 实现）
- **不引入 NuGet 包**（保持零第三方依赖的现状，参考 `FctAggregator.csproj`）
- **不重写已有公开 API**（只在末尾加路由）
- **不修改数据库 schema**（除 02 的新增表，按 `DbMigrator` 规范追加 v8 迁移）

## 4. 落地路线图

```
阶段 1：02 自反馈（低风险、立竿见影）   → 立即可推
阶段 2：03 季节性（纯加法、回退容易）    → 1 周后
阶段 3：04 健康分（替换内部算法）       → 2 周后
阶段 4：01 归因（多源 join、UI 工作量大） → 3 周后
```

每阶段独立 commit + PR + 验证 + 发布。任一阶段回滚都不影响其他。
