# 规格 05：机台端自学习（Self-Learning，产品针对性）

> 状态：已评审（2026-09-04）
> 承接：算法优化 4 规格全部落地后的第 5 份规格；本规格为**机台端本地自学习**，不依赖聚合端、不引入任何第三方依赖（纯 C# 手写统计）
> 产品依据：`G4.9 FCT Specification of PCBA v3.0`（2026-06-15）——信号族、判定结构、治具依赖、型号阈值差异全部取自产品规范本身，不基于历史数据统计

---

## 1. 目标与非目标

### 1.1 目标

| 目标 | 度量 |
|---|---|
| **产品针对性**：预警/归并/建议全部建立在 G49 产品知识（信号族、判定语义、治具依赖）之上，不说无指向的"异常" | 每条预警必须带根因指向（治具/仿真器/来料/通信/供电）——进自检断言 |
| 预警准确率：固定阈值 → 本机"正常范围"（滚动基线） | 历史回放对拍：自基线 vs 固定阈值命中/误报对比（自检内置） |
| 自适应学习：机台越用越懂自己 | 基线每日重算滚动更新；learned 参数可查可重置 |
| 零依赖、机台零外部依赖 | 不动 §2 依赖白名单；学习全程本机完成，断 mesh 可用 |
| 性能可忽略 | 学习计算 O(样本数)，7 天窗口毫秒~十毫秒级；每日 1 次后台执行 |

### 1.2 非目标（明确不做）

- **不引入 ML 库/ML.NET**（已否决，见会话记录 2026-09-04）
- **不做 mesh 基线同步**：纯本地学习；将来聚合端汇总另立规格
- **规格带漂移预警（P2 预留）**：spec 各参数带宽已知（如 `P1V2_PHY_AVDD = 1.14~1.26V`、`KL30_1 < 5mA`），可解析失败值算"偏离规格带深度"做渐近恶化预警（如 KL30_1 电流逼近/超出 5mA 上限的趋势）。**前置验证项**：PASS 记录的测量值是否可得（需 XmlParser 深度模式验证），一期仅 FAIL 值严重度趋势，不承诺
- **不做 TDMS 波形分析**：XCP 参数 100Hz 记录为 .tdms，体量大，一期只用测试项级 pass/fail
- **不聚合端改动**：WebAggServer/聚合库零改动
- **不学判定阈值**：FAIL 判定以产品 spec 为唯一来源，自学习只学"本机正常态"，不碰 spec 阈值

## 2. 产品针对性分析（全部取自 G49 spec）

### 2.1 fail_reason 与 spec 判定表对应

fail_reason 格式 `{spec章节号} {信号名}({测量类型})`，其中章节号即 spec 各章"预期结果"表的步骤号（如 `6.1.1.2.7 P5V_CAN(DMM)` = 电源测试表步骤 2.7）。测量类型四类均为 spec 定义：DMM（万用表）/ XCP（标定协议读取）/ OSC（波形）/ Power（电源）。**解析器按此结构构建，字典优先（§2.3）。**

### 2.2 关键口径决策

| 口径 | 决策 | 依据（产品 spec） |
|---|---|---|
| 型号分桶 | 良率/产能基线 key **必含 PCBA 型号** | spec §6.1/§8.3 明确按型号区分阈值与硬件配置（P17V_LV_LS 16.5V vs 18V、KL30_2 电流 0.35A vs 0.42A、HWCFG 各异），不同型号混线时正常态天然不同 |
| 时段分桶 | **型号 × 时段段（夜 00-06 / 早 06-12 / 午 12-18 / 晚 18-24 四段）**，不做 24 小时分桶 | 工程决策：FCT 产线测试集中在白班，24 小时分桶夜间桶样本过稀永远冷启动；四段分桶保证每桶可学习 |
| 中断记录 | INTERRUPTED **独立通道**（每日中断率基线 + 时段热区），不混入良率学习 | 中断无失败项，是治具/通信/操作域问题（spec §8.22 测试后状态检查独立成章，同属流程域） |
| SN 重测 | 学习输入按 **SN 去重** | spec 兼容 6 个型号（§4.1），同一板卡重复测试属复测，非独立样本 |
| 注入型排除 | 8.19/8.20/8.21 注入型失败**不进章节群挂**（仍进真实良率口径） | 见 §2.4 语义分类 |

### 2.3 支柱一：G49 产品信号族字典（字典优先，正则回落）

G49 spec 的信号结构**已知且固定**，归并不靠猜——spec §6~§9 的信号族固化为产品字典（`Intelligence/G49ProductDictionary.cs`，随产品走，新增产品型号=加字典文件）：

| 族 | 成员（spec 实名） | 失效含义（产品知识） |
|---|---|---|
| 栅极驱动六相 | `SiC_G_HU/HV/HW/LU/LV/LW`（±`SiC_S_*`） | 单相挂 = 该相驱动/接触；多相挂 = 驱动芯片/供电（spec §8.18/§8.20） |
| 三相电流 | `TC_AI_Cur_1/2/3`、`CURMV_v_CurL1V/L2V/L3V` | 单相挂 = 接触；三相挂 = 板问题（spec §8.9） |
| 旋变四角 | `RES_v_ResAng(45°/135°/225°/315°)` | 全挂 = 旋变仿真器/接线（spec §8.11 需仿真器） |
| IGBT 三相温度 | `IGBTTM_v_IgbtTU/TV/TW` | 多相同挂 = NTC 仿真链（spec §4.4 493.4Ω 电阻） |
| 成对通道 | `CBTM_v_CbT1/T2`、`BSW_v_eFuse_A/B`、`HVIL_In/Out` | 成对挂 = 共源问题 |
| KL30 双轨 | `KL30_1/KL30_2`（含 `KL30_FILT_1/2`、HS/LS 变体） | 两轨独立，**不并** |
| GD 状态数组 | `BSW_v_GD_Status1/2[0..5]`、`FLTM_v_ErrStateInvOff1..10` | 数组下标 = 相位映射（spec §9.1），同族归并 |
| 电源轨群 | `P17V_LV_LS`/`P5V_*`/`P3V3_*`/`P1.25V_LVD_Core`/`P12V_FB_HS`/`P15V_LVD_LS` 等 | 同章节多轨挂 = 供电系统性（spec §6.1 步骤 2 全轨清单） |
| 双轮测量 | `6.1.1.x`（PWM off）/ `6.1.2.x`（PWM on）同信号 | 跨轮归并；仅单轮挂 = 边界/接触（spec §6.1 流程步骤 2 vs 7） |

匹配优先级：全名精确 → 族占位（相位/角度/下标归一）→ 正则结构解析（章节号 + 测量类型，容忍空格异常与属性后缀如 `_Offset`/`High·Low Level`/`Frequency`）→ **原串回落，绝不吞掉**。

### 2.4 支柱二：判定语义四分类（不同语义的失败分开学）

G49 spec 的"FAIL"有四种不同物理含义，混在一起学必然误报：

| 语义 | spec 依据 | 学习处理 |
|---|---|---|
| **测量型** | 电压/电流/温度超规格（§6.1、§8.1、§8.7~§8.12、§8.14~§8.17） | σ 基线 + 章节群挂 + 稳定性分类全适用 |
| **通信型** | XCP 读取失败、以太网 `linkStatus/sqi`（§7.2） | 独立频次基线，根因指向治具通信链 |
| **注入型** | §8.19 DESAT、§8.20 ASC/SPO/Toggle、§8.21 SBC——**流程故意注入故障，FAIL = 预期翻转未出现**（如 `BSW_vb_NMI_ESR1_Flt` 应 0→1→0） | 排除出章节群挂（流程性失败不证明供电/治具问题）；仅独立频次跟踪 |
| **中断型** | INTERRUPTED（无失败项） | 时段热区统计 |

### 2.5 支柱三：治具依赖与根因指向

spec §4.4 测试设置明确依赖外部工装的章节：

| 章节 | 工装依赖（spec §4.4/§8.x） | 预警根因指向 |
|---|---|---|
| §8.11 旋变 | ResE/ResD 旋变仿真器 + 120Ω 10W | "先查旋变仿真器/接线" |
| §8.14 继电器 | X4400 继电器负载 | "先查继电器工装" |
| §8.15 阀体 | Valve_Coil 30Ω 10W 负载 | "先查阀体负载" |
| §8.7 SiC 温度 | SiC_NTC 493.4Ω 电阻 | "先查 NTC 仿真电阻" |
| §8.10 EM NTC | 四标准电阻（1724k/61.47k/6.12k/0.313k） | "先查 NTC 标准电阻链" |
| §4.4 全局 | SiC_D/S 短接点、SiC_G 100nF 电容 | 涉及项挂 = 先查工装短接/电容 |

测量型持续超差（如 KL30_1 电流超出 spec 5mA 上限且多日复现）→ 指向"来料批次/程序版本"；通信型 → "治具通信链"。**机器不说"异常了"，说"哪大概率坏了"。**

## 3. 四项功能设计

### 3.1 良率/产能自基线（learn_baseline_enabled）

- 数据源：本机 `test_records`（PASS/FAIL/INTERRUPTED 全量，SN 去重）
- 基线结构：按 `型号 × 时段段`（四段，§2.2）分桶，滚动 `learn_baseline_window_days`（默认 7）天窗口：
  - 每桶：样本数、PASS/FAIL/INTERRUPTED 数、良率 mean/σ
  - 当日某桶良率偏离基线 > `learn_baseline_sigma`（默认 3.0）σ → 本机预警标记（含期望区间与实际值）
- 中断独立通道：每日中断率基线 + 时段热区
- 呈现：主页看板/总览页预警条目（只标记不强动作）
- 冷启动：窗口内样本 < `learn_baseline_min_samples`（默认 30）→ 该桶不产出预警（宁缺勿滥）

### 3.2 资源自采样+基线（learn_resource_sampling_enabled）

- 本机自采样：`Intelligence/DeviceSampleRecorder.cs` 每 5min 记录 CPU/内存/磁盘剩余——CPU 用 kernel32 `GetSystemTimes` P/Invoke（差分算占比）、内存用 `GlobalMemoryStatusEx` P/Invoke、磁盘用 `DriveInfo`（BCL），**零 NuGet 新依赖**（禁 PerformanceCounter——需额外包，违反白名单）
- 新表 `device_samples_local(ts TEXT PRIMARY KEY, cpu_pct REAL, mem_pct REAL, disk_free_gb REAL)`（DbMigrator v13，老库幂等迁移）
- 滚动清理：DbMaintenance 每日删 `learn_resource_retention_days`（默认 14）天前样本（288 行/天 × 14 ≈ 4K 行，可忽略）
- 基线：按小时分桶同 3.1 统计，偏离 >3σ 本机自预警（设备页标记）
- 与聚合端 device_samples 互不影响（聚合端照旧收 mesh 上报）

### 3.3 维修/待办自学习（learn_priority_enabled）

- 数据源：本机 `maintenance_records`（完成顺序/耗时）+ `dismissed_todos`（忽略记录）
- 学习规则（乘性校准，防跑飞）：
  - 实际被先处理的待办特征（优先级来源、类型）→ 权重上调
  - 高频被忽略的建议来源 → 权重下调
  - 校准因子 clamp `[0.5, 2.0]`，仅影响 **PriorityScorer/TodoSuggester 排序**，不改状态机、不改数据
- 重算时机：每日 DbMaintenance 窗口，后台线程

### 3.4 故障归并 + 章节群挂 + 根因指向（learn_fail_merge_enabled）

- 解析器 `Intelligence/FailReasonMerger.cs`：**字典优先（§2.3 G49ProductDictionary）→ 正则回落 → 原串兜底**
- 归并 key 三级粒度（config `learn_fail_merge_level`）：
  - `off`（默认）：不归并，行为 100% 兼容
  - `signal`：章节号+信号族+测量类型（推荐）
  - `section`：仅章节号（如 §8.11 全部旋变项一类）
- 应用点：**仅展示层**——本地 Top 5 排行（DashboardWidgets.TodayFailRankPanel 数据源与 FailListPanel 统计）按归并 key 聚合；test_records 数据层不动
- 章节群挂检测：当日按章节号聚合去重信号基名数 ≥ `learn_group_alert_min`（默认 3）→ 章节级预警；**注入型章节（§8.19/8.20/8.21）排除**
- 根因指向：群挂/族命中后，预警文案按 §2.5 附产品根因指向（治具/仿真器/来料/通信/供电），不做无指向播报
- 产品价值示例（spec 推演）：旋变四角度族全挂 → 一条预警"旋变仿真器/接线"；§6.1 多电源轨同日群挂 → 一条预警"供电系统性"，替代散落的十几个单项告警

## 6. 人工干预与控制

1. 每项功能独立 config 开关，默认全关；开关即时生效（ConfigWatcher 已有）
2. 基线/学习状态可查：设置页"自学习"区（各桶样本数、σ、上次重算时间、校准因子、字典命中/回落比例），一键重置
3. 自预警只标记不强动作（不自动建待办、不发飞书，一期）
4. 权重校准只改排序，不改状态机；clamp 0.5~2.0 防跑飞；重置即回默认权重
5. 预警文案的根因指向可在 UI 一键标"误报"→ 记入 dismissed 侧反馈（供 §3.3 学习与人工审计）
6. 兼容铁律：老库 v13 幂等迁移+失败回滚；config 缺省可运行；mesh 协议不动

| SelfBaseline | 型号×时段段分桶/σ 边界（卡开区间侧，v3.22.0 教训）/冷启动不预警/窗口滚动/型号隔离 |

## 9. 评估与验收

1. **回放对拍**（自检内置）：固定样本集回放，自基线 vs 固定阈值命中/误报对比断言——注入的渐进异常命中、正常抖动不误报
2. **字典命中断言**：spec 全部信号族样本归并正确；未知信号回落率可观测（设置页显示）
3. **根因指向断言**：每条预警必带指向（无指向文案即断言失败）
4. **上线后人工观察**（config 开启后 1~2 周）：预警是否可行动、误报标记率（§6.5 反馈闭环）
5. 全部开关关闭 = 与 v3.23.3 行为一致（回归断言保证）
