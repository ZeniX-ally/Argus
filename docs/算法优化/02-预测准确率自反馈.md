# 规格 02：预测准确率自反馈（Predict Accuracy Loop）

> 状态：v3.20.0 候选 | 阶段 1（最先落地） | 改动范围：小 | 风险：低

---

## 1. 动机与目标

### 1.1 现状痛点

所有预测都"打出去就忘了"：

| 现有 | 行为 |
|---|---|
| `AlertPredictor.Predict()` 预测良率会跌破 90% | 落 `alert_predict_log` 后**不再回看** |
| `DevicePredictor.Predict()` 预测 CPU 3 天后到 95% | 落 `device_predict_log` 后**不再回看** |
| 阈值（`yield_alert_yield_pct=90`、`device_alert_cpu_pct=90`）| **硬编码** 在 `config.json`，人工手动调 |

结果：
- 预测准不准？不知道
- 阈值是不是太严/太松？不知道
- 现场反馈"误报太多"或"漏报" → 工程师只能猜着改阈值

### 1.2 目标

每条预测自动和"后来实际值"对账，落一张 `predict_accuracy_log` 表，并在 `/api/predict/accuracy` 端点暴露：

```json
{
  "window_days": 30,
  "summary": {
    "yield":   { "total": 142, "hit": 98, "accuracy": 0.69, "avg_lead_days": 1.0 },
    "cpu":     { "total": 67,  "hit": 51, "accuracy": 0.76, "avg_lead_days": 2.3 },
    "disk":    { "total": 12,  "hit": 11, "accuracy": 0.92, "avg_lead_days": 1.4 },
    "offline": { "total": 8,   "hit": 7,  "accuracy": 0.88, "avg_lead_days": 0.0 }
  },
  "per_machine": [
    { "machine": "FCT3", "rule": "yield", "hit_rate": 0.85, "miss_streak": 0 },
    { "machine": "FCT5", "rule": "yield", "hit_rate": 0.42, "miss_streak": 5 }
  ],
  "threshold_tuning": [
    { "rule": "yield", "current": 90.0, "recommended": 92.5, "reason": "近 30 天 5 连 miss" }
  ]
}
```

**业务价值**：让所有预测"自我校准"——长期看会越来越准。

### 1.3 成功标准

| 指标 | 目标 |
|---|---|
| 对账覆盖率 | 已落库的 predict_log 中能被对账的比例 ≥ 90% |
| 阈值推荐触发率 | 连续 4 周 miss_streak ≥ 5 → 自动出推荐 |
| 推荐有效性（模拟） | 调整后 4 周命中率提升 ≥ 5pp |
| 新增存储开销 | ≤ 500 行/月（30 台 × 4 规则 × 30 天） |

## 2. 数据口径与依赖

### 2.1 复用已有能力

| 资源 | 来源 | 用途 |
|---|---|---|
| `alert_predict_log` | `AlertPredictor.LogPredictions()`（已有） | yield 预测输入 |
| `device_predict_log` | `DevicePredictor.LogPredictions()`（已有） | cpu/disk/offline 预测输入 |
| `yld_daily` | DbMigrator v2 | yield 实际值对账来源 |
| `device_samples` | P6 | cpu/disk 实际值对账来源（取最新样本） |
| `device_info` | P6 | offline 实际值对账来源（`last_seen`） |

### 2.2 "对账"定义

| 规则 | 预测成功的判定（hit） |
|---|---|
| yield | 预测 time + N 天后，实际 yld_daily.yield < 阈值（与预测一致） |
| cpu | 预测 N 天后，device_samples 里 cpu_usage ≥ 95（与 `Level` 一致） |
| disk | 预测耗尽日期 ± 3 天内，disk_free_gb ≤ 0 或 ≤ 5GB（"真的快耗尽了"） |
| offline | 预测 offline 后，实际 24h 内出现 `last_seen - now > 90s`（"真的离线过"） |

"miss" = 同条件下**未发生**预测警告的事件。

"lead_days" = 实际发生日期 - 预测日期（领先天数，越长越有价值）。

## 3. 算法与伪代码

### 3.1 后台对账任务

```text
function ReconcileOnce(db, cfg):
    now = DateTime.Now
    horizon = 14  # 14 天前的预测一定有结论了
    
    # 1) 取过去 horizon 天的所有 predict_log
    for rule in ["yield", "cpu", "disk", "offline"]:
        candidates = QueryPredictLog(rule, from=now-horizon, to=now-1)
        for p in candidates:
            # 2) 检查是否已对账（predict_accuracy_log.reconcile_key 唯一）
            if AlreadyReconciled(p.id): continue
            
            # 3) 取"未来的实际值"
            actual = LookupActual(rule, p.machine, p.predicted_ts)
            if actual is None: continue  # 还不够数据
            
            # 4) 判定 hit / miss
            hit = IsHit(rule, p, actual)
            lead_days = (actual.event_ts - p.predicted_ts).TotalDays
            
            # 5) 落 predict_accuracy_log
            db.InsertAccuracy({
                predict_id: p.id,
                rule: p.rule,
                machine: p.machine,
                predicted_value: p.predicted_value,
                actual_value: actual.value,
                threshold: p.threshold,
                hit: hit,
                lead_days: lead_days,
                reconciled_at: now
            })
```

### 3.2 阈值推荐算法（核心）

```text
function RecommendThreshold(rule, recent_accuracies, current_threshold):
    # 输入：最近 4 周的 accuracy 记录（窗口可配）
    # 输出：recommend new threshold (or null = 维持)
    
    # A) 找连续 miss_streak ≥ 5 的机器（"总是狼来了"）
    per_machine_misses = GroupByMachine(recent, g => g.where(!x.hit).count())
    chronic_miss = any(per_machine_misses >= 5)
    
    # B) 算全局命中率
    overall_hit = recent.hit_count / recent.total
    
    # C) 推荐规则
    if overall_hit < 0.30:
        # 误报太多：放宽阈值（更难触发）
        new = current_threshold * 1.05   # yield 反向：阈值 ↑ 表示更严，但 yield_alert 是越低越糟
        # 注：yield_alert 是"跌破阈值告警"，阈值 ↑ → 难跌破 → 告警少 → 放宽
        return AdjustYieldThreshold(current, +5%)
    elif overall_hit > 0.85 and recent.total >= 30:
        # 漏报多：收紧阈值
        return AdjustYieldThreshold(current, -5%)
    elif chronic_miss:
        # 单机问题，不是阈值问题，建议去查那台机台（不出阈值推荐）
        return null
    else:
        return null
```

**冷启动保护**：样本 < 30 条规则不推荐（避免抖）。

### 3.3 关键参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `reconcile_horizon_days` | 14 | 14 天前的预测必查 |
| `reconcile_cron` | 每日凌晨 04:00 | `DbMaintenance` 顺带执行（同锁内串行） |
| `min_samples_for_tune` | 30 | < 30 不推荐 |
| `miss_streak_threshold` | 5 | 连续 5 次 miss 标"慢性误报" |
| `accuracy_low` | 0.30 | < 0.30 → 放宽阈值 |
| `accuracy_high` | 0.85 | > 0.85 且 ≥ 30 样本 → 收紧 |
| `tune_step_pct` | 5 | 推荐调整步长 ±5% |

## 4. 接口与签名

### 4.1 新增静态类 `PredictAccuracyReconciler`

```csharp
namespace FctAggregator;

public static class PredictAccuracyReconciler
{
    public sealed class ReconcileSummary
    {
        public int WindowDays = 30;
        public Dictionary<string, RuleStat> Summary = new();  // rule -> RuleStat
        public List<MachineHitRate> PerMachine = new();
        public List<ThresholdTune> ThresholdTuning = new();
        public DateTime GeneratedAt;
    }

    public sealed class RuleStat
    {
        public int Total;
        public int Hit;
        public double Accuracy;       // hit/total
        public double AvgLeadDays;
    }

    public sealed class MachineHitRate
    {
        public string Machine = "";
        public string Rule = "";
        public double HitRate;
        public int MissStreak;        // 末尾连续 miss 次数
    }

    public sealed class ThresholdTune
    {
        public string Rule = "";
        public double Current;
        public double Recommended;
        public string Reason = "";
    }

    /// <summary>对账 + 统计 + 推荐（一次性执行，0.5s 内完成 30 台机台）</summary>
    public static ReconcileSummary Reconcile(AggDatabase db, AppConfig cfg);

    /// <summary>后台入口，由 DbMaintenance 每日凌晨 04:00 顺带调用</summary>
    public static int RunOnce(AggDatabase db, AppConfig cfg);  // 返回对账条数

    public static (bool Hit, double LeadDays)? ClassifyYieldHit(YldDailyRow actual, AlertPredictLogRow predict);
    public static (bool Hit, double LeadDays)? ClassifyCpuHit(DeviceSampleRow actual, DevicePredictLogRow predict);
    public static (bool Hit, double LeadDays)? ClassifyDiskHit(DeviceInfoRow actual, DevicePredictLogRow predict);
    public static (bool Hit, double LeadDays)? ClassifyOfflineHit(DeviceInfoRow actual, DevicePredictLogRow predict);
}
```

### 4.3 SQL（核心查询）

**Q1：取待对账的 predict_log（去重已对账的）**

```sql
SELECT p.id, p.rule, p.machine, p.predicted_value, p.level, p.ts AS predicted_ts, p.detail
FROM alert_predict_log p
LEFT JOIN predict_accuracy_log a ON a.predict_id = p.id AND a.predict_table = 'alert'
WHERE p.ts BETWEEN @from AND @to
  AND a.id IS NULL
ORDER BY p.ts;
-- 同样模板套 device_predict_log
```

**Q2：取实际值**

```sql
-- yield 实际：predict_ts + lead_days 那天的 yld_daily
SELECT machine, test_date, pass, fail, total
FROM yld_daily
WHERE machine = @m AND test_date = @target_date;

-- cpu 实际：device_samples 在 target_date 附近的最新一条
SELECT cpu_usage
FROM device_samples
WHERE machine = @m AND ts <= @target_ts
ORDER BY ts DESC LIMIT 1;
```

**Q3：命中率统计**

```sql
SELECT machine, rule,
       SUM(CASE WHEN hit=1 THEN 1 ELSE 0 END) AS hits,
       COUNT(*) AS total,
       AVG(lead_days) AS avg_lead
FROM predict_accuracy_log
WHERE reconciled_at >= @since
GROUP BY machine, rule;
```

## 6. 数据库变更

### 6.1 新增表 `predict_accuracy_log`（DbMigrator v8 末尾追加）

```sql
CREATE TABLE IF NOT EXISTS predict_accuracy_log (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    rule TEXT NOT NULL,              -- yield/cpu/disk/offline
    machine TEXT NOT NULL,
    predict_id INTEGER NOT NULL,
    predict_table TEXT NOT NULL,     -- 'alert' or 'device'
    predicted_value REAL,            -- 预测值（如预测良率、CPU%、剩余GB）
    actual_value REAL,               -- 实际值（对账时查到的）
    threshold REAL,                  -- 当时的告警阈值（用于 audit）
    hit INTEGER NOT NULL,            -- 1=预测准确, 0=误报/漏报
    lead_days REAL,                  -- 领先天数（实际 - 预测）
    predicted_at TEXT NOT NULL,      -- 预测时间
    reconciled_at TEXT NOT NULL,     -- 对账时间
    note TEXT
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_acc_unique
    ON predict_accuracy_log(predict_table, predict_id);
CREATE INDEX IF NOT EXISTS idx_acc_rule_time
    ON predict_accuracy_log(rule, reconciled_at);
CREATE INDEX IF NOT EXISTS idx_acc_machine_rule
    ON predict_accuracy_log(machine, rule);
```

**存储估算**：30 台 × 4 规则 × 30 天 = 3600 行/月，180 天滚动清理 ≈ 21,600 行，
单文件 ~1MB（SQLite），**完全可接受**。

## 8. 自检断言（必跑）

在 `selftest/SelfTest.cs` 新增分组 `[自反馈]`，至少 14 条断言：

| # | 断言 | 模拟 |
|---|---|---|
| 1 | 空库不报错，返回空 summary | 空 db |
| 2 | predict_log 注入 5 条，对账后 accuracy 表有 5 条 | mock yld_daily |
| 3 | UNIQUE 约束：同 (table, predict_id) 二次对账不报错（走 UPSERT） | 调两次 |
| 4 | yield hit 判定：预测 88%，实际 87% → hit | |
| 5 | yield miss 判定：预测 88%，实际 92% → miss | |
| 6 | cpu hit 判定：预测 3d 后 95%，3d 后 sample 96% → hit | mock device_samples |
| 7 | cpu lead_days 计算正确 | 边界 |
| 8 | disk 耗尽 ±3 天 → hit，否则 miss | |
| 9 | offline 24h 内 last_seen>90s → hit | |
| 10 | 总命中率 < 0.30 → 推荐放宽（yield 阈值 +5%） | 注入 30 条全是 miss |
| 11 | 总命中率 > 0.85 → 推荐收紧（-5%） | 注入 30 条全 hit |
| 12 | 样本 < min_samples_for_tune → 不推荐 | 注入 10 条 |
| 13 | chronic miss（单机连续 5 次）→ per_machine 标出，不出阈值推荐 | |
| 14 | /api/predict/accuracy 路由返回正确 JSON | HTTP 自检 |

**回归**：现有 `alert_predict_log` / `device_predict_log` 落库自检不能红。

## 9. 边界与回退

| 场景 | 行为 |
|---|---|
| 聚合端无 yld_daily | yield 对账返回 `actual=null` → 跳过该条，不落 accuracy |
| 预测被 Purge 删了（180 天前） | 自动跳过，不报错 |
| 配置 `predict_reconcile_enabled=false` | `RunOnce` 直接 return 0 |
| 对账失败（DB 锁） | 整批回滚，下次再试，不污染 accuracy 表 |
| 阈值推荐被现场否决 | 仅写 `ThresholdTuning.Recommended`，**不自动应用**，必须人工点确认 |
| 自动应用阈值 | **不做**——本规格只到"推荐"，应用由 v3.20.1 `/api/config/recommend/apply` 承担 |
| `predict_log.detail` 含无效字段（如新增自定义字段） | 反序列化兜底，默认字段缺失不影响 |

**回退**：迁移脚本 v8 失败 → 整体回滚（同 `DbMigrator` 既有机制）。
**功能回退**：`predict_reconcile_enabled=false` + `predict_tune_enabled=false` → 完全禁用。

## 11. 备注

- **数据闭环，无 ML 依赖**——纯 SQL + 规则
- **推荐不自动应用**——避免现场被自动改阈值后懵（与 `ConfigAdvisor.Recommend()` 同套路）
- **`DbMaintenance` 顺带执行**——不新增后台线程，避免线程膨胀
- **跨机台友好**——`machine` 字段已带，跨机台统计天然支持
- **不影响推送路径**——纯只读计算 + 写新表
